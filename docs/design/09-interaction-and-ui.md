# 交互层与信息呈现

```
状态：草稿
负责人：设计
最后更新：2026-10-17
上游依据：docs/design/01-vision-and-pillars.md（P1 意图层）、docs/design/11-freedom-design.md
下游影响：PRD-005（意图与微观控制）、PRD-006（仓储规则与因果诊断）、所有 PRD 的交互与反馈章节
事实依据：docs/research/03-front-and-interaction.md（基底交互能力盘点，调研中）
```

> 交互层是**意图层**的物理形态。玩家体验到的「自由度」与「掌控感」，80% 由这一层的清楚程度决定。
> 原则：**能看得见 → 能点得到 → 能撤销 → 能解释为什么**。

---

## 1. 设计目标

| 编号 | 目标 |
| --- | --- |
| G1 | 新手在不看外部教程的情况下，30 分钟内理解并使用「意图层四件套」 |
| G2 | 任何系统状态都能在 3 次交互内找到解释 |
| G3 | 所有玩家指令可撤销或可撤销化（有明确的反向操作） |
| G4 | 高级功能渐进披露：默认界面干净，深入时才出现 |
| G5 | 信息呈现不依赖外部 wiki；游戏内课程覆盖每个主要系统 |
| G6 | **双语（`zh_cn` + `en_us`）**、键位可改、色盲友好、字号可调 |

## 2. 交互的四个入口

| 入口 | 形态 | 适合表达 | 对应自由度层 |
| --- | --- | --- | --- |
| **世界内手势** | 手持工具/殖民书，左右键 + 潜行 + 滚轮 | 空间意图：划地、画线、放置、标记 | L0 / L3 |
| **殖民书与面板** | 物品打开的 UI（多页面） | 策略意图：职业排序、订单、库存规则、日程、优先级 | L0 / L1 / L2 |
| **世界内覆盖层（Overlay）** | 半透明可视化 | 状态理解：禁限区、物流线、需求热力、警戒范围 | 诊断 |
| **命令与配置** | 命令、配置文件、数据包 | 规则与世界：剧本、难度、自动化、modding | D1 / D2 |

**R-UI-1**：同一件事**只在一个入口做**（不要「面板里能改、世界里也能改、命令也能改」三套并行），除非有明确的高频理由。
**R-UI-2**：世界内手势必须遵守基底已有的持握/瞄准语义（避免与 Folkways 现有交互冲突，具体见 `research/03`）。

## 4. 诊断性（管理者的生命线）

> 「为什么没按我想的来？」必须是可回答的。这是本项目与「黑箱自动化」的分界线。

| 玩家疑问 | 系统必须给出 | 呈现位置 |
| --- | --- | --- |
| 为什么没人干这个活？ | 原因链：没有合格居民 / 都在忙 / 缺工具 / 缺材料 / 路径不可达 / 被更高优先占用 / 被禁限区挡住 / 恐惧不敢去 | 工地/订单悬停 + 总览「停滞」列表 |
| 他为什么不高兴？ | 情绪原因清单（每条带权重、来源、可定位对象） | 居民详情 |
| 东西为什么没送到？ | 物流链路：源头有货吗 / 有搬运工吗 / 目标满了吗 / 路线被堵了吗 | 库存规则悬停 |
| 为什么产量下降？ | 缺料 / 缺人 / 缺燃料 / 工具损耗 / 季节 / 情绪 / 机械故障 | 工作站详情 + 生产流视图 |
| 敌人为什么来？ | 前兆记录 + 势力动机（财富/声望/时代/事件） | 威胁页 |
| 为什么他死了？ | 死亡链条（受伤→感染→缺药→无人照料） | 讣告 |

**R-UI-4**：**任何「系统没有执行玩家指令」的情况都必须产生一条可读原因**（对应基底的 Refusal 机制）。
**R-UI-5**：原因文案必须**双语齐全（`zh_cn` + `en_us`）**，且尽量引用具体对象名（人名、物品名、地名），而不是抽象错误码。

## 5. 覆盖层（Overlay）与可视化

| 覆盖层 | 内容 | 何时有用 |
| --- | --- | --- |
| 区块用途层 | 每块地的用途与状态（生长进度、牲畜数、渔获） | 规划农业 |
| 禁限层 | 谁能去哪（按居民/按人群） | 安全与调度 |
| 物流层 | 运输路线、吞吐、拥堵 | 优化规模 |
| 需求层 | 需求满足度热力（饥饿/疲劳/寒冷） | 危机前兆 |
| 情绪层 | 情绪状况与原因热点 | 社会管理 |
| 威胁层 | 警戒范围、前兆、敌情 | 备战 |
| 建筑完好层 | 失修/损坏/火灾风险 | 维护 |
| 生态层 | 肥力、林地、水源、污染 | 长期规划 |
| 气体与污染层 | 分区气体成分、污染指数、通风死角、密封失效点（[d13](13-gases-pollution-and-cycles.md)） | 工业与密闭空间；**CO 与可燃气默认不可见**，需仪器或症状揭示 |

**R-UI-6**：覆盖层必须**可叠加但不过载**（默认关闭，最多同时 2 层，自动降噪）。

## 6. 反馈规范（所有 PRD 共用）

| 触发类型 | 必须有的反馈 |
| --- | --- |
| 操作模式进入/退出 | 光标/准星变化、屏幕边缘提示、音效 |
| 目标合法/非法 | 视觉（绿/红）、音效、失败时给出原因文案 |
| 持续状态（工地缺料、居民饥饿） | 世界内图标 + 悬停信息（不打断） |
| 即时事件（死亡、袭击、袭击结束） | 音效 + Toast + 可选暂停 + 编年史条目 |
| 长周期进度（建造、研究） | 进度条 + 剩余时间估计 + 谁在做 |
| 错误/异常 | 玩家可读的说明 + 日志记录（便于报 bug） |

**R-UI-7**：**不得**用弹窗打断玩家的操作，除「需要玩家决策的事件」与「不可逆操作确认」。
**R-UI-8**：所有 Toast 必须可关闭、可调频率、可关闭某类（避免刷屏）。

## 7. 教学（Lessons）

| 机制 | 说明 |
| --- | --- |
| 课程（Ponder 场景） | 基底已提供；每个新系统必须配一节课程 |
| 触发方式 | 面板页签 + 长按课程键；也可在事件发生时提示「要看这段吗」 |
| 内容要求 | 60 秒内讲清：这是什么 / 怎么用 / 常见错误 |
| 因果提示 | 首次遇到某状态时，一次性提示（可关闭） |
| 图鉴 | 物品/建筑/事件/概念的百科（可搜索） |

**R-UI-9**：任何新系统的 PRD 必须包含「课程条目」的验收项。

## 8. 可访问性与本地化

| 项 | 要求 |
| --- | --- |
| 键位 | 全部可改；提供预设 |
| 字号/缩放 | 可调（至少 3 档） |
| 色盲 | 关键状态不依赖单一颜色（配图标/纹理） |
| 语言 | 新增文案为**双语（`en_us` / `zh_cn`）**；基底既有四语言文件保留不动（`zh_hk`/`zh_tw` 用各地区 Minecraft 术语，[ADR-017](../00-charter.md)） |
| 字体 | 继承基底的 Unicode 字体处理（基底已有 `FontManagerMixin`） |
| 移动端/手柄 | 不在范围（见章程「不做」） |
| 阅读障碍友好 | 传说页/图鉴支持导出为纯文本 |

## 10. 数据与性能

| 项 | 策略 |
| --- | --- |
| 面板数据 | 打开时才请求/同步（服务端权威，按需分页） |
| 覆盖层 | 客户端本地计算（若数据已在客户端），避免频繁网络包 |
| 诊断原因 | 服务端在规划时生成，随状态同步，不临时计算 |
| 通知 | 服务端去重 + 客户端限流 |

**R-PERF-4**：任何 UI 不得每秒轮询服务端；用推送 + 按需拉取。
