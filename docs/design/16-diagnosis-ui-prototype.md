# 16 · 诊断界面的文字线框原型

> 状态：草稿（2026-10-18）
> 上游依据：[PRD-006](../prd/PRD-006-stock-rules-and-diagnosis.md)（D-1…D-31、覆盖率 ≥95%、建议动作）、[d09](09-interaction-and-ui.md)（硬预算与覆盖层）、[PRD-012](../prd/PRD-012-multiplayer-and-permissions.md)（诊断默认全员只读）、[r03](../research/03-front-and-interaction.md)（基底 UI 原语与上限）
> 下游用途：实现阶段的**行数契约**与**文案契约**；UI 评审与 gametest 的判定基准

## 1. 为什么需要这份原型

[PRD-006](../prd/PRD-006-stock-rules-and-diagnosis.md) 已经把「任何没发生的事都要能解释」落成 **31 个具名阻塞类别**（D-1…D-31）、四段诊断链（意图 → 计划 → 资源 → 执行）与五类建议动作；[d09](09-interaction-and-ui.md) 定了交互原则、覆盖层清单与硬预算。但**没有任何一份文档画出"玩家实际看到的那一屏"**。

后果是可预见的：

1. **各画各的**：需求页一套排版、诊断页一套排版，"为什么"在不同页面长得不一样，玩家每次都要重新学习。
2. **预算被悄悄突破**：基底是 `32 行/页、4 动作/行、8 行/卡`（[r03 §7.2](../research/03-front-and-interaction.md) 第 9 条）。设计稿里"再加一行就好"最容易在实现时变成"滚动条 + 分页 + 一堆截断"。
3. **结论被图表挤到第二屏**：PRD-006 §9.5.1 的八条可视化原则（**结论先行**、每页 ≤2 张图、无图也能完整表达）只有落到具体页面才可执行。
4. **降级变成空白**：权限收紧、计算降频、历史不足——三种情况下如果界面是空白，玩家会当成 bug（PRD-006 §11 `R-MP-2` 已禁止）。

这份文档因此**只做一件事**：把六个页面画成**等宽文字线框**，并给出**行数/动作/参数/文案/降级**的可判定规则。它**不是**视觉设计稿（基底布局走 taffy + `Rows` 常量，`Rows.java` 里没有像素概念），而是**契约**。

**不做什么**（非目标）：

| 不做 | 为什么 |
| --- | --- |
| 像素级视觉稿、配色、图标 | 基底用 `lss/desk.lss` 既有类与 sprite 目录（[r03 §7.2](../research/03-front-and-interaction.md) 第 5 条），不属于文档层 |
| 新动作分类（第 6 种 `act` 动词） | `Board.Act` 只有 `Do/Edit/Open/Ping/Admit`（[r03 §2](../research/03-front-and-interaction.md)）→ 新动词 = **L3**，本原型**不申请** |
| 图表组件 | 基底**没有**图表组件（PRD-006 §9.5.1）；只允许轻量自绘条形/迷你趋势线，且必须可降级为数字 |
| 自定义布局与换肤 | 不在范围（d09 OQ-UI-4 倾向：只做缩放与键位） |

## 2. 硬约束（不可协商）

### 2.1 预算表

| 约束 | 数值 | 出处 |
| --- | --- | --- |
| 每页行数 | **≤32** | [r03 §7.2](../research/03-front-and-interaction.md) 第 9 条、[d09](09-interaction-and-ui.md) §5 |
| 每行动作 | **≤4** | 同上 |
| 每卡行数 | **≤8** | 同上（对应 `LookLines(entityId, lines ≤ 8)`，`front/engine/net/LookLines.java:10-11`） |
| `Notice` 参数 | **≤4 个**，每参 ≤160 字符 | `Notice(key, args≤4, 每参 ≤160)`（[r03 §4](../research/03-front-and-interaction.md)） |
| `ZoneSettings` 槽位 | **24** | `ZoneSettings.SLOTS = 24` |
| 物品组 | **≤8 组** | [r03 §7.2](../research/03-front-and-interaction.md) 第 9 条 |
| 诊断全量刷新 | 每玩家 **5 秒 1 次** | PRD-006 §13 `R-PERF-1` |
| 覆盖层 | 同时 **≤2 层**，默认关闭 | [d09](09-interaction-and-ui.md) §5 `R-UI-6` |
| 面板轮询 | **禁止**每秒轮询服务端 | [d09](09-interaction-and-ui.md) §10 `R-PERF-4` |
| 图表 | 每页 **≤2 张**、每卡 **≤1 张**、每条 **≤3 序列** | PRD-006 §9.5.1 原则 ⑤⑥ |

### 2.2 基底原语与出处（照抄，不发明）

| 原语 | 用途 | 出处 |
| --- | --- | --- |
| `Rows.page()` / `Rows.fills(Rows.box())` | 每页标准骨架 | `front/api/ui/Rows.java` |
| `Facing.board(page, colony)` → `Board(figures, rows, whenEmpty, data)` | 声明式页面（自动渲染 / 自动 NBT 同步 / 自动处理 5 类 act） | `front/api/Facing.java`、`front/api/panel/Board.java`、`front/ui/screen/DomainPage.java:251-345,449-491` |
| `Line` 联合类型 | 信息卡行：`Said(Notice)` / `Literal` / `Text` / `Blocked(Notice, Sentence)` / `Told(Sentence)` | [r03 §4](../research/03-front-and-interaction.md) |
| `Sentence`（图示语） | 图标+词，≤24 token | 同上 |
| `Notice` / `Attempt.Refused(Notice)` | 跨端文本与失败反馈 | `front/api/notice/Attempt.java` |
| `Placard(UUID, Outline, List<Line>)` | 世界内牌匾（工地/选区） | `front/api/Placard.java` |
| `LonePanel.open(id, title, w, h, builder)` | 独立窗口（"为什么"详情） | `front/api/ui/LonePanel.java` |
| `Inlay` + `Bay.RESIDENT` | 把我们的区块塞进基底居民窗口 | `front/api/ui/Inlay.java`（样例 `plugins/person/PersonInlay.java`） |
| `Tokens.name` | 给元素命名（Ponder 悬停 + 稳定测试 id） | [r03 §7.2](../research/03-front-and-interaction.md) 第 4 条 |
| 列表 → 详情模式 | 超上限时的唯一正确答案 | PRD-006 §6.3 `R-UI-2`、[r03 §7.2](../research/03-front-and-interaction.md) 第 9 条 |

### 2.3 三条铁律

- **铁律一：结论先行。** 每张卡的第一行必须是**一句人话结论**，然后是数字，最后才是图。整页的第一行必须是**整页的结论**（PRD-006 §9.5.1 原则 ①）。
- **铁律二：文字自足。** 删掉所有图表，页面仍能完整回答"发生了什么、为什么、怎么办"（`R-FLOW-10`）。
- **铁律三：降级必须说话。** 数据缺失、计算降频、权限收紧，三种情况都必须有一行**明确的原因**与一个**可执行的下一步**，不允许空白（PRD-006 §11 `R-MP-2`、[pack/03](../pack/03-performance-budget.md) 降级纪律）。

## 3. 信息架构

### 3.1 六页与它们各自回答的一个问题

| # | 页面 | id（提案） | 只回答一个问题 | 主要数据源 |
| --- | --- | --- | --- | --- |
| 1 | 概览 | `plaa:overview` | **殖民地现在怎么样？** | PRD-006 日聚合、PRD-001 情绪、PRD-003 存量预测 |
| 2 | 为什么 | `plaa:why` | **这件事为什么没发生？**（核心页） | PRD-006 §9.2 四段链、D-1…D-31 |
| 3 | 需求与情绪 | `plaa:needs` | **他/他们为什么不高兴、还能干多久？** | PRD-001 需求注册表 + 专注度 |
| 4 | 仓储与物流 | `plaa:stock` | **东西在哪、够不够、为什么送不到？** | PRD-006 Part A（reserve/quota/affinity/quality） |
| 5 | 居民档案 | `plaa:resident` | **这个人现在是什么状态？** | PRD-013 伤病、PRD-008 关系、PRD-001 记忆 |
| 6 | 系统健康 | `plaa:systems` | **哪些"看不见的系统"正在坏？** | [d13](13-gases-pollution-and-cycles.md) 气体、[d15](15-power-and-mechanical-residents.md) 电网、病房、牢房 |

**为什么是六页而不是十六页**：[d09](09-interaction-and-ui.md) `R-UI-3` 的纪律是"每页回答一个具体问题，否则合并或删除"。诊断的价值在**收敛**，不在**铺开**——所以六个页面之外，其余诊断入口都是**从对象跳进来**（§6.1），不新增页面。

### 3.2 与基底已有页面的合并

基底已有 Workforce、Members、Blueprints、Orders、Lessons 等页面（[r03 §2](../research/03-front-and-interaction.md)、[d09](09-interaction-and-ui.md) §3）。我们的策略是**四新两并**：

| 我们的页 | 与基底的关系 | 做法 |
| --- | --- | --- |
| 概览 | 新增 | 独立页；入口在殖民书首页 |
| 为什么 | 新增 | 独立页 + **可从任意对象以窗口形式打开** |
| 需求与情绪 | 新增 | 独立页；居民档案里只放"摘要 + 跳这里" |
| 仓储与物流 | **并入**基底 `Orders` 页 | 作为该页的**第二个标签**，不新建页 |
| 居民档案 | **并入**基底 `Members` 详情 | 用 `Inlay` + `Bay.RESIDENT` 塞区块（`Inlay` 的既有用法） |
| 系统健康 | 新增 | 独立页；无该系统时整卡降级（§8） |

> 页面 id 的最终取值受 [d09](09-interaction-and-ui.md) `OQ-UI-1`（与基底页面合并方案）约束；本原型只给**提案 id**，命名规则沿用基底（`<ns>:<name>`，`ns = plaa`）。

### 3.3 导航与入口

```
殖民书（手持右键）
├─ 首页 ──────────── 概览（默认）           [Tab 1]
├─ 为什么 ────────── 最近 5 条阻塞（全局）   [Tab 2]
├─ 人 ────────────── Members（基底）→ 居民档案（Inlay）
│                  └ 需求与情绪（独立页，从居民档案跳入）
├─ 物 ────────────── Orders（基底）→ 仓储与物流（第二标签）
├─ 系统 ──────────── 系统健康               [Tab 6]
└─ 命令 ──────────── /plaa why …
```

**R-UI16-1**：页面切换**不得丢失筛选条件**（§6.2）；返回时回到原滚动位置。
**R-UI16-2**：任何页面都必须是**可关闭的覆盖层或可返回的页**，不得出现"只能前进不能后退"的面板。

## 4. 行预算（32 行怎么花）

### 4.1 标准页骨架

| 区段 | 行数 | 内容 | 可压缩性 |
| --- | --- | --- | --- |
| 页眉 | 1 | 页面名 · 殖民地名 · 游戏内日期 · 关闭 | 不可压 |
| **整页结论** | 1–2 | 一句话（状态 + 对象 + 数字 + 时限） | 不可压 |
| 关键数字条 | 1 | 3 个数字，用分隔符隔开 | 可压成 0（并入结论） |
| 正文卡 | ≤24 | 每卡 ≤8 行 | 可压（列表 → 详情） |
| 动作条 | 1 | ≤4 个动作 | 不可压 |
| 页脚 | 1 | "截至 %s" + 数据状态 + 刷新 | 不可压 |

### 4.2 卡片骨架（8 行）

| 行 | 内容 | 说明 |
| --- | --- | --- |
| 1 | **结论句** | 必填，且必须能独立读懂 |
| 2–4 | 关键数字 / 归因 | 数字带单位与方向（↑↓→） |
| 5 | 建议动作（≤2 个） | 与页脚动作条不重复 |
| 6–7 | 明细（≤2 行） | 对象名 + 状态 |
| 8 | 数据状态 | `截至 %s` / `数据不足（还需 %s 天）` / `降频` |

### 4.3 溢出规则

- 超过 24 行正文 → **列表 → 详情**（基底 `select(index)` + 详情窗模式，见 `ResidentsPage` 的既有做法），**不是**加滚动条。
- 超过 4 个动作 → 第 4 个固定为「更多…」，把其余动作放进详情窗。
- 超过 8 行卡片 → 拆卡；拆卡优先按**类别**（缺口/溢出/腐坏/不可达），不按对象。

**R-UI16-3**：任何"塞不下"的解法都必须是**列表 → 详情**，不允许滚动条、不允许分页标签超过 3 个。

## 6. 跨页交互

### 6.1 从任何东西跳到「为什么」

| 入口 | 打开方式 | 落到哪一段 |
| --- | --- | --- |
| 世界内准星对着工地 | `Blocked(Notice, Sentence)` 已有失败原因（`Line` 联合类型） | 直接显示该对象的四段链摘要 |
| 订单/规则行悬停 | 行内 `[为什么？]` 动作 | 该订单的影响链 |
| 居民档案的"工作被拒"行 | 行内 `[为什么？]` | 该居民 × 该工作的四段链 |
| 概览的三件事 | 整行点击 | 对应对象的四段链 |
| 系统健康的 ⛔/⚠ 行 | 行内 `[为什么？]` | 该类系统阻塞（D-20…D-31） |
| 命令 | `/plaa why zone <pos>` | 与 UI **同一函数**输出 |

**R-UI16-4**：任何一个"没发生的事"**最多 2 次点击**必须能看到 **D 编号 + 对象名 + 一句根因 + 一个建议动作**。
**R-UI16-5**：「为什么」是**窗口**（`LonePanel`）而不是页面跳转——玩家必须能一边看着世界一边读原因（否则会丢失上下文）。

### 6.2 筛选保持

- 筛选条件（居民/区域/类别/时间窗）**存在页级状态里**，切页再回来必须保持。
- 从"为什么"窗口的"相关对象"点进去 → 目标页**继承当前筛选**并高亮该对象。
- 命令行的参数与 UI 筛选**语义相同**（同一套过滤函数），不允许两套。

**R-UI16-6**：跨页传递的对象引用必须是**稳定 id**（居民 UUID / 区域 key / 物品 id），不是显示名。

### 6.3 命令与 UI 同源

| 命令 | 输出 | 与 UI 的关系 |
| --- | --- | --- |
| `/plaa why colony` | 全殖民地阻塞统计（按影响排序） | 与概览页"最该处理的三件事"**同一份数据** |
| `/plaa why resident <id>` | 该居民为何空闲/被拒 | 与居民档案"工作被拒"**同一条链** |
| `/plaa why item <item>` | 库存/物流链状态 | 与仓储页"查看"**同一条链** |
| `/plaa why zone <pos>` | 该区域为何没在做某事 | 与"为什么"窗口**同一函数** |
| `/plaa diag coverage` | 覆盖率报告（发布门禁） | 只读，不面向普通玩家 |
| `/plaa diag dump` | 导出快照（缺陷报告） | 与「导出」动作**同一序列化** |

**R-UI16-7**：`why` 与 UI **必须调用同一个实现**（一份 `Diagnosis.chain(...)`，函数名待定），命令输出是它的纯文本渲染。**禁止**两条路径各算一次——否则玩家会看到"界面说 D-4、命令说 D-9"。

> ⚠ **待裁决（OQ-7）**：PRD-006 §6.4 把 `why` 的权限定为 `gamemaster`，但 PRD-006 §11 与 PRD-012 已定"诊断默认全员只读"。二者冲突——建议把 `why` 降到**成员**，与 UI 一致；`diag coverage/dump` 保持 `gamemaster`。

### 6.4 动作与确认

- 每行 **≤4** 个动作，顺序固定：**主建议 → 定位 → 查看 → 更多**。
- 建议动作的五种类型（PRD-006 §9.4）：跳转 / 预填 / 一次修改 / 定位 / 导出。
- **一次修改**必须二次确认（`R-FLOW-6`：建议动作不得直接执行破坏性变更）。
- 「自动修复全部」**不做**（`R-FLOW-7`），也不得用"一键优化"的名字变相出现。

**R-UI16-8**：动作必须能**键盘完成**（Tab 聚焦 + Enter），不能只靠鼠标——手柄/键位可改的要求见 §8.3。

### 6.5 权限与 👁

| 情形 | 界面表现 |
| --- | --- |
| 默认（`diagnosis_visibility=member`） | 全员可看**全部**诊断（只读）；动作按目标动作权限 |
| 私密字段（居民私密情绪/记忆/崩溃原因） | **👁 只读降级**：显示"有这条，但内容不对你展开"，不是隐藏 |
| 服务器收紧为 `manager` | 成员看到**降级版**：自己的 + 公开的阻塞（PRD-006 §11 `R-MP-2`），并在页眉明示 |
| 无权限执行某动作 | 按钮**可见但禁用**，悬停给出「需要什么权限 + 你当前等级 + 找谁要」（PRD-012） |

**R-UI16-9**：**永远不要**因为权限而让页面空白；最差也必须显示"为什么看不到"。


| 无医生 D-17 | `%s 受伤 %s 小时，但没有可用医生` | 居民、时长 |
| 缺氧 D-21 | `%s 氧气 %s%%，低于安全线 %s%%` | 分区、当前、阈值 |
| 结构性 D-12 | `%s 结构上无法完成——这是缺陷，请报告（%s）` | 对象、缺陷 id |

**R-UI16-10**：结论句**不得**包含"操作失败/出错了/未知错误"这类无信息量的词（PRD-006 §9.3 的具名类别就是为此存在）。

### 7.2 参数与对象名

- `Notice` **≤4 个参数**，每参 **≤160 字符**（[r03 §4](../research/03-front-and-interaction.md)）；超过就说明这条结论该拆。
- 参数优先用 **`Arg.Named`（嵌套翻译键）** 传对象名，让语言切换时对象名也跟着翻译（例如居民名、物品名、区域名）。
- 对象名**必须来自数据**（`Tokens.name` 的同一来源），**禁止**在文案里写死"农田/仓库"这类泛称。
- 数字：整数与一位小数为主；百分比在翻译键里写 `%%`。

### 7.3 禁止清单（评审时逐条对照）

| 禁止 | 为什么 | 正确做法 |
| --- | --- | --- |
| 「操作失败」 | 没有信息量，无法行动 | 用 D 编号 + 对象 + 原因 |
| 「未知错误」 | 等于承认不可诊断 | 用 D-12 并引导报告 |
| 「请稍后再试」 | 掩盖了退避机制 | 用 D-10 + 具体剩余时间 |
| 在图形里烤死文字 | 破坏 i18n（PRD-006 §9.5.1 原则 ⑤） | 标签走键 |
| 只靠颜色区分状态 | 色盲不可读 | 颜色 + 图标 + 文字 |
| 用滚动条解决超长 | 破坏 32 行契约 | 列表 → 详情 |
| 结论写在图表下面 | 违反"结论先行" | 结论在第一行 |

### 7.4 键命名与示例

```
plaa.page.overview            = 概览
plaa.page.why                 = 为什么
plaa.why.conclusion.lacking   = %s 缺 %s：%s/%s
plaa.why.segment.intent       = ① 意图
plaa.why.segment.plan         = ② 计划
plaa.why.segment.resource     = ③ 资源
plaa.why.segment.exec         = ④ 执行
plaa.why.advice.order_tool    = 建议：下 %s 把 %s 订单
plaa.why.empty                = 目前没有任何阻塞
plaa.why.denied.private       = 👁 该对象的私密明细不对你展开
plaa.state.stale              = 数据可能滞后 %s 秒
plaa.state.no_data            = 数据不足（还需 %s 天）
plaa.state.degraded           = 诊断已降频（每 %s 秒一次）
plaa.action.more              = 更多…
```

**R-UI16-11**：键族前缀固定为 `plaa.`（[ADR-017](../00-charter.md) modid 裁决）；新增键**只做 `zh_cn` + `en_us` 两份**，基底既有四语言文件不动、缺键回退 `en_us`。

### 7.5 数字、单位与时间

- 单位由键提供（`%s 天` / `%s 秒` / `%s%%`），**不拼接**。
- 时间一律给**相对量**（「4 天后」）并附**绝对量**（「第 45 日」）；只有需要跨日比较时才显示日期。
- 数据新鲜度必须显示：`截至 %s`；陈旧时用 `plaa.state.stale`，**不静默**（PRD-006 §9.5.1 原则 ③）。

## 8. 降级与可达性

### 8.1 三种降级（都必须"说话"）

| 类型 | 触发 | 界面必须显示 | 必须提供的下一步 |
| --- | --- | --- | --- |
| **数据缺失** | 系统未启用 / 历史不足 / 无该内容 | 第一行说明**为什么空** + 何时会有 | 去开启 / 去建造 / 看教程 |
| **计算降频** | 限流、降级阶梯、多人共享聚合 | 页眉 `⚠ 降频（每 %s 秒）` + `截至 %s` | 刷新（立即重算一次） |
| **权限收紧** | `diagnosis_visibility=manager` / 私密字段 | 页眉 `👁 只读降级` + 能看到什么 | 找管理者要权限 |

**R-UI16-12**：三种降级**不得**用同一个图标或同一句话——玩家必须能区分"没有数据""数据旧了""你没权限"。

### 8.2 图表的降级

- 图表**永远不是**唯一的信息载体（`R-FLOW-10`）：同一张卡必须同时有数字。
- 历史不足 `min_history_days` → 显示 `plaa.state.no_data`（「数据不足（还需 %s 天）」），**不画空图**。
- 客户端不支持自绘 / 绘制失败 → **降级为数字表**，并在卡尾写明"图表不可用，已用数字显示"。
- 每页 ≤2 张图、每卡 ≤1 张、每条 ≤3 序列（PRD-006 §9.5.1 原则 ⑥）。

### 8.3 色盲、字号、键位

| 项 | 要求 |
| --- | --- |
| 状态编码 | **图标 + 文字 + 颜色**三重（✅ / ⚠ / ⛔ / 👁 / ⏸）；去掉颜色仍可读 |
| 字号 | 至少 3 档；放大后行数契约不变（文本换行不新增行） |
| 键位 | 全部可改；页面内 `Tab` 走动作、`Esc` 逐层关闭（基底 `Desk` 已有该行为） |
| 悬停依赖 | **禁止**只靠悬停传达关键信息（悬停内容必须也能在详情窗里看到） |
| 导出 | 任意页可导出为纯文本（对应 `R-FLOW-10` 与 d09 的"阅读障碍友好"） |
