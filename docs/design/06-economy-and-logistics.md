> **本项目经济系统的第一原理：一切都是实物。**
> 没有「凭空出现的面包」——面包必须有人种麦、有人磨粉、有人烤、有人端过去、有人吃。物流就是玩法本身。
> 这也是 Folkways 已有的强项（订单 / 搬运 / 存储 / 工作站），我们的工作是**加深**，不是重做。

---

## 1. 设计目标

| 编号 | 目标 | 可判定信号 |
| --- | --- | --- |
| G1 | 每条生产链都能被玩家**看见**（从原料到成品到消费） | 面板能追踪某件物品的来源与去向 |
| G2 | 瓶颈**可诊断**（为什么没生产/没送达） | 每个停工都有原因输出 |
| G3 | 生产有**取舍**（时间、燃料、工具、人力、空间） | 同一目标至少两种可行方案 |
| G4 | 贸易提供**外部选择**（买/卖/换，价格随供需波动） | 商队价格随殖民地供需变化 |
| G5 | 经济规模受**物流能力**限制，而非上限硬编码 | 扩仓、修路、上铁路能明显提升吞吐 |
| G6 | 玩家的微观干预**可选**（库存规则 / 优先级 / 手动搬运） | 不配置也能运转，配置后更好 |

## 2. 物资分类

| 类别 | 例 | 特性 | 仓储需求 |
| --- | --- | --- | --- |
| **原料** | 原木、矿石、砂石、黏土、纤维、生食 | 体积大、价值低 | 露天/堆放 |
| **中间品** | 木板、锭、面粉、皮革、布料、部件 | 需工序 | 一般仓 |
| **成品** | 工具、衣物、家具、武器、餐食 | 价值高 | 一般仓 |
| **食物** | 生食/熟食/加工品（腌/晒/酿） | **会腐坏** | 需冷藏/腌制/地窖 |
| **燃料** | 木柴、煤炭、焦炭、油 | 消耗品 | 堆放 |
| **工具** | 斧、镐、镰、锤、渔具 | **有耐久，会消耗** | 工具架 |
| **奢侈品** | 酒、香料、装饰品、艺术品 | 满足美感/意义需求 | 展示/仓 |
| **货币** | 硬币/代币（后期） | 交换媒介 | 金库 |

**R-ECO-1**：食物必须有**腐坏与保存**机制，否则储粮季节机制失效。
**R-ECO-2**：工具必须有**消耗**，否则生产链断裂（工具是「劳动能力」的物质化）。
**R-ECO-3**：物品要有**品质与来源署名**（谁做的、什么材质、什么品质），这是叙事的载体（「这是老张的遗作」）。

## 3. 生产链（按时代）

| 时代 | 链示例（原料 → 中间 → 成品） | 关键瓶颈 |
| --- | --- | --- |
| 石器 | 树枝+石头 → 简易工具；兽皮 → 衣物 | 人力与时间 |
| 农耕 | 麦 → 面粉 → 面包；羊毛 → 线 → 布 → 衣 | 农时、储藏 |
| 铜石 | 铜矿+锡矿 → 熔炼 → 青铜锭 → 工具/武器 | 燃料、炉温、专职工匠 |
| 铁器 | 铁矿+煤 → 生铁 → 熟铁/钢 → 工具/机械部件 | 采矿深度、运输 |
| 工业 | 钢+部件 → 机械；面粉 → 流水线食品 | 供能、跨区物流 |
| 蒸汽/天空 | 蒸汽机、铁路车辆、飞艇部件 | 精密部件、稀有材料 |
| 星辰 | 特殊材料、燃料、生命维持 | 稀有资源、跨世界物流 |

**R-ECO-4**：每个时代的**瓶颈必须与上一个时代不同**（人力 → 农时 → 燃料 → 运输 → 供能 → 材料），这样进程才有意义。

## 4. 仓储与库存规则

### 4.1 存储层级

| 层级 | 内容 | 玩家控制 |
| --- | --- | --- |
| 容器（Container） | 箱子、桶、柜、储罐 | 允许/禁止某类物品（过滤器） |
| 仓储区（Store） | 一组容器的集合（基底已有 `Stores` / `StorePlaces`） | 优先级、保留量、取用权 |
| 库房（Warehouse） | 建筑级的仓储（含温控/防潮/防虫） | 建筑等级与改造 |
| 殖民地总账（Ledger） | 全局库存视图（基底已有 `Ledger`） | 只读 + 缺口预警 |

### 4.2 库存规则（Store Rule）

| 规则 | 说明 | 例 |
| --- | --- | --- |
| **保持量（Keep at least）** | 容器/仓储区至少保持 N 个某物 | 「厨房至少 32 个面包」 |
| **上限（Keep at most）** | 超过则不再入库 | 「木箱最多 512 原木」 |
| **只出不进 / 只进不出** | 方向约束 | 「种子箱只出不进」 |
| **品质门槛** | 只收 ≥ 某品质 | 「工具架只放精良以上」 |
| **优先级** | 多个仓储区之间的取用顺序 | 「先吃地窖的旧粮」 |
| **预留（Reserve）** | 为某用途预留 | 「为过冬预留 200 食物」 |
| **禁限** | 禁止某类居民取用 | 「酒窖禁止儿童」 |

**R-ECO-5**：所有规则都必须有**默认值**，不配置也能合理运转（对应 [自由度](11-freedom-design.md) R-F4 渐进披露）。
**R-ECO-6**：规则冲突必须可诊断（哪条规则赢了、为什么）。

## 5. 物流

| 手段 | 时代 | 容量 | 速度 | 成本 |
| --- | --- | --- | --- | --- |
| 人力搬运 | 石器 | 小（背包） | 慢 | 占用人 |
| 驮畜/推车 | 农耕 | 中 | 中 | 需要饲养/制造 |
| 河道/运河 | 铜石 | 大 | 中 | 工程量大 |
| 铁路（基底已有） | 铁器 | 大 | 快 | 建设+维护 |
| 机械传送（Create） | 工业 | 大 | 快 | 供能+维护 |
| 飞艇/飞船 | 蒸汽 | 很大 | 快 | 昂贵、风险 |

**R-ECO-7**：物流是**规模的真实上限**。扩大生产前必须解决运输，否则产能闲置（这是好的设计压力）。
**R-ECO-8**：物流网络必须**可视化**（路线、吞吐、拥堵点），否则玩家无法优化。

## 6. 订单、需求预测与短缺

| 机制 | 说明 |
| --- | --- |
| 订单（Order） | 基底已有：为某容器指定「保持某物 N 个」，系统自行安排采集/制造/搬运 |
| 生产令（Work Order） | 指定「制造 N 个某物」（可排队、可设条件） |
| 短缺预警 | 全局预测：按当前消耗速率，某物将在 X 天后耗尽，提前告警 |
| 库存目标 | 按季节设目标（入冬前储粮目标） |
| 配额 | 每人/每职业的物资配给（后期阶级时代） |

**R-ECO-9**：短缺预警必须**提前量足够**（至少一个采集周期），否则是「告知失败」而非「帮助规划」。

## 7. 贸易与外部经济

### 7.1 演进

| 时代 | 形态 |
| --- | --- |
| 石器/农耕 | 无（自给自足）或偶发以物易物 |
| 铜石 | 定期商队：以物易物，价格有波动 |
| 铁器 | 常设商路、议价、订单式采购 |
| 工业 | 货币出现、价格与税率、市场波动 |
| 蒸汽+ | 跨区域贸易、外交性贸易条约、垄断 |

### 7.2 价格模型（草案）

```
价格 = 基准价
     × 外部供需系数（该物品在外部世界的稀缺度）
     × 本地供需系数（本地存量 vs 本地消耗）
     × 关系系数（与交易方的外交关系）
     × 时代系数（技术普及度）
     × 随机波动（±N%）
```

**R-ECO-10**：玩家**不能**靠单一商品无限套利（价格随大量买卖移动）。
**R-ECO-11**：贸易必须给出**真实的选择**：卖粮过冬 vs 饿肚子买铁；而不是「总是赚」。

## 8. 劳动分工与专业化

| 机制 | 说明 |
| --- | --- |
| 职业（Vocation） | 基底已有：农牧渔猎、建造、搬运、制造、巡逻、驾驶、调度 |
| 专精 | 熟练度提升速度与品质上限（基底的 `Xp`/`Perk`） |
| 学徒 | 师徒关系加速成长（见 [殖民地与居民](05-settlement-and-residents.md)） |
| 工坊专属 | 特定工作站带来品质/速度加成（Stonehearth 式） |
| 劳动力上限 | 人口是硬约束，因此「专业化 vs 全能」是真实取舍 |

**R-ECO-12**：专业化必须带来**可感知**的收益差异，否则玩家会永远用「谁有空谁干」。

## 9. 统计与可视化（管理者体验）

| 视图 | 内容 |
| --- | --- |
| 库存总览 | 按类别/位置/品质的库存与变化趋势 |
| 生产流 | 某物的「产/耗/存」曲线 |
| 劳动分配 | 各职业占用的人力与产出 |
| 瓶颈图 | 哪个环节在排队（缺料/缺人/缺空间/缺工具） |
| 消费结构 | 食物/燃料/工具的实际消耗 |
| 贸易记录 | 每次交易的物品、数量、价格、对方 |

## 10. 与基底（Folkways）的关系

| 需要 | 基底已有（待 `research/01`/`02` 确认） | 需要新增 |
| --- | --- | --- |
| 物品描述与查询 | `ItemSpec`、`ItemQuery`、`ItemFilter`、`Goods` | 品质、腐坏、署名 |
| 存储与取用 | `Stash`、`StoreRule`、`Stores`、`StorePlaces`、`Ledger` | 规则类型扩展、预留、品质门槛 |
| 搬运与投递 | `Delivery`、`Haul`、`Carry`、`Transfer` | 大宗运输（铁路/传送）、优先级 |
| 生产与配方 | `plugins/wares`（`CraftNode`、`CraftRecipes`、`Smelt`、`Hearth`、`Machines`、`Stations`） | 品质、工具消耗、流水线 |
| 订单 | `plugins/orders`（已完成骨架） | 生产令、短缺预警、季节目标 |
| 贸易 | 待确认（`plugins/dispatch` 偏邮政/调度） | 商队、价格、外交关联 |
| 统计 | 待确认（`front` 的 metrics 相关） | 生产/消费/瓶颈视图 |

**关键判断**：基底已经把「实物物流 + 订单 + 配方」做得很扎实。**我们的重心是：品质与腐坏、工具消耗、贸易外部世界、诊断可视化**。不要重新发明搬运。

## 11. 数据与性能

| 项 | 策略 |
| --- | --- |
| 库存 | 复用基底的容器/仓储索引，不自建重复索引 |
| 腐坏 | 按「批次」计时（同一批入库的食物共享一个计时器），不逐物品 tick |
| 价格 | 按交易日结算 |
| 统计 | 按日聚合，保留有限窗口（例如 1 年），更早的降采样 |
| 大仓储 | 容器数量大时用区域级聚合值 + 惰性明细 |

**R-PERF-2**：任何经济统计不得引入逐 tick 的全量扫描；不得为统计而复制库存数据。
