## 0. 与基底冲突的既有处理

| 情况 | 处理 | 例子 |
| --- | --- | --- |
| 基底已有官方译名 | **沿用** | `Colony` = 殖民地；`colony_book` = 殖民书 |
| 我们的旧口径与基底不同 | **一律改成基底译名**（2026-10-18 已全局替换：原「聚落」→ 殖民地） | 见 [ADR-012](../00-charter.md) |
| 同一英文词在两边含义不同 | **必须有一边改名**，禁止歧义 | 见 §3 易混词 |
| 基底没有的概念 | 由我们命名，登记在 §2 | Need / Mood / Memory / Incident / Age |

**重要（已定）**：术语统一为 **殖民地（Colony）/ 殖民书（colony_book）**。全项目**不再使用「聚落」一词**，包括设计文档与玩家文案（[ADR-012](../00-charter.md)）。

## 3. 易混词与禁用词（冲突检查）

| 词 | 问题 | 结论 |
| --- | --- | --- |
| 「殖民地」 | 与 Minecraft 原生 Villager 的「村庄」概念易混 | 我们的殖民地实体**必须**称「殖民地」；原生村庄称「村庄」 |
| 「村民」 | 与 Minecraft 原生 Villager 混淆 | **禁用**。一律用「居民」 |
| 「区块」（Zone） vs 「区块」（Chunk） | Minecraft 的 chunk 在中文也是「区块」 | 指用途区域时用**区块用途（Delegation）**或「地块」；指 chunk 时用「区块/加载区块」并加限定 |
| 「订单」（Order） | 与「生产令」「任务」易混 | 「订单」= 保持库存量的长期目标（基底含义）；一次性制造需求叫**「生产令」（Work Order）** |
| 「建筑」 | 指方块结构还是建造行为 | 名词用「建筑」；行为用「建造」 |
| 「冲动」（Urge） | 与我们的「需求」不同：Urge 是**想做什么**，Need 是**缺什么** | 两者不得互换；技术文档保留 `Urge`/`Need` 英文标识 |
| 「任务」 vs 「工作」 vs 「节点」 | 基底用 Node/Tour/Doing | 玩家用语统一为**「活」/「工作」**；技术文档用 `Node`/`Tour` |
| 「科技点」 | 我们不使用点数制科研 | **禁用**；用「知识」「时代条件」 |
| 「殖民地」的政治含义 | 中文语境可能有殖民联想 | 沿用基底译名以保证一致性；对外宣传可在说明中解释为「拓荒殖民地」 |

## 4. 命名与 key 规范

| 项 | 规范 | 例 |
| --- | --- | --- |
| i18n key | 继承基底：`<域>.<modid>.<标识>`；我们的插件用统一 modid 前缀 | `folkways.need.hunger`、`plaa.incident.raid.herald` |
| 拒绝理由 | `RefusalKind.Named` 自动拼 `folkways.refusal.<Area>.<CONST>` | `folkways.refusal.steering.no_labour` |
| 数据包货架 | 新增货架用小写单数 | `need` / `memory` / `incident` / `scenario` / `age` |
| 配置项 | 继承基底 `folkways-server.toml` 风格；我们的配置用独立文件（**`plaa-server.toml`**，modid 已定） | `event_frequency` / `season_days` |
| **`<ns>` 占位符** | **全部文档中的 `<ns>` 一律指我们的命名空间 `plaa`**（[ADR-017](../00-charter.md)）；**第三方内容用其自有命名空间**，我们的加载器读取所有命名空间（R-AUTH-1） | `/<ns> why` = `/plaa why`；`data/<ns>/…` = `data/plaa/…` |
| 玩家可见文案 | **双语（`zh_cn` + `en_us`）**；参数 `%s`；字面百分号 `%%`（基底既有四语言文件保留；[ADR-017](../00-charter.md)） | 见 [PRD 模板](../prd/00-prd-template.md) 第 12 节 |
| 术语英文标识 | 优先与基底风格一致（生活化英文：`folkways` 用 `Folk` 味词汇） | 我们的插件命名避免生造缩写 |

## 5. 维护流程

1. 新增术语 → 在 §2 加一行（英文标识 / 中文 / 定义 / 归属）。
2. 与基底冲突 → 在 §3 加一行并给出裁决。
3. 人类确认（H2 决策点）→ 更新状态。
4. 术语变更必须检查是否已有文档/代码使用旧词（可用 [P8 漂移检测](../workflow/04-prompts.md)）。
