```
负责人：规划者（agent）
最后更新：2026-11-06
上游依据：prd/PRD-015-captivity-and-prisoners.md、design/05-settlement-and-residents.md

```

---

## 1. 盘点：哪些原语已经存在

R1（禁限区）建的时候，`ZoneRule` 就已经不是"能不能进"这一个问题：

| 原语 | 现状 | 关押能不能直接用 |
| --- | --- | --- |
| `Kind.FORBID` | 谁都别进（可指定主体） | ✅ 禁闭室对外人封闭 |
| **`Kind.ALLOW_ONLY`** | **只有列出的主体能进** | ✅ 只有守卫能进牢区 |
| `Kind.LIMIT` + `quota` | 最多 N 个主体同时在 | ✅ 牢房容量 |
| `subjects`（`ResourceLocation`） | 按**职业或居民种类**限定 | ✅ 用囚犯种类限定 |
| `Verdict.ONLY_FOR_OTHERS` / `QUOTA_FULL` | 已能表达"这格是给别人的/满了" | ✅ 拒绝理由 |

**结论：围住一个区域、只让某些人进、限制人数——都已经能表达。**

---

## 2. 缺口一：**反向白名单**（把一个人关在里面）

现在是"这一格允许谁进"。关押需要的是：

> **对某个囚犯，除了牢区里的格子，整个世界都不许进。**

`ZoneRule` 表达不了这个——它按格子描述，不是按人描述"只准待在这片"。

### 建议：新增 `Kind.CONFINE`（我们自己的枚举，L1）

```java
/** 对列出的主体，只有本区覆盖的格子是允许的；区外一律禁止。 */
CONFINE
```

语义与其它 Kind 的差别：其它 Kind 只影响**区内的格子**，`CONFINE` 影响**区外的所有格子**（只对被列出的主体）。
`verdict(cell, subject, insideCount)` 需要知道"这个格子是不是本区覆盖"——已有 `covers(cell)`，可判定。

**影响**：改的是**我们自己的枚举**（`plugins/steering`），不是上游代码 → L1；但要加测试覆盖 `CONFINE` 与其它 Kind 的组合。

---

## 3. 缺口二：**强制劳动**（没有同意的工作）

自由居民"愿不愿意干"由 `Urges` 决定；囚犯是**被指派**的。这在引擎里没有等价物：

| 方案 | 代价 | 我的判断 |
| --- | --- | --- |
| A. 把强制劳动做成"囚犯的特殊 urge" | 需要一个来源把任务塞给**指定的人**，而 `Urges` 是"谁合适谁去" | 语义不对 |
| B. 在 `Tours`/`Scheduler` 加"指定执行者"通道 | **L3**（动选留阶段） | 可能必要，但要报批 |
| C. 先不做强制劳动，只做关押与看管 | 少一块玩法，但零 L3 | **建议先这样** |

**所以这一轮的结论**：关押**可以先做"关得住、看得见、有理由"**，强制劳动推迟到单独一轮并明确报批。

---

## 4. 缺口三：谁算"囚犯"

`Resident` 有 `kind`（`ResourceLocation`）——囚犯可以是**一种居民种类**（如 `folkways:prisoner`），
而不需要新的实体系统。这与 d18 §4 的纪律一致：**不新开一套居民概念**。

需要新增的是"这个人是不是囚犯"的**判定入口**（一个只读查询），以及它在哪被问：

| 问题 | 谁问 | 谁来答 |
| --- | --- | --- |
| 这个人能被关吗 | 守卫/玩家操作 | PRD-015 的规则 |
| 他被关在哪 | 排班与卡片 | 牢区（`CONFINE` 区） |

---

## 5. 接缝形状（总结）

| 组件 | 形态 | 层 |
| --- | --- | --- |
| 牢区 | `ZoneRule.Kind.CONFINE`（我们自己的枚举扩展） | **L1** |
| 拒绝理由 | 复用 `Vetoes`（`CONFINE` 区外 → 拒绝） | L1 |
| 身份 | `Resident.kind` + 一个只读判定 | L1 |
| 强制劳动 | **不做**（需 L3：指定执行者通道） | ⛔ 待报批 |
| 玩家可见 | 解释层（"他被关在里面"）+ 卡片 | L1 |

## 6. 明确不做

| 不做 | 为什么 |
| --- | --- |
| 越狱/守卫战斗 | 属 PRD-004 与 PRD-015 战斗侧 |
| 囚犯的社交与关系 | 先在 R1 的框架里自然发生，不特殊化 |
| 赎金/交换/审判 | 属 PRD-010 外交与 PRD-015 处置 |
| 强制劳动 | 见 §3-C |

---

## 7. 验收（做关押那一轮时）

| 判据 | 怎么验 |
| --- | --- |
| `CONFINE` 语义不与其它 Kind 冲突 | 纯函数测试：区外拒绝、区内允许、非目标主体不受影响 |
| 关押不挡住别的居民 | 测试：守卫可进、无关居民照常 |
| 玩家看得到理由 | 卡片/解释里出现"被关押"，且不冒充禁限区 |
| 默认零影响 | 没有 `CONFINE` 区时，1482 基线不退 |
