## 1. 对标对象

| 类别 | 对象 | 为什么对标 |
| --- | --- | --- |
| 深度叙事 | **Dwarf Fortress** | 涌现叙事、个体深度、失败即内容、传说页 |
| 宏观规模 | **Songs of Syx** | 人口规模、种族、经济与政治、大战略层 |
| 人物张力 | **RimWorld** | 需求/情绪/事件叙述者、关系与精神崩溃 |

| 基座 | **Folkways** | 已提供的能力边界（详见 `docs/research/*`） |

## 2. 逐款拆解

### 2.1 Dwarf Fortress —— 借「因果与记录」，弃「门槛」

| 维度 | 它的做法 | 我们的取舍 |
| --- | --- | --- |
| 个体深度 | 每个矮人有偏好、性格、关系、记忆、梦想 | **借**：偏好与性格（会直接影响工作与情绪）；记忆系统 |
| 涌现叙事 | 系统不写剧本，人物自己产生故事 | **借**：不写主线剧情，改为「事件 + 人物反应」 |
| 传说页（Legends） | 世界历史可查、可导出 | **借（MVP 简化）**：本殖民地的编年史、人物条目、墓志、家族树 |
| 失败即内容 | 团灭是可接受结局 | **借（加缓冲）**：失败有前兆与过程，且玩家可调叙述者强度 |
| 多层空间 | Z 轴分层、地下城、岩浆、地下河 | **借（Minecraft 天然具备）**：强化竖井、矿场、地下水、塌方 |
| ASCII 与操作门槛 | 极高学习成本 | **弃**：3D 可视化 + 游戏内教学 + 因果提示 |
| 极端拟真（如猫被酒毒死） | 有趣但不可控 | **弃**：只做能产生决策或故事的拟真 |

### 2.2 Songs of Syx —— 借「规模与政治」，弃「同屏规模」

| 维度 | 它的做法 | 我们的取舍 |
| --- | --- | --- |
| 人口规模 | 数百到上千人 | **改**：目标 60–150 居民/殖民地；超出部分用「世界地图抽象层」承接 |
| 多种族 | 人类/矮人/精灵/兽人等，各有偏好与冲突 | **借**：2–4 个可玩种族/文化，影响需求、建筑、饮食、外交 |
| 经济纵深 | 生产链、价格、税收、贸易 | **借**：实物物流 + 价格波动的商队贸易 |
| 政治层 | 法律、阶级、奴隶制、贵族议会 | **借（后期）**：律法与阶级作为 M4 内容，谨慎处理伦理表达 |
| 大战略地图 | 多殖民地、征服、外交 | **改**：抽象世界地图层（见 [世界与模拟总纲](04-world-and-simulation.md)） |
| 数百人同屏即时演算 | 性能取向 | **弃**：Minecraft tick 预算不允许；改为 LOD / 抽象模拟 |
| 饥荒与死亡的高强度 | 大量饿死是常态 | **改**：保留饥荒作为危机，但强度可调，且有预警与救济手段 |

### 2.3 RimWorld —— 借「人物张力与事件设计」，弃「网格小地图」

| 维度 | 它的做法 | 我们的取舍 |
| --- | --- | --- |
| 需求与情绪 | 需求条 → 情绪 → 精神崩溃阈值 | **借（核心）**：直接对标，见 PRD-001 |
| 叙述者（Narrator） | 卡桑德拉/菲比/兰迪控制事件节奏 | **借（核心）**：叙述者风格 + 事件冷却 + 前兆规则 |
| 关系与社交 | 好感/敌意/恋爱/婚姻/争执 | **借**：关系网 + 社交事件 + 婚育 |
| 医疗与手术 | 伤病、感染、义体 | **借（裁剪）**：伤病、感染、草药/药品；不做外科手术小游戏 |
| 囚犯与招募 | 俘虏、说服、招募 | **借（后期）**：战俘与收留难民 |
| 事件卡（Incident） | 有明确选项与后果 | **借**：事件系统的形状（选项化事件 + 权重表 + 冷却） |
| 网格小地图 + 单人小队 | 3–20 人，单格地图 | **弃**：我们是连续世界 + 更大人口 |
| 殖民者作为唯一劳动力 | 玩家必须微观指挥 | **改**：意图层优先，微观控制可选 |

### 2.4 Stonehearth —— 借「职业与建造」，弃「线性王国剧情」

| 维度 | 它的做法 | 我们的取舍 |
| --- | --- | --- |
| 职业体系 | 工匠树、进阶职业、专属工坊 | **借**：职业进阶 + 工坊专属 + 作品品质 |
| 蓝图建造 | 玩家画蓝图，工人自动建造 | **借**：Folkways 的图案/蓝图已具备，强化「玩家设计 → 居民施工」 |
| 风格化与可爱 | 低多边形、明亮 | **借（美术方向）**：用材质包/模型整合出温暖风格，不追求写实 |
| 怪物袭击（Goblins） | 波次袭击与防守 | **借**：袭击 + 城墙 + 民兵 + 陷阱 |
| 线性剧情与固定阵营 | 剧情推进固定 | **弃**：改为涌现叙事 + 可选剧本 |
| 工程感弱（无机械/铁路/自动化） | —— | **补**：这是我们的差异化（整合 Create、铁路、飞艇） |

### 2.5 补充参考（单点机制）

| 来源 | 单点机制 | 我们怎么用 |
| --- | --- | --- |
| Banished | 季节与储粮、人口曲线、教育 | 农时与冬季压力、人口年龄结构、学徒制 |
| Oxygen Not Included | 资源循环与气体/温度、连锁故障 | 公共卫浴、供能、通风（仅在工业时代作为一层机制） |
| Going Medieval | 3D 多层建造、温度与光照 | 建筑内部的温度与照明影响居民 |
| Manor Lords | 劳动力分配与区域经济 | 劳动力面板、区域分工 |
| Kenshi | 无主角的沙盒、派系 | 派系与关系、可被攻击的世界 |
| Frostpunk | 道德抉择与社会张力 | 事件选项的道德两难（但必须给第三条路） |
| Create (mod) | 机械与自动化、蓝图 | 直接整合：玩家机械能被居民使用/维护 |
| Minecolonies | 建筑放置 + 工人自动化 + 请求系统 | 我们必须在「意图层」和「人味」上做到它没有的深度 |
| MineFortress / Tektopia | 村民殖民地、袭击 | 参考其袭击与防御循环；我们做更深的个体模拟 |

| Dwarf Colonies | Minecolonies 的矮人分支 | 说明「矮人主题 + MC」有明确需求，但缺少「涌现叙事」 |

## 4. 明确「弃」的清单（防止膨胀）

| 弃 | 来源 | 理由 |
| --- | --- | --- |
| ASCII / 极端操作复杂度 | DF | 用户群与体验目标不符 |
| 上千人口同屏 | Syx | 性能不可行，用抽象层替代 |
| 外科手术小游戏、器官移植 | RimWorld | 决策价值低、实现成本高 |
| 线性主线剧情 | Stonehearth | 与涌现叙事冲突 |
| 多人 PVP / 竞技 | —— | 反支柱 |
| 口渴/排泄拟真 | 硬核生存 mod | 与「殖民地经营」主体验无关 |
| 无敌对势力也能通关的纯建造 | —— | 会失去 P3 的决策压力 |

## 6. 结论

1. **我们的不可替代性 = P1（意图层）× P2（人味）× P4（进程）三者的交集**。单看任何一项都有竞品更强，但「在 Minecraft 里、用意图层驱动、每个人都是故事、还能一路走到星辰」目前没有直接竞品。
2. **Folkways 已经解决了最难的一半**：自主规划劳动 + 意图层 + 数据包内容体系。我们的工作重心应在**人味（需求/情绪/关系/记忆）**与**世界压力（事件/威胁/进程）**，而不是重写物流。
3. **性能是硬边界**：任何「规模」类设计都必须先过 [性能预算](../pack/03-performance-budget.md)。
4. **每个机制必须写下「预防/缓解/承受」三条路径**，否则不允许进入 PRD。
