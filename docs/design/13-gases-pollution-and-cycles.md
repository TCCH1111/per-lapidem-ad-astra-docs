> 缺氧（Oxygen Not Included）最迷人的不是"气体"这个题材，而是**一格一物造成的连锁故障**：
> 一个通风口堵了，二十个周期后整个殖民地因为二氧化碳堆积而停摆。

## 1. 目标与非目标

### 1.1 目标

| 编号 | 目标 | 可判定信号 |
| --- | --- | --- |
| G1 | 空气是**有质量的资源**，不是背景 | 密封房间能维持可呼吸空气；通风/过滤/循环是玩家必须建造与维护的东西 |
| G2 | 污染有**真实后果**且**与工业联动** | 烟囱/炉/发电机的排放会改变它所在分区与下风向分区的空气；后果可测（效率/健康/作物） |
| G3 | 必须产生**连锁故障** | ≥6 条因果链可复现（§6），每条都有前兆与三路应对（预防/缓解/承受，对应支柱 P3） |
| G4 | 资源循环**闭环可建成** | ≥4 条闭环（水/碳/废物/烟，§5），每条给出输入、输出、建筑、工作与失效模式 |
| G5 | 一切由**居民执行** | 通风、堵漏、灭火、戴面具、换滤芯、撤离都是工作或 `Urge`；玩家不能靠手动吹散气体解决问题（ADR-013） |
| G6 | 性能与存档**可控** | 常态 ≤2%、峰值 ≤5%（§9）；存档体积随**分区数**而非方块数增长（§11） |
| G7 | 温度场**只有一套** | 本层提供温度，[PRD-003](../prd/PRD-003-season-temperature-thirst-nutrition.md) 的温度场改为消费本层（ADR-016，§3.6） |

### 1.2 非目标

| 编号 | 不做 | 理由 |
| --- | --- | --- |
| N1 | **不做 ONI 式逐格气体仿真**（每格独立压力/温度/组成 + 每 tick 流体解算） | 性能、多人同步、存档体积三项都不可接受（§2 对比表） |
| N2 | 不做第二个温度系统 | ADR-016；温度必须由本层统一提供，否则 PRD-003 与本层会互相打架 |
| N3 | 不采用 `Pollution of the Realms`（**CC-BY-ND** + 实测性能差） | 用户裁决；且 ND 禁止演绎，我们无法按其理念改造 |
| N4 | 不打包任何外部污染 mod；桥接若做必须**可整套删除** | ADR-010 纪律（缺失时功能降级但完整可玩） |
| N5 | 不把"空气污浊/缺氧"做成新的**需求** | **vitals 不进需求栏**（ADR-009）；需求集是数据驱动注册表（[PRD-001](../prd/PRD-001-needs-mood-memory.md)）；气体只能作为 vitals 或需求/情绪的**输入**（§3.7） |
| N6 | 不做气体驱动的"魔法死亡"（进屋即死） | 必须有前兆与可读的死亡原因（P3 + [PRD-002](../prd/PRD-002-incidents-and-narrator.md)） |
| N7 | 不做跨维度的全球大气 | 分区只存在于**已加载/被追踪**的空间；方块默认是"透气边界"而非真空 |

### 1.3 里程碑归属（2026-10-18 裁决）

**完整气体层放在 M4；M3 只预埋接口，不承诺实现。** 这条裁决是为了保护 M3 的范围（M3 已经背着时代/知识/经济扩展三件大事）。

| 里程碑 | 范围 | 明确不做 |
| --- | --- | --- |
| **M3（接口预埋）** | ① 数据包契约：`gas_source`/`gas_sink`/`gas_barrier` 的**注册与读取**（可以没有气体量的结算，但声明必须能解析、能进 `/reload` 自检、能被诊断列出）；② **作物与疾病的最小读取面**：一个只读查询"某坐标的空气污染指数"（M3 阶段可由常数值/区域属性填充），供 [PRD-003](../prd/PRD-003-season-temperature-thirst-nutrition.md) 的农业与未来的疾病系统消费；③ 温度**门面接口**先立起来（PRD-003 通过它取温度，M3 仍可用 PRD-003 的过渡实现，M4 换成本层池）；④ 三个 spike（§10）可在 **M3 末尾**执行 | 分区池结算、梯度、反应器、爆炸、中毒、闭环产线、覆盖层 |
| **M4（实现范围）** | ① 分区池 + 边界梯度的完整结算与节拍；② 7 种气体与 4 类挂点的**运行时**行为；③ §5 的 4 条闭环；④ §6 的 8 条连锁故障与全部前兆/应对；⑤ §7 的居民行为；⑥ 气体覆盖层与仪器；⑦ 空间站复用（与 [PRD-011 §9.6](../prd/PRD-011-progression-knowledge-and-space.md) 的离屏批次结算同一机制）；⑧ §9 的探针与降级阶梯 | —— |

**R-GAS-29**：M3 期间**不得**出现"半套气体层"（例如只实现排放却不实现扩散）——预埋的接口必须**可缺失、可返回中性值**，让 M3 在 `gas_layer_enabled=false` 的语义下完整可玩（与 ADR-010 同一纪律）。
**R-GAS-30**：M4 实现时**不得**要求 M3 的内容返工；若发现必须返工（例如 §3.6 的温度门面设计不成立），以 spike 结论为准**先改本文件与 ADR-016**，再动代码。

## 2. 模型选择：为什么是「分区池 + 格级梯度」

### 2.1 三条路线对比

| 维度 | A. 真·逐格仿真（ONI） | B. 纯分区池（每房间一个混合值） | **C. 混合（采用）** |
| --- | --- | --- | --- |
| 每 tick 成本 | O(格数 × 气体数)；一个 32³ 的厂房就是 32 768 格 | O(分区数) | O(分区数) + O(边界层格数 × 气体数) |
| 存档体积 | O(格数)（百万级） | O(分区数) | O(分区数) + 少量格级缓存（**不存**，见 §11） |
| 多人同步 | 每格变化都要广播 → 不可行 | 每分区变化可增量广播 | 同 B（格级只影响视觉，走客户端预测） |
| 连锁故障能力 | 最强（局部梯度自然涌现） | **弱**：房间内匀质，看不出"角落先积气" | **够用**：池决定"什么时候出事"，梯度决定"哪里先出事" |
| 可视化 | 逐格热力图 | 房间色块 + 一个浓度值 | 房间色块 + 边界渐变（[d09 §5](09-interaction-and-ui.md) 覆盖层） |
| 可改写性 | 参数极多、难以平衡 | 少量参数 | 中等（§8/§12） |
| 判定 | 否 | 否 | **采用** |

**R-GAS-1**：**禁止**任何"每 tick 遍历全部方块/全部格"的气体计算；气体结算只能遍历**分区**与**分区边界层**（对应 [pack/03 R-PB-4](../pack/03-performance-budget.md)）。
**R-GAS-2**：分区池是**权威数据**；格级梯度是**派生数据**，可以从池重建（丢了不算丢档）。

### 2.2 混合模型为什么仍能产生"ONI 式"连锁故障

连锁故障的**必要条件是延迟与耦合**，不是逐格精度。我们靠三件事拿到它：

| 机制 | 说明 | ONI 对应物 |
| --- | --- | --- |
| **池的惯性** | 分区有体积（热容/气容），注入与抽出是**速率**，所以"发现晚了"是必然的 | 气体扩散慢 |
| **边界梯度** | 泄漏/扩散只在门、通风口、破损处发生，且**由内向外的方向性**（烟往哪飘、CO₂ 往哪沉） | 一格一物的方向感 |
| **阈值 + 居民反馈环** | 阈值触发居民行为（撤离/戴面具/抢修），行为改变产出，产出影响下一次维护能力 | 复制人窒息前的抢修 |

**R-GAS-3**：每条连锁链（§6）必须在文档里写出**延迟量级**（从触发到不可逆后果的游戏时长），因为"来得及反应"是这套系统的体验核心。

## 3. 数据模型

### 3.1 空间切分：分区图（Region Graph）

| 项 | 设计 |
| --- | --- |
| 分区（`GasRegion`） | 一个**空气连通域**：由密封面（实心方块）、门、通风口、气闸围成的连通空间 |
| 切分依据 | 空气可通行性 + 密封等级；门视为**高阻隔**（不切断分区，但降低交换速率）；气闸视为**两级缓冲**（两个相连分区，逐个开） |
| 空间哈希 | 复用基底的 `Section`（8×8×8 体素，`SHIFT = 3`）作为分区归属的加速结构（[r01:55](../research/01-core-engine.md)，`LocalGrounds.java:12`、`Survey.java:26`）——**只是索引，不改变其寻路语义** |
| 脏标记 | 方块变化经 `BlockChanges.listen` → `LocalGrounds.blockChanged` 的既有链路标脏（[r01:55](../research/01-core-engine.md)），分区**事件驱动重建**，不做每 tick 扫描 |
| 分区上限 | `region_count_cap`（默认 2048）；超限时合并且**必须告知**（降级阶梯第 4 档，§9.4） |
| 垂直分层 | 分区内按密度做**软分层**（可配置开关）：烟/蒸汽偏上、CO₂/可燃气偏下 → 只影响**边界层采样**与阈值判定位置，不做逐格解算 |

**R-GAS-4**：分区的重建必须是**增量**的（只重算脏区块相关的分区），且重建次数必须进探针（§9.3）。
**R-GAS-5**：`Section` 只是空间索引；**不得**修改基底对 `Section` 的寻路失效语义（L4 禁区，[d12 §10](12-fork-strategy.md)）。

### 3.2 格级梯度（边界层）

| 项 | 设计 |
| --- | --- |
| 范围 | 只在**分区边界**的 `gradient_width` 层内计算（默认 3 层，范围 1–8） |
| 内容 | 每种气体的**方向性浓度**：从高浓度分区指向低浓度分区，穿过门/口/破损处 |
| 用途 | ① 可视化（覆盖层渐变）② 阈值判定位置（"门边先呛到"）③ 泄漏通量计算 |
| 不存 | 梯度是**运行期派生数据**，不写存档（R-GAS-2） |
| 成本 | 与**边界面积**成正比，不与体积成正比——这是混合模型的关键收益 |

**R-GAS-6**：梯度计算必须在 `gradient_width` 之外**直接取池值**（插值），禁止为了"平滑"而扩到整个分区。

### 3.3 气体种类

| 气体 | 来源 | 汇 | 危害 | 可见性 | 危险特性 |
| --- | --- | --- | --- | --- | --- |
| **O₂ 氧** | 藻池、电解、罐装补给、通风（外部） | 呼吸、燃烧、电解逆向（少见） | 过低 → 缺氧（vitals） | 覆盖层（淡蓝） | — |
| **CO₂ 二氧化碳** | 呼吸、燃烧、堆肥、发酵 | 藻池、洗涤、通风 | 浓度升高 → 意识/效率下降；极高 → 窒息 | 覆盖层（灰） | 比空气重（下沉） |
| **CO 一氧化碳** | 不完全燃烧（缺氧的炉/窑） | 通风、催化氧化 | **中毒**（剂量累积，可不流血地减员） | 覆盖层（暗红，需仪器） | **无色无味 → 必须先有仪器/症状才可见** |
| **烟（颗粒）** | 木材/煤燃烧、火灾 | 沉降、洗涤器、过滤 | 呼吸系统病、美感下降、能见度 | 覆盖层（黑） | 与可燃气/CO 常同时出现 |
| **可燃气** | 沼气池、煤/油、电解副产 H₂ | 燃烧（当燃料）、受控排放 | 达到爆炸极限 + 火源 → **爆炸** | 覆盖层（黄，需仪器） | 爆炸下限/上限（§8） |
| **蒸汽** | 沸腾、洗涤、冷凝失效 | 冷凝器、通风 | 烫伤、腐蚀、遮蔽 | 覆盖层（白） | 携带大量热（§3.6） |
| **污浊（污染）** | 垃圾/粪便堆积、尸体、工业排放、污水 | 通风、洗涤、填埋、净化 | 疾病风险、作物减产、美感下降 | 覆盖层（褐绿） | 与温度/湿度耦合（热 + 湿 = 更糟） |

**R-GAS-7**：`CO` 与 `可燃气` **默认不可裸眼看见**，必须由仪器（气体探测器方块）或居民症状揭示——这是"工业时代的代价"的一部分（[d08:36](08-progression-and-ages.md) 已把污染列为工业时代压力）。
**R-GAS-8**：每种气体必须有**可见性规则**（裸眼/覆盖层/仅仪器），不允许"玩家看得到但居民不知道"或反之（信息一致性，P5）。

### 3.4 压力、泄漏与密封

| 概念 | 定义 | 作用 |
| --- | --- | --- |
| 池量 `amount[gas]` | 分区内该气体的**分子量抽象值**（非真实物理单位） | 一切结算的基本量 |
| 压力 `pressure` | `Σ amount / volume`（仅用于**过压破裂**与通风判定） | 高压 → 破损风险；低压（真空）→ 缺氧 |
| 交换速率 | 相邻分区间 `k × 边界面积 × 压差`；`k` 由门的开闭与密封等级决定 | 门开 → 快速混合；气闸 → 分级放气 |
| 泄漏 | 密封完好度 `seal` 低于阈值时，按 `leak_rate` 与环境交换 | 破损、爆炸、塌方都会降低 `seal` |
| 过压 | `pressure > burst_threshold` → 结构受损/破裂 | 给"密闭 + 加热"一条真实的危险路径 |

**R-GAS-9**：气闸（airlock）必须是**两级缓冲**，一次只开一层；单门 + 高浓度差 = 快速污染（这是可预期的玩法，不是 bug）。

### 3.5 密封性与建筑挂点

| 建筑/构件 | 作用 | 参数 |
| --- | --- | --- |
| 墙/地板/天花板 | 密封面 | `seal` 材质分档（土/木/石/金属/玻璃） |
| 门 | 高阻隔 + 通行 | `seal_closed` / `exchange_open` |
| 窗 | 密封但透光 | 保温差、易碎（破 → 泄漏） |
| 通风口 | 定向交换 | 被动（压差驱动）/ 动力（风机） |
| 气闸 | 两级缓冲 | 逐级放气/充气时间 |
| 管道 | 点对点输气 | 通量上限 + 泄漏率（与工厂挂点同契约） |
| 风机/净化器/洗涤器 | 主动搬运/清除 | 耗能、耗材（滤芯） |
| 气体探测器 | 揭示 CO/可燃气 | 耗能；报警进事件系统 |

**R-GAS-10**：所有挂点都是**数据可声明的对外契约**（§4/§12），基底与其它 mod 的方块可以注册为"排放源/吸收源"，**不需要**我们逐个硬编码。

### 3.6 温度耦合（统一温度场）

| 项 | 设计 |
| --- | --- |
| 热载体 | 每个分区的气体**携带热量**（热容由气体组成决定：蒸汽 ≫ 空气） |
| 产热源 | 炉/窑/发电机/火源/居民体热/阳光（经 [PRD-003](../prd/PRD-003-season-temperature-thirst-nutrition.md) 的季节曲线） |
| 反应热 | 燃烧（放热）、电解（吸热）、堆肥（放热）、冷凝（放热） |
| 对外接口 | 本层导出一个**只读温度查询**：`(坐标) → 环境温度`；[PRD-003](../prd/PRD-003-season-temperature-thirst-nutrition.md) 的 `TemperatureField` 改为**它的门面**（facade），不再自建采样器 |
| 缓存与失效 | 复用 PRD-003 的采样 + 缓存 + TTL 纪律（`field_sample_radius` 64 / `field_cache_ttl` 1200 tick，[PRD-003:254-255](../prd/PRD-003-season-temperature-thirst-nutrition.md)），但采样数据源改为分区池 |

**R-GAS-11（ADR-016 的落地）**：温度**只有一个数据源**（本层的分区池）。PRD-003 的"禁止逐方块逐 tick 重算"（[PRD-003 R-CL-3](../prd/PRD-003-season-temperature-thirst-nutrition.md)）在本层仍然成立，且更严格：**逐格温度不计算**。

## 4. 与工业的联动挂点（对外契约）

这是用户认可 Pollution of the Realms 的**那个理念**：污染必须从真实设施里冒出来，而不只是"某个方块的范围 debuff"。

### 4.1 四类挂点（全部数据可声明）

| 挂点 | 语义 | 关键参数 | 例子 |
| --- | --- | --- | --- |
| **排放源 `gas_source`** | 按速率往所在（或朝向）分区注入气体 | 气体、速率、条件（燃烧中/转速/温度）、位置与**朝向**（烟囱方向） | 炉、窑、烟囱、发电机、沼气池、尸体、垃圾堆 |
| **吸收源 `gas_sink`** | 按速率抽取 | 气体、速率、条件、耗材、副产物 | 藻池、洗涤器、过滤器、冷凝器 |
| **反应器 `gas_reactor`** | 气体之间的转化 | 输入比例、输出比例、ΔT、条件（电/光/水/催化） | 电解槽、燃烧室、堆肥池 |
| **屏障 `gas_barrier`** | 定义密封与交换 | 密封等级、开启时的交换率、破损阈值 | 墙、门、窗、气闸、厂房壳体 |

### 4.2 烟囱为什么必须支持"方向"

**R-GAS-13**：烟囱必须能把排放**指向一个方向/高度**（而非四面扩散），因为"把烟囱建在菜地上风处"应当是玩家会后悔的具体决定（与 [PRD-003](../prd/PRD-003-season-temperature-thirst-nutrition.md) 的作物减产联动，§6 C3）。

### 4.3 与 Create 等 mod 的关系

| 项 | 立场 |
| --- | --- |
| 硬依赖 | **无**（R-GAS-14） |
| 可选互操作 | 若装了 Create 系：其风机/管道/燃烧设备可作为 `gas_source`/`gas_sink` 的**注册者**（compat 桥接，可整套删除，ADR-010） |
| `create-smog`（MIT） | 仅作**参照**（它的"雾/能见度"表现思路值得借）；是否引入未定（OQ-5） |
| 冲突风险 | 两个系统同时改同一片空气 → 以本层为唯一权威；外部 mod 的"空气效果"若与我们冲突，禁用其效果而不是禁用它（§13） |
| **外部污染 mod（2026-10-18 补充核实）** | `Pollution of the Realms` = **CC-BY-ND 4.0**（**禁止演绎** → 无法按它的理念改造）；`wuziyue840/repother-reload`（RePother 的移植）**仓库无任何许可证 = ARR**，且 **0 star / 2026-08 后未动** → **两者都只能作参照**，不打包、不 fork、不作依赖。**唯一允许的形态**：若将来出现**许可允许**的同类 mod，只能以**单向只读输入**接入（把它的污染值当作 `gas_source`/只读采样），**不得让它成为第二套权威**（R-GAS-31） |

**R-GAS-31（2026-10-18）**：任何外部污染/气体 mod 与本层的关系**只能是"输入或表现"，不能是"权威"**——外部值可以喂进我们的分区池，但**权威状态永远在我们这里**（存档、诊断、多人同步都只有一份）。这条是为了防止"两个 mod 各记一份污染，删掉一个存档就变了"。**注**：PoTR 系 mod 能影响**原版生物**，但那不等于能影响**我们的居民**——居民是自定义实体，需求/vitals 走我们自己的模型（[PRD-001](../prd/PRD-001-needs-mood-memory.md)），这才是必须自研的真正原因。

**R-GAS-14**：本层的功能在**没有任何外部 mod**时完整可用；桥接缺失只允许降低"表现丰富度"，不允许降低模拟能力。

## 5. 资源循环（4 条可建成闭环）

闭环的判据：**输入自持 + 输出被消费 + 中间产物有去处**。任一条不满足，就只是"一条会堵死的产线"。

### 5.1 水 → 电解 → O₂ + H₂ → （燃烧/发电）→ 水（冷凝回收）

| 项 | 内容 |
| --- | --- |
| 输入 | 水（井/河/冷凝）、电 |
| 输出 | O₂（供呼吸）、H₂（燃料/发电） |
| 建筑 | 电解槽（`gas_reactor`）、储气罐、管道、冷凝器 |
| 工作 | 加料、维护、换件（居民，走 `colony.submit`） |
| 闭环条件 | 燃烧/发电产生的水蒸气**必须**被冷凝器回收，否则循环净亏水 |
| 失效模式 | 缺电（O₂ 断供 → §6 C8）、冷凝器冻结（冬天）、氢气泄漏（§6 C4） |
| 验收判据 | 连续 3 游戏日：O₂ 浓度稳定在阈值以上，且**水净消耗 ≤ 补给能力** |

### 5.2 CO₂ + 藻池（光 + 水）→ O₂ + 生物质

| 项 | 内容 |
| --- | --- |
| 输入 | CO₂（呼吸/燃烧）、水、光（日照或灯）、温度窗口 |
| 输出 | O₂、生物质（→ 食物/堆肥/饲料） |
| 建筑 | 藻池（`gas_sink` + 生长方块）、灯、供热 |
| 闭环条件 | 光照与温度必须**人工保障**（冬天/地下需要灯与热），否则冬天集体失效 |
| 失效模式 | 温度过低 → 光合停止 → CO₂ 堆积（§6 C1） |
| 验收判据 | 冬天连续 3 日：CO₂ 不超阈值，且生物质产出 ≥ 维持灯/热的消耗 |

### 5.3 废物（粪便/垃圾/尸体）→ 堆肥 / 沼气 → 肥料 + 燃料

| 项 | 内容 |
| --- | --- |
| 输入 | 废物（**如厕与卫生的产物**）、水、可燃气 |
| 输出 | 肥料（→ 作物）、沼气（→ 燃料/发电 → CO₂ → 回到 5.2） |
| 建筑 | 厕所/化粪池、堆肥池、沼气池、储气罐 |
| 闭环条件 | 肥料要有田去消耗、沼气要有设备去烧；否则池子满了就变成污染源 |
| 失效模式 | 沼气池超压 → 爆炸（§6 C4）；堆肥过湿/过热 → 恶臭与污浊扩散（§6 C3） |
| 验收判据 | 连续 7 游戏日：废物**零堆积**（或被安全填埋），肥料产出 ≥ 农田需求 |
| **缺口（2026-10-18 已闭合）** | ~~如厕/卫生需求在 PRD-001 中尚未出现~~ → **已落地**：[PRD-001](../prd/PRD-001-needs-mood-memory.md) 已把**如厕做成计量式需求**（膀胱/肠道计量 + **失禁** + **卫生压力出口**），本闭环的**输入侧已有着落**（粪便/污水由如厕与卫生产出） |
| **我们自建的"联动厕所"（2026-10-18 定，ADR-019）** | 除 PoopSkyMod 提供的方块对外，我们**自己再加一套与殖民地系统联动的厕所**：**公厕**（多蹲位/排队）、**旱厕+粪坑**、**堆肥厕所**、**沼气池**。它们同时是**需求满足点**与**工作地点**（掏粪/清坑/清堵/维护都是居民自己的活，走 `Urge`/`Node`/`submit`）；产出进本闭环，**臭味/污浊进气体层**，**堵塞或溢出会产生事故**（丑闻、疾病、恶臭扩散） |

### 5.4 烟（颗粒）→ 洗涤/过滤 → 洁净气 + 副产物（灰/硫/焦油）→ 建材/药剂/填埋

| 项 | 内容 |
| --- | --- |
| 输入 | 烟、水（湿法洗涤）、耗材（滤芯） |
| 输出 | 洁净气（可回流室内）、灰（建材/肥料）、硫/焦油（药剂/燃料/污染源） |
| 闭环条件 | **副产物必须有去处**：填埋场（占地方、会渗出污浊）、建材、或再加工 |
| 失效模式 | 滤芯不换 → 效率归零（§6 C2）；洗涤水不处理 → 污水 → 污浊 |
| 验收判据 | 连续 3 游戏日：烟浓度在室内阈值以下，且副产物无堆积 |

### 5.5 元素账（用于验证"闭环是否真的闭"）

| 元素 | 主要来源 | 主要汇 | 平衡判据 |
| --- | --- | --- | --- |
| 氧 O | 藻池、电解、通风 | 呼吸、燃烧 | 室内 O₂ 不长期下降 |
| 碳 C | 燃料、食物、CO₂ | 藻池、作物、洗涤 | CO₂ 不长期单调上升 |
| 水 H₂O | 井/河/冷凝/补给 | 电解、洗涤、饮用、灌溉 | 净消耗 ≤ 补给 |
| 氮 N（可选） | 空气、肥料、堆肥 | 作物、排放 | 仅在引入氮肥时启用（OQ-9） |
| 能量 | 燃料、电、日照 | 电解、风机、灯、热 | 供能 ≥ 维持生命支持所需 |

**R-GAS-15**：每条闭环必须在**游戏内可查**（"这个循环现在净亏什么"），复用 [PRD-006](../prd/PRD-006-stock-rules-and-diagnosis.md) 的存量预测与"为什么"精神，禁止另做一套。

| `seal_breach_threshold` | 0.6 | 0.2–0.9 | 破损多严重开始漏 |
| `burst_pressure` | 3.0×额定 | 1.5–8× | 爆炸/破裂的宽容度 |
| `o2_hypoxia_mild/severe` | 17% / 12% | 10–20% | 缺氧体感（默认**温和**，[PRD-003 §1.1 的教训](../prd/PRD-003-season-temperature-thirst-nutrition.md)） |
| `co2_efficiency_knee` | 1.5% / 3% / 5% | 0.5–10% | 效率惩罚曲线折点 |
| `co_poison_dose_per_hour` | 100 ppm·h | 20–1000 | 中毒节奏（越低越硬） |
| `lel_lower/upper`（可燃气） | 5% / 15% | 3–20% | 爆炸窗口（越窄越安全） |
| `pollution_crop_penalty` | −15% / 满污染 | 0–60% | 农业压力（与 [PRD-003](../prd/PRD-003-season-temperature-thirst-nutrition.md) 作物） |

| `region_budget_micros` | 800 /tick | 200–4000 | 性能预算硬上限（§9） |
| `gas_layer_enabled` | true | — | 不想玩气体的存档（必须能关且不崩） |
| `station_batch_days` | 1 游戏日 | 6 小时–7 天 | 与 [PRD-011 `abstraction_batch`](../prd/PRD-011-progression-knowledge-and-space.md) 同一参数 |

## 9. 性能预算与降级

### 9.1 预算（从 [pack/03 §2](../pack/03-performance-budget.md) 的余量里扣）

| 项 | 常态 | 峰值 | 说明 |
| --- | --- | --- | --- |
| 分区扩散（每 `diffusion_period_ticks`） | ≤1.0% | ≤1.5% | 与分区数 + 边界面积线性 |
| 气相反应（每 `reaction_period_ticks`） | ≤0.3% | ≤0.5% | 反应器数量上限受控 |
| 分区重建（事件驱动） | ≈0 | ≤1.0% | 只在方块变化/爆炸时 |
| 温度查询（供 [PRD-003](../prd/PRD-003-season-temperature-thirst-nutrition.md)） | ≤0.5% | ≤0.5% | 命中缓存时是查表 |
| 火灾/爆炸/大范围泄漏 | ≈0 | ≤2.0% | 峰值事件 |
| **合计** | **≤2%** | **≤5%** | [pack/03 R-PB-2](../pack/03-performance-budget.md) 要求常态/峰值两项估值 |

**R-GAS-21**：本层**独立立账**（与 [PRD-011 R-AG-18](../prd/PRD-011-progression-knowledge-and-space.md) 的太空账分开），并提交探针。
**R-GAS-22**：任何一次结算不得超过 `region_budget_micros`；超预算时按 §9.4 **降级并告知**，绝不静默少算（[pack/03 R-PB-6](../pack/03-performance-budget.md)）。

### 9.2 结算节拍（决定成本的根因）

| 系统 | 节拍 | 复杂度 | 依据 |
| --- | --- | --- | --- |
| 扩散/交换 | `diffusion_period_ticks`（默认 20 tick） | O(分区数 + 边界层) | [Cadence.Cron 相位选择](../research/01-core-engine.md)（`Cadence.java:82`） |
| 反应 | `reaction_period_ticks`（默认 100 tick） | O(反应器数) | 同上 |
| 分区重建 | 事件驱动 | O(脏区块) | `BlockChanges.listen`（[r01:55](../research/01-core-engine.md)） |
| 池→需求/情绪输入 | 每游戏小时 | O(居民数 × 所在分区) | 与 [PRD-001](../prd/PRD-001-needs-mood-memory.md) 的小时节拍一致 |
| 汇总/统计/预测 | 每游戏日 | O(分区数) | [pack/03 §3](../pack/03-performance-budget.md) |
| 离屏批次 | `station_batch_days` / 按批次 | O(分区数) | 与 [PRD-011 §9.6](../prd/PRD-011-progression-knowledge-and-space.md) 同一机制 |

### 9.3 探针（没有探针不许合并）

| 探针 | 度量 |
| --- | --- |
| `gas-regions` | 分区数、平均/最大体积、边界面积 |
| `gas-update-micros` | 单次扩散耗时（平均 / 95 分位） |
| `gas-rebuilds` | 分区重建次数与原因分布 |
| `gas-reactions` | 各反应器吞吐与副产物堆积 |
| `gas-events` | 火灾/爆炸/泄漏/中毒次数与持续时长 |
| `gas-save-bytes` | 存档中气体数据的字节数 |

**R-GAS-23**：必须能回答"这个档的气体系统花了多少 tick"（[pack/03 R-PB-7](../pack/03-performance-budget.md)）。

### 9.4 降级阶梯（单调、可预测、必须告知）

| 顺序 | 措施 | 影响 | 告知 |
| --- | --- | --- | --- |
| 1 | 梯度层数 3 → 1 | 边界表现变粗 | 是（配置可关提示） |
| 2 | 扩散周期 20 → 40 tick | 气体反应变慢 | 是 |
| 3 | 反应周期 100 → 200 tick | 产线响应变慢 | 是 |
| 4 | 远处分区冻结（并入离屏批次） | 远方变化变慢 | 是 |
| 5 | 站内/远层细节降频 | 诊断精度下降 | 是 |
| 6 | 关闭气体层（`gas_layer_enabled=false`） | 玩法整体缺失 | **必须明确告知**（[pack/03 R-PB-5](../pack/03-performance-budget.md)） |

**R-GAS-24**：降级不得改变**已经发生**的世界状态（不许"降级后毒气消失了"），只能降低**更新频率**。

### 9.5 多人

| 项 | 策略 |
| --- | --- |
| 权威 | **服务端**（池、压力、反应、爆炸判定全部服务端权威） |
| 同步 | 只广播**玩家所在分区 + 相邻分区**的增量；格级梯度由客户端按同一公式重建（客户端预测，允许短暂不一致） |
| 防作弊 | 客户端不能上报"我这边没毒气"；点火/排放等**不可逆**动作服务端复核（[PRD-012](../prd/PRD-012-multiplayer-and-permissions.md)） |
| 共享聚合 | 每个分区**只算一次**，禁止按玩家重复计算（与 [PRD-003 R-MP-1](../prd/PRD-003-season-temperature-thirst-nutrition.md) 同款纪律） |
| 降级 | 与单人同一阶梯，但**任何影响玩法的降级必须对所有玩家可见** |

## 10. 先行 Spike（2–3 个，必须先做；**排期在 M3 末尾**）

> 按 §1.3 的里程碑裁决：spike 属于 **M3 的收尾动作**，M4 才进入完整实现。

| # | spike | 验证什么 | 通过判据 |
| --- | --- | --- | --- |
| **S1** | 合成世界造 **1000 个分区**（含边界层），按 `diffusion_period_ticks=20` 跑 20 TPS | 混合模型的**性能上限**与是否值得继续 | 单次扩散 95 分位 < 预算的 60%；整层常态 ≤2% |
| **S2** | 泄漏发生在**区块卸载边界**：加载 → 泄漏 → 卸载 → 重新加载 | 气体守恒（不许因卸载凭空消失/倍增） | 往返后总量漂移 <±5%，且不产生"爆炸复现" |
| **S3** | 密封破损 → 可燃气爆炸 → 地形破坏 → 存档往返 | 破坏、存档、多人的一致性（这是最贵的一块） | 存档往返后无重复破坏、无残留爆炸；客户端重连不二次起爆 |

**R-GAS-25**：三个 spike 全部通过前，**PRD-014 不进入实现**；任一不通过则回退到"B 纯分区池"（§2.1），并同步修订本文件与 ADR-016。

## 11. 数据与存档

| 项 | 策略 |
| --- | --- |
| 存档内容 | 每分区：`amount[gas]`、温度、体积、`seal`、开口状态、反应器状态；**不存**格级梯度 |
| 存档体积 | O(分区数 × 气体数)；按 §8 默认估算需实测（§13 未验证项） |
| 卸载/未加载 | 冻结 + 按批次结算（与 [PRD-011 §9.6](../prd/PRD-011-progression-knowledge-and-space.md) 同一机制）；**不加载区块** |
| 版本与迁移 | 自管版本号；缺字段取默认；旧档 = 无气体层（`gas_layer_enabled=false` 等价），世界不损坏 |
| 未知气体/反应器 | 数据包被移除 → 标记"来源缺失"，其量按**惰性**处理，不崩、不静默丢进度 |
| 卸载 mod | 存档必须可加载（丢失气体层，世界与居民仍在） |
| 回滚 | 崩溃恢复按"先写快照后结算"防重复爆炸/重复给料（与 [PRD-007](../prd/PRD-007-scenarios.md) 的开局固化同款纪律） |

**R-GAS-26**：**不可逆动作必须先落盘再结算**（点火、purge、爆炸），否则服务器崩溃会导致"爆炸回滚"或"爆炸双发"。

## 16. 落地 PRD 待建（PRD-014）

本文是**设计纲要**，落地规格由 **PRD-014**（气体、污染与资源循环）承接，须按 [PRD 模板](../prd/00-prd-template.md) 的 19 节写成，并至少包含：

1. 五层模型（分区池 → 梯度 → 反应 → 温度门面 → 需求/事件）与全部状态机（泄漏、爆炸、火灾、中毒、撤离）；
2. §8 全部数值项的正式定义与验收口径；
