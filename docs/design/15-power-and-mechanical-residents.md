## 1. 目标与非目标

### 1.1 目标

| # | 目标 | 可测判据 |
| --- | --- | --- |
| G1 | **做适配层，不做第四套能源** | 包内同时有 Create（旋转力）/ Mekanism（FE）/ GT（EU）时，三者都能驱动我们的机器与居民，且**不出现能量凭空增加**（元素账式核对，误差 ≤1%） |
| G2 | **能源必须有代价** | 每一种发电都写清"它的废料去哪"（排放/污染/噪声/占地/维护），并与 [d13](13-gases-pollution-and-cycles.md) 的排放契约对接 |
| G3 | **机械族是"人"，不是工具** | 有需求（可充能）、有磨损、有关系、可恋爱、可被哀悼；**停机不等于死亡**，且可被同伴搬去充电 |
| G4 | **多种动力形态各有性格** | 齿轮/蒸汽/电动/发条四种驱动在效率、续航、维护、噪声、可否离线五个维度**明显不同**，不存在"最优解" |
| G5 | **人造子宫可以"生"，但不是人口打印机** | 有资源、能量、时间、失败率与社会反应；单位时间产出受 `pop_pressure` 约束 |
| G6 | **缺 mod 也能玩** | 不装 Create / Mekanism / GT 时，自建最基础发电设备（手摇/风/水/燃烧）足以维持 M3 的机械族；**缺电只表现为停机**（R-NM-24） |

### 1.2 非目标

| # | 非目标 | 理由 |
| --- | --- | --- |
| N1 | 自己做一套完整的科技能源树（像 GT 那样从 ULV 到 UV） | 那是 GT 的活；我们只做**适配与调度**，深度科技留给可选 mod |
| N2 | 让玩家手动给每台机器接线/调压 | 与 A-max 冲突：玩家定"优先级与红线"，具体接线由居民完成 |
| N3 | 机械族拥有独立 AI 体系 | 复用基底 `Urge` / `Node` / `submit`（ADR-013），只换 `ResidentKind` 与 `Locomotion` |
| N4 | 无限人口的"子宫流水线" | 会毁灭人口压力、住房与食物的全部张力 |
| N5 | 电解/蒸汽/燃烧的逐格流体仿真 | 由 [d13](13-gases-pollution-and-cycles.md) 的分区池承担，本文件只消费 |
| N6 | 机械族"性爱/性征"的露骨表现 | 与 PRD-009 N1 同纪律：亲密关系用**事件与文案**表达 |
| N7 | 跨维度共享一张电网 | 空间站必须**本地发电**（否则"星辰"失去意义），见 R-PWR-19 |
| N8 | 能量单位对玩家可见的复杂换算 | 玩家只看到"够/不够/还能撑多久"，换算只存在于实现与诊断里 |

## 2. 决策与依据

| 决策 | 内容 | 依据 |
| --- | --- | --- |
| 基准单位 | 内部统一为 **E**（默认 1 E = 1 FE），其它单位按可配系数换算 | 基底与主流 mod 生态以 FE 为事实标准；PRD-001 R-NM-24 已把机械族能量定为 FE |

## 3. 能量模型

### 3.1 统一单位与换算

内部只有一个标量：**E**（energy unit）。所有外部能量在**边界**上换算，进入我们的网络后只以 E 计账。

| 来源 | 原生单位 | 默认换算 | 备注 |
| --- | --- | --- | --- |
| NeoForge Energy（Mekanism、Create Crafts & Additions、多数科技 mod） | FE | **1 FE = 1 E** | 基准 |
| Mekanism Joules | J | **1 J = 0.4 E**（即 1 FE = 2.5 J） | 与 Mekanism 官方换算一致 |
| GregTech EU | EU | **1 EU = 1 E**（可配） | GT 的电压等级见 §6.2 |
| GregTech 蒸汽 | mB | **1 mB ≈ 0.5 E**（可配，取决于温度/压力） | 蒸汽**同时**是 d13 的气体种类，见 §3.5 |
| Create 旋转力 | 应力 SU × 转速 RPM | **P = SU × RPM × k**，`k` 默认使一台小风车 ≈ 32 E/t | 只取"功率"，不复制 Create 的应力损耗模型（§10.1） |

**R-PWR-1**：所有换算系数必须**世界级可配**（`pack/02` 的配置项），且默认值必须在游戏内"能量账"页可查；改系数不得导致已存档的机器瞬间爆炸或永久停机。

**R-PWR-2**：网络内部**只存 E**；不允许两种单位在同一张网里并行流动（避免"1 FE 与 1 J 混着算"这类经典 bug）。

### 3.2 为什么是适配层

包内至少有三套能量体系（Create 的旋转力、Mekanism 的 FE/J、GT 的 EU/蒸汽），若我们自造第四套，玩家就必须为"我们的机器"再建一套发电——这与"整合包"的定位冲突，也会让时代门槛变成"再爬一棵科技树"。

适配层的代价是**必须做守恒与循环检测**（§3.4），收益是：**任何一套能源都能养活我们的殖民地与机械族**，且玩家可以按自己喜欢的方式玩（Create 派 / 科技派 / GT 派）。

### 3.3 结算模型

每张网（§6.1）每 10 tick 结算一次，顺序固定：

```
1. 收集：所有 source 的产出（发电机、太阳能、手摇、蒸汽机、外部 FE/EU 推送）
2. 转换：外部单位 → E（损耗 conversion_loss）
3. 传输：沿拓扑送达 sink（损耗 transmission_loss × 距离）
4. 消费：按优先级分配（§5.2）；不足则按优先级**降级**，并记录"谁没吃到电"
5. 储能：剩余充入 storage（往返损耗 storage_roundtrip_loss）
6. 记账：产出/损耗/消费/储能变化写入"能量账"（§6.4）
```

**R-PWR-3**：结算是**确定性**的（同样的拓扑与优先级得到同样的分配），因为多人模式下所有客户端要看到同一张账（[PRD-012](../prd/PRD-012-multiplayer-and-permissions.md)）。

**R-PWR-4**：任何一次结算都必须**记账守恒**：`产出 = 消费 + 损耗 + 储能增量 + 溢出丢弃`。溢出必须**可见**（"电网过载，浪费了 X"），不允许静默丢弃。

### 3.4 守恒与漏洞对策

| 漏洞 | 表现 | 对策 |
| --- | --- | --- |
| 转换器循环放大 | FE → E → 蒸汽 → EU → FE，绕一圈变多 | **同一个网内禁止形成"A→B→A"的转换环**；检测到环时**断环**并记一条诊断（`power_loop_detected`） |
| 双向转换器 | 一个方块同时是 FE→E 与 E→FE | 转换器只有**单向**；双向需求用两个方块，且两个方向各自的损耗**独立计** |
| 卸载区块复制 | 区块卸载后储能"暂停"，加载后重复结算 | 储能按**绝对时间戳**结算（`lastTick` 差 × 速率），卸载期间只按时间差记账，见 R-PWR-17 |
| 创造模式/作弊源 | 创造能量方块为所欲为 | 允许，但**在能量账里标记为 `creative`**，多人下可被权限收紧（PRD-012） |
| 无限燃料 | 某种 mod 的"永动机"配方 | 我们只做适配，不做平衡修正；但**能量账会暴露它**（玩家与服务器管理员能看到异常） |

### 3.5 与气体层（d13）的接口

发电与转换**必然**产生热、烟、蒸汽或可燃气，这些一律不是本文件自己算的：

| 我们的动作 | 交给 d13 的东西 |
| --- | --- |
| 燃烧（木/煤/油） | `gas_source`：烟 + CO（不完全燃烧时）+ 热 |
| 蒸汽机/锅炉 | `gas_source`：蒸汽（高压时泄漏风险）+ 热；冷凝水回收走 d06 的水路 |
| 电解水 | `gas_sink`（水/电）+ `gas_source`（O₂、H₂ 可燃气） |
| 电池充放 | 热（小）；**没有排放**，但过充/短路 → 起火（§6.3） |
| 机械族呼吸/散热 | 无（它不是生物）；但它的**冷却**需要通风，归 d13 的分区池 |

**R-PWR-5**：本文件**不得**自行定义"污染"或"温度"数值；一切环境后果由 d13 的 `pollution_rule` 与温度场产生（ADR-016）。

### 3.6 一个算例（让"损耗"变成可感知的东西）

一台 512 E/t 的蒸汽机，经 40 格导线送到 3 台熔炉（每台 120 E/t）+ 1 个充电站（64 E/t）：

| 环节 | 数值 | 说明 |
| --- | --- | --- |
| 产出 | 512 E/t | 蒸汽机额定 |
| 转换损耗（10%） | −51 | 蒸汽 → E |
| 传输（40 格 × 0.5%） | −92 | 距离是**真实的成本**，所以发电机应该建在用电区附近 |
| 到达 | 369 E/t | |
| 需求 | 424 E/t | 3 × 120 + 64 |
| 缺口 | −55 E/t | 按优先级：熔炉停 1 台（P2），充电站（P1）保住 |
| 玩家看到的 | "缺口 55 E/t：**熔炉 3 号没吃到电**（P2 被降级）" | 一句话 + 关键数字 + 该做什么 |

> 这张表就是"能量账"的模板：**结论先行、数字可核、归因到具体设备**（与 [PRD-006](../prd/PRD-006-stock-rules-and-diagnosis.md) 的视觉原则一致）。

## 4. 发电阶梯（按时代）

每个时代**只解锁"新的瓶颈解法"**，不是数值 +10%（d08 的 G2）。每一条都写清"废料去哪"。

| 时代 | 发电方式 | 规模（默认） | 代价 / 废料去哪 |
| --- | --- | --- | --- |
| 0 落脚（石器） | **手摇**（人力踩踏/摇柄） | 8–16 E/t，需 1 名居民 | 人力占用；无排放；**累**（如厕/休息需求涨） |
| 1 定居（农耕） | **风车 / 水车** | 32–64 E/t（风）/ 48 E/t（水，需落差） | 占地；风不稳定（季节曲线接 PRD-003）；水车改变水流（与 d06 的灌溉抢水） |
| 2 分工（铜石） | **畜力**（牛转盘） | 24 E/t | 饲料（与 d06 的粮仓抢粮）；粪 → d13 的堆肥/沼气 |
| 3 工程（铁器） | **燃烧炉 + 蒸汽机** | 128–256 E/t | 烟/CO/热 → d13；燃料砍伐 → d06 的林业；**噪声**（影响附近居民的休息需求） |
| 4 规模（工业） | **集中供能**（多机组 + 电网） | 1k–8k E/t | 污染集中爆发（d13 的 C 链）；冷却水；**过载风险**（§6.3） |
| 5 远征（蒸汽/天空） | **移动动力**（机车/飞艇轴系） | 依载具 | 同上；**移动源的排放随位置改变**（d13 的分区池必须支持"移动源"） |
| 6 星辰（终局） | **同位素/太阳能阵列**（太空站本地） | 2k–16k E/t | 太空站**没有大气**（排放无害但**散热极难**，接 d13 的温度场）；补给依赖（PRD-011 §9.6） |

**R-PWR-6**：**手摇发电必须永远可用**——它是"没电时最后的尊严"，也是 R-NM-24 的兜底（不装任何能源 mod 时仍能给机械族充电）。

**R-PWR-7**：每种发电都必须有**前兆**（d13 的 P3 纪律）：燃料将尽（库存曲线）、风季结束（季节曲线）、锅炉压力升高（仪表）、污染累积（覆盖层）。

**R-PWR-8**：移动动力源（机车/飞艇）在 d13 中的排放**按当前所在分区**计，不允许"因为它在移动所以不排"。

### 4.1 可再生与"看天吃饭"

风、水、太阳都受**季节与昼夜**影响（曲线来自 [PRD-003](../prd/PRD-003-season-temperature-thirst-nutrition.md) 的季节曲线，本文件不另建）：

| 来源 | 波动 | 玩家的应对 |
| --- | --- | --- |
| 风车 | 季节 ×0.4–1.6（冬季风大、夏季弱），并有**连续无风日** | 储能（飞轮）+ 备用手摇；"无风周"是可预期的危机 |
| 水车 | 枯水期 ×0.5（冬季结冰则归零，接 PRD-003 的温度场） | 建在活水；备燃烧机组 |
| 太阳能 | 昼夜 0/1，冬季 ×0.7 | 电池组 + 优先级调度 |
| 燃烧/蒸汽 | 稳定，但**燃料是库存**（d06） | 储粮式储燃料；燃料断供是"慢速停摆"而非"瞬间黑屏" |

**R-PWR-8a**：可再生波动必须**可被预测**（日历/季节页给出"未来 3 日的预计出力"），不允许玩家靠猜——这同时是 [PRD-006](../prd/PRD-006-stock-rules-and-diagnosis.md) 的"结论先行"要求。

## 5. 储能与调度

### 5.1 储能形态

| 形态 | 时代 | 容量（默认） | 特性 |
| --- | --- | --- | --- |
| 电池组 | 3 | 4k E | 即插即用；过充/短路会**起火**（§6.3） |
| 飞轮 | 3 | 8k E | 无化学风险；**有噪声**；停机后缓慢自放电（2%/日） |
| 蒸汽蓄能 | 4 | 20k E 等效 | 需要保温；**泄漏**会变成 d13 的蒸汽（好事也是坏事） |
| 发条 | 3 | 2k E | **手动的电池**：居民上弦（彩蛋，§7.2） |

### 5.2 优先级调度（"先保命"）

| 优先级 | 消费者 | 断供后果 |
| --- | --- | --- |
| P0 | 生命维持（氧气循环、恒温、医疗设备） | 立即告警；d13 的缺氧链启动 |
| P1 | 机械族充电站、牢房照明/门锁 | 机械族停机；关押风险上升（PRD-015 的 `unrest`） |
| P2 | 生产（工作台、熔炉、泵） | 停线；订单积压（诊断可见） |
| P3 | 舒适（照明、装饰、娱乐） | 需求下降 → 专注度下降（PRD-001） |
| P4 | 可选（研究、美化） | 最后才断 |

**R-PWR-9**：优先级**由玩家设定**（默认如上），但 **P0 永远不可被关闭**（除非玩家显式关闭"生命维持保护"并确认）。

**R-PWR-10**：断供必须**告知并归因**：`Notice` 文案给出"谁没吃到电 + 为什么"（发电不足 / 传输损耗 / 优先级被降），并进入 [PRD-006](../prd/PRD-006-stock-rules-and-diagnosis.md) 的诊断链（新增 D 类别见 §11.5）。

**R-PWR-11**：降级是**单调、可预测**的：先降 P4 → P3 → P2，不允许随机抖动（"灯忽明忽暗"是 bug 不是氛围）。

## 6. 传输与拓扑

### 6.1 网络

- 一张网 = 一组**连通**的导体（导线/线缆/轴/蒸汽管）及其上的设备。
- 网由系统自动识别，**玩家可命名**（"东厂电网"），并可在面板上看到：产出、消费、储能、损耗、优先级分配、**最近的异常**。
- 跨维度**不自动连通**（R-PWR-19）。

### 6.2 电压/应力等级

| 等级 | 上限（默认） | 对应 GT | 超载后果 |
| --- | --- | --- | --- |
| T0 | 32 E/t | ULV | 起火（概率递增） |
| T1 | 512 E/t | LV/MV | 起火 + 熔断（断网，需居民修） |
| T2 | 8k E/t | HV/EV | **爆炸**（破坏方块，接 d13 的可燃气/热） |
| T3 | 128k E/t | IV+ | 爆炸 + 火灾 + 可能**伤亡**（PRD-013） |

**R-PWR-12**：超载后果必须**先有前兆**（导线发红、嗡嗡声、仪表进入红区），且有**保险丝/断路器**可建（居民维护）。

**R-PWR-13**：等级不是"越高越好"——高等级导线的**成本、占地、维护**都更高；跨等级必须经过**变压器**（有转换损耗）。

### 6.3 故障形态

起火 / 熔断 / 断轴（Create 的轴被拉断）/ 蒸汽管爆裂 / 电池热失控。全部是**居民要修的工作**（`Urge` → `Node` → `submit`），不是玩家点一下就恢复。

### 6.4 能量账与诊断

每张网维护一份**滚动账**（最近 100 次结算）：产出、损耗、消费、储能、**被降级的消费者**。诊断卡给出：

1. **一句话结论**（"东厂电网过载 18%，因为熔炉同时启动"）
2. **关键数字**（产出 412 / 消费 486 E/t）
3. **该做什么**（加一台发电机 / 把熔炉移到夜间 / 提高变压器等级）

**R-PWR-14**：能量账的数据结构必须**可导出**（服务器管理员可用于排查"谁在偷电/复制能量"）。

## 7. 机械族

### 7.1 定义

机械族是**我方注册的 `ResidentKind`**（`kind: machine`），不是一个新实体类：

| 方面 | 与人形居民相同 | 与人形居民不同 |
| --- | --- | --- |
| 行为 | 走 `Urge` / `Node` / `submit`；能被派工、能拒绝（`RefusalKind`） | 自带 `Locomotion`（[PRD-011](../prd/PRD-011-progression-knowledge-and-space.md) R-AG-17）；不进食、不睡眠、不如厕 |
| 需求 | 有"能量"（可充能，PRD-001 §5.3.4）；可有社交需求（§7.6） | **不参与**情绪、崩溃与专注度（R-NM-25） |
| 伤病 | 会被打坏（部件故障），需要维修 | 无出血、无疼痛、无感染；不会"病死" |
| 关系 | 可建立关系、可恋爱、可被哀悼（§8.1） | 关系建立速度受"形态差异"影响（叙事材料，不是禁止） |
| 世代 | 可被"组装"出来（§8.2） | 不能自然生育；需人造子宫 |

### 7.2 四种驱动形态

| 驱动 | 能源 | 效率 | 续航 | 维护 | 噪声 | 可否离线 | 特点 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **齿轮**（旋转力） | Create 的轴/应力 | 高 | 依网 | 需润滑（油脂） | 中 | 否（必须连轴） | 适合工厂内固定岗位；**不能离开轴** |
| **蒸汽** | 蒸汽管/锅炉 | 中 | 中（自带小锅炉） | 高（水垢、密封） | **大** | 短时可（自带蒸汽罐） | 力量大、适合重活；**排蒸汽**（d13） |
| **电动** | FE/EU | **最高** | 依电池 | 低 | 低 | **是**（电池） | 通用型；M3 主力 |
| **发条**（彩蛋） | 手动上弦 | **最低** | 极短（2k E） | 极低 | 低 | 是 | **不需要电网**；停下只因为没人上弦；适合"穷开心的早期" |

**R-PWR-15**：四种驱动**必须**在"能否离线"上有真实差异（齿轮不能、电动能、发条永远能）——这是玩家的**战略选择**，不是皮肤。

**R-PWR-16**：发条型是**彩蛋**但必须**真的可用**：上弦是一个居民工作（`Urge`），一次上弦 = 2k E；它**永远不会因为"没充电"而永久停机**，只会停在那里等上弦的人——这是对 R-NM-24 的幽默注脚。

### 7.3 能量状态机（与 PRD-001 §5.3.4 对齐）

`Powered → Draining → LowPower → Depleted → Charging → Powered`

| 状态 | 表现 | 玩家可见 |
| --- | --- | --- |
| `Powered` | 正常工作 | 无 |
| `Draining` | 工作中耗电 | 面板显示"还能撑 X 小时" |
| `LowPower`（<20%） | 速度下降、拒绝重活 | 头顶疲惫图标 + 一条 `Notice` |
| `Depleted` | **停机**：站在原地不动，可被搬运 | 诊断"XX 停机，需要充电" |
| `Charging` | 在充电站/被上弦 | 进度条 |

**R-PWR-17**：`Depleted` **不是死亡**：不会掉生命值、不会腐烂、不会被当作尸体；同伴可以把它**搬去充电**（复用基底 Carry）。离线（区块卸载）时按时间戳结算（§3.4）。

**R-PWR-18**：停机时必须**保留全部人格、关系与记忆**；复电后不"失忆"（否则玩家不敢让它没电）。

### 7.4 磨损与维护（机械族的"衰老"）

机械族不会老，但会**磨损**：每个部件有 `wear`（0–100）。磨损的来源是使用（工作时 +，闲置时缓慢 +），不是时间。

| 磨损段 | 后果 | 维护 |
| --- | --- | --- |
| 0–40 | 无 | 定期保养（低优先工作） |
| 41–70 | 效率 -5%~-15% | 更换易损件（齿轮/密封/电池） |
| 71–90 | 效率 -20%，**故障概率上升** | 大修（需工作台 + 零件 + 时间） |
| 91–100 | 随时可能**故障停机**（不是死亡） | 拆解/重造 |

**R-PWR-19**：机械族的维护是**工作**（有人要做），不是自动回血；`Vocation` 上表现为"技师"（照 `militia` 的先例）。

**R-PWR-20**：**跨维度电网不连通**（N7）：太空站必须本地发电；把地球的电"传上去"会消灭终局的紧张感。

### 7.5 机械族的"伤"（接 PRD-013）

它的"伤"是**部件故障**，不是分部位出血：

| 人形居民的伤 | 机械族的对应物 | 医疗/维修 |
| --- | --- | --- |
| 骨折/断肢 | 关节/肢体部件损坏 | 更换部件（需零件） |
| 出血/失血 | 冷却液/润滑泄漏 | 补液 + 密封 |
| 感染 | 短路/腐蚀 | 清洁 + 更换 |
| 疼痛 | 无（**没有痛觉**） | 无 |
| 昏迷 | 停机 | 充电/重启 |

**R-PWR-21**：机械族**不受**疼痛、感染、出血影响；但**过热**会停机（接 d13 的温度场），**进水/腐蚀**会加速磨损。

### 7.6 需求集（机械族与人的差异）

| 需求 | 人形 | 机械族 |
| --- | --- | --- |
| 饥饿 / 口渴 / 如厕 | 有 | **无** |
| 休息 | 有 | 无（停机 ≠ 睡眠） |
| 温暖/舒适 | 有 | **无**（但有过热） |
| 社交 | 有 | **有**（默认开，可关）——这是"能谈恋爱"的前提 |
| 意义 | 有 | 有（`purpose`：被需要/被承认）——机器人也会"空转" |
| 能量 | 无 | **有**（可充能） |

**R-PWR-22**：机械族的社交与意义需求**默认开启**（因为用户裁定"当然可以谈恋爱"）；关闭它们必须是一个**显式的世界选项**，且关闭后在 UI 里明确写"这个世界的机械族不需要陪伴"。

## 8. 关系与生育

### 8.1 恋爱与伴侣（接 PRD-008）

- 关系仍是**双轴**（`bond` / `grudge`），每人 ≤ `relation_cap = 30` 条（[PRD-008](../prd/PRD-008-relationships-and-social.md) G1）。
- **伴侣必须双方互认**（PRD-008 N9 禁止强迫婚配）；机械族与人、机械族与机械族**都可以**。
- 形态差异只影响**建立速度**与**社会反应**，不影响**上限**：

| 组合 | 建立速度 | 社会反应（叙事材料） |
| --- | --- | --- |
| 人 × 人 | 基准 | 无 |
| 人 × 机械 | ×0.7（更慢，需要更多共同经历） | 部分居民 `bond` 增长 -X（"它又不是人"），部分居民 +X（"它比人可靠"） |
| 机械 × 机械 | ×1.2（同频） | 保守派居民不适；孩子们觉得酷 |

**R-PWR-23**：社会偏见**只能通过情绪与关系表达**，**不得**阻止关系成立（不得"系统禁止人机恋"）；玩家可以关闭"偏见"（世界选项），但不能关闭"恋爱"本身。

**R-PWR-24**：机器伴侣的死亡按**居民死亡**处理（讣告、哀悼、`grudge` 归因），不得因为"它是机器"而降级为物品损毁——除非玩家把 `machine_personhood` 关掉（那时它只是工具，且**明确告知**这个世界的机械族不是"人"）。

### 8.2 人造子宫

一座**建筑**（多块结构或单块大机器，默认 3×3），两种用途：

| 用途 | 输入 | 产出 | 时长 | 失败 |
| --- | --- | --- | --- | --- |
| A. 体外孕育（生物居民） | 父母双方的遗传材料（至少一方是居民）+ 营养液 + 能量 2k E/日 + 医师照护 | 一名**生物**婴儿（PRD-009 的出生事件） | `pregnancy_days × 0.8`（比自然略短） | 基础 10%，随医疗质量下降（最低 2%）；失败 = 流产/畸形（可被 PRD-013 处理） |
| B. 组装机械族 | 蓝图（知识，PRD-011）+ 部件（义体/机械零件）+ 能量 8k E + 时间 3 日 | 一名**机械族**居民（随机人格与驱动形态） | 3 游戏日 | 基础 15%，随技师熟练度下降；失败 = 报废（材料损失） |

**R-PWR-25**：人造子宫**不是人口打印机**：每个殖民地同时只能建 **1 台**（`womb_max_concurrent = 1`，可配但上限 2），且每次产出后进入**冷却**（默认 5 游戏日），并**计入 `pop_pressure`**（PRD-009 的涌现式压力；压力高时**拒绝启动**并给出原因）。

**R-PWR-26**：两种用途都必须有**社会反应**：① 体外孕育在保守势力眼中是"违背自然"（`standing` 下降）；② 组装机械族在部分居民眼中是"造人"（情绪事件）。这些是**叙事**，不是禁令。

**R-PWR-27**：人造子宫的失败必须**有前兆**（胎心监测异常 / 组装诊断报警），且**可被医学/技师介入**（PRD-013 的术前风险预览同源原则）。

### 8.3 与 PRD-009 的接口（谁发起、谁维护、谁级联）

| 问题 | 答案 |
| --- | --- |
| 谁发起出生事件 | **PRD-009**（它拥有妊娠与出生状态机） |
| 谁维护关系图 | **PRD-008**（亲缘边由 009 写入，008 维护 bond/grudge） |
| 人造子宫归谁 | **本文件**提供设施与产能；**009 决定"能不能生"**；**013 决定"生得下来吗"** |
| 机械族"出生" | 009 记录为**出生事件**（`LifeRecord` 无父母，只有"制造者"引用）；008 建立"制造者—被造者"关系（默认 `bond = 30`，可成长） |

### 8.4 三个叙事片段（用来说明数值为什么会变成故事）

> 这些片段不是需求，而是**验收标准**：如果玩家玩不到这类时刻，说明本文件的设计失败了。

**片段 A（人机伴侣）**
铁匠 **玛拉** 的机械助手 **十二** 在矿难中把她拖了出来（`bond` 从 40 涨到 72）。两年后十二磨损到 88，`Depleted` 停在院子里；玛拉把它搬去充电站，坐在旁边等。系统：`bond` +5，生成记忆"她守着它充电"；三天后十二复电，`bond` 已到 85 → 关系类型升为 `伴侣`（互认）。其他两名居民 `bond` 对玛拉 -3（"她跟一台机器"），一名前矿工 +4（"它救过她"）。

**片段 B（人造子宫，失败）**
一对伴侣（人类 + 人类）选择体外孕育。营养液不足、医院的洁净度只到"简陋"→ 基础失败率 10% 升到 22%。第 4 日胎心监测报警（**前兆**），医师介入但缺药（诊断：D-18）→ 流产。系统：伴侣双方 `grudge` 对医院 -8、情绪"悲痛"、编年史记一条"未出世的孩子"。**没有复活**，也没有"读档建议"——这是设计上的痛感。

**片段 C（发条彩蛋）**
殖民地断粮，电网因为燃料耗尽而停摆。所有人都以为机器人也完了，但 **七个**（发条型，效率只有电动的 1/5）还在搬水——它只要有人每 8 秒上弦。玩家在那一刻明白了 R-PWR-6 与 R-PWR-16 的意义：**最落后的技术，是最后停下的技术**。
