## 1. 目标与非目标

### 1.1 目标

1. **历史永不因"覆盖"而消失**：任何一次自动备份都落成**独立压缩包**，重名不覆盖、不轮转替换。
2. **能回到任意一个历史时刻**：给定时间点，找得到可还原的包，并且**还原路径可验证**。
3. **备份本身不会坏档**：写入原子、包内有清单与校验和、坏包不会被当成好包。
4. **失败必须可诊断**：磁盘满、权限、IO 错误、存档被封印，都要给出**具体原因**而不是"备份失败"。
5. **决策日志与编年史可读、可导出**：玩家能把殖民地史书带走，而它不在主存档里膨胀。
6. **迁移显式、可回滚**：版本升级失败时回到升级前，**绝不静默把可写存档变成只读**。

### 1.2 非目标

- **不做云同步 / 异地备份**：范围外（OQ-4）。专用服务器的多实例备份按 [ADR-018](../00-charter.md) **延后**到单机全部完成之后。
- **不做跨存档去重**：v1 每个存档各管各的（OQ-3）。
- **不做存档编辑工具**：我们不改玩家数值，只做备份、校验、迁移。
- **不做回放录像**：决策日志是文本，不是逐帧录像。
- **不把备份做成"时间机器"UI**：列表 + 还原即可，不做时间轴动画（PHUD-11：不堆砌）。

### 1.3 与其它文档的边界

| 主题 | 归谁 | 本文件负责什么 |
| --- | --- | --- |
| 编年史的内容与叙述规则 | [PRD-002](../prd/PRD-002-incidents-and-narrator.md) | 只负责**归档与导出**（写什么由 PRD-002 定） |
| `rule_used` 仲裁日志 | [PRD-012](../prd/PRD-012-multiplayer-and-permissions.md) | 只负责**落盘与可读导出** |
| 存档内的自定义状态 | 各 PRD（走 `Colony.keep` / 附件） | 负责**版本号、迁移、容错** |
| 性能额度 | [pack/03](../pack/03-performance-budget.md) | 在这里**申请额度**并给探针 |

## 2. 为什么自研（不靠基底、不靠第三方备份 mod）

### 2.1 基底现状（直读源码，r01）

- 殖民地状态是 `ColonyRegistry extends SavedData`，名字 `folkways_colonies`，挂在 overworld 的 `DataStorage`（`ColonyRegistry.java:24-25,54`）。
- **只有一个存档后端替换点** `Colonies.install(Source)`（r01 §4），版本门 `SaveVersion.CURRENT` 是**硬编码常量**（r01 §4）。
- **最危险的缺陷**：读到不可解析或更高的版本时 `sealed()`，此后**不再 `setDirty`**（`ColonyRegistry.java:42-51`、`SaveVersion.java:27`）→ **玩家看到殖民地不再回写，却没有任何错误提示**（r01 §9 第 8 条）。
- 自定义持久状态必须走 `Colony.keep(owner, CompoundTag)` 或 body attachment；`WorldPos` 还涉及 `Keeps` 迁移（r01 §9 第 7 条）。

**结论**：基底只保证"存得下"，完全不保证"存得住、退得回、说得清"。**必须由我们补偿**，尤其是 §8.3 的"绝不静默只读"。

### 2.2 第三方备份 mod 为什么不够

| 需求 | 典型第三方做法 | 差距 |
| --- | --- | --- |
| 按时间打包 | 多数只是**整目录复制**，不压缩 | 磁盘占用翻倍，玩家会关掉它 |
| 压缩级别可配 | 无 | 用户明确要求 |
| 不覆盖历史 | 固定数量**轮转覆盖**（如只留 5 份） | 直接违背"永不覆盖" |
| 可校验 | 无 manifest、无哈希 | 坏包被发现时已经晚了 |
| 可诊断 | 日志一句 "backup failed" | 违背 [pack/03](../pack/03-performance-budget.md) 的降级告知纪律 |
| 与存档格式联动 | 不知道 `sealed()` / `SaveVersion` | 会**备份一个永远不会回写的存档**还告诉玩家"备份成功" |

**结论**：自研。层级以 **L1** 为主（新文件 + 事件钩子）；需要读基底存档元数据的地方标 **L2**；**无 L3/L4**。

## 3. 备份模型

### 3.1 三种产物

| 产物 | 内容 | 用途 | 进不进主存档 |
| --- | --- | --- | --- |
| **存档**（world save） | MC 自己的 `level.dat`、`region/*.mca`、`data/*.dat`（含 `folkways_colonies.dat`） | 游戏本体 | 就是主存档 |
| **逻辑快照**（snapshot） | 殖民地账本、居民摘要（id/姓名/年龄/状态）、编年史指针 | **校验**与**人类可读的 diff** | 否（独立文件） |
| **备份包**（archive） | 存档相关文件 + `manifest.json` + 可选快照 | 归档与还原 | 否 |

**为什么还要逻辑快照**：压缩包只能证明"文件在"，不能证明"内容对"。快照让我们能回答"这份 3 天前的包，居民还是那 60 个人吗"，也让**还原后校验**有对照物（§7.2）。

### 3.2 全量与增量：两层，不做链式

- **全量（full）**：完整文件集。
- **增量（inc）**：**只相对"最近一次全量"**记录变更文件。**不做多级增量链**（A→B→C→D），因为链越长，任何一环坏掉，后面的全废；而玩家永远搞不清"该先还原哪个"。

```
full@D0 ── inc@D0+30m ── inc@D0+60m ── … ── inc@D0+23h
                                          └→ 次日 full@D1 开启新的一层
```

- **诚实说明**：`region/*.mca` 是 4 KB 对齐的大文件，改一个方块也会让整文件变更。所以**增量对小存档收益有限**（可能只省 10–20%），**对大存档（>500 MB）才明显**。我们不做块级 diff（v1 明确不做，见 OQ-2）。

### 3.3 目录布局

```
<saves>/<world>/plaa-backups/
  index.json                     # 索引（可重建，见 R-SAVE-20）
  full/2026-10-18T03-00-00Z-full.zip
  inc/2026-10-18T03-30-00Z-inc.zip
  inc/2026-10-18T04-00-00Z-inc.zip
  chronicle/2026-10-18.md        # 决策日志归档（人类可读，§9）
  chronicle/2026-10-18.json      # 同上，程序读
  book.md                        # 导出的「殖民地史书」
```

- **包名 = UTC ISO-8601 + 类型**。**重名不覆盖**（追加 `-2`、`-3`），因为"永不覆盖"优先于"命名好看"。
- 目录放在存档目录**内部**（跟着存档走，玩家复制存档时备份一起走）；用 `plaa-backups` 前缀避免与其它 mod 打架。

### 3.4 元数据（manifest）

每个包内必须有 `manifest.json`：

| 字段 | 说明 |
| --- | --- |
| `world_id` | 存档唯一 id（防"把 A 世界的包还原进 B 世界"） |
| `game_time` | 游戏内天数 / tick |
| `real_timestamp` | UTC 现实时间 |
| `players` | 当时玩家数 |
| `plaa_version` / `upstream_version` | 我们的版本 / 上游 Folkways 版本 |
| `pack_hash` | 整合包内容哈希（mod 列表 + 版本） |
| `kind` | `full` / `inc` |
| `base_full` | 增量指向的全量包名（全量为 `null`） |
| `files` | 文件列表 + 大小 + sha256 |
| `snapshot` | 逻辑快照文件名（可空） |
| `sealed_detected` | 备份时是否检测到存档被封印（§8.3） |

### 3.5 增量链断裂的检测与修复

- 检测：还原时校验 `base_full` 存在且哈希匹配；任一步失败 → **明确告知"这个包不可单独还原，需要 full@X"**。
- 修复（自愈）：`index.json` 损坏 → 扫目录重建（R-SAVE-20）；`full` 丢失 → 该层所有增量标 `orphan`，**保留但不伪装可还原**。

## 5. 原子性与并发

### 5.1 写临时文件 + 原子改名

1. 写 `<name>.partial`；
2. `flush` + `fsync`（确保落到磁盘，不是页缓存）；
3. 同分区 `rename` 成最终名（原子操作）；
4. 更新 `index.json`（同样 `.partial` → `rename`）；
5. 删除 `.partial` 残留（启动时清一次）。

**R-SAVE-1**：任何备份产物都必须经过"临时文件 → 原子改名"，禁止直接写最终文件。
**R-SAVE-2**：`index.json` 也必须原子替换；启动时若发现 `index.json` 缺失/损坏，**必须能扫目录重建**（R-SAVE-20）。

### 5.2 不阻塞主线程

- 备份在**后台线程**；每帧最多写 `max_frame_ms`（默认 2 ms）就用完让出，进度与"正在备份"提示走 UI（可关闭）。
- **R-SAVE-3**：备份不得让单帧超过 `max_frame_ms`；被测到超限时**降级为更小的分片**并告知（[pack/03](../pack/03-performance-budget.md) 的降级告知纪律）。
- **R-SAVE-4**：备份开始前必须触发一次落盘并**确认完成**（flushing 状态不可备份），否则会读到半写的区域文件。

### 5.3 与自动保存/退出的互斥

- 退出时若 `backup_on_exit=true`：**先落盘、再备份、再退出**；退出流程中的备份有**硬超时**（默认 20 s），超时则**放弃备份但保存存档**，并在下次启动时提醒（绝不因为备份失败而丢档）。
- 两个备份任务不并发：后到的排队，队列上限 1，超出丢弃并记录（别让备份堆积拖慢游戏）。

### 5.4 磁盘满 / 权限失败 / IO 错误

- **R-SAVE-6**：磁盘空间不足 `min_free_space_mb` 时，**不删除任何旧包**来腾空间；只**停止新的备份**并告知玩家"备份已暂停：空间不足，请清理或调整保留策略"。
- 权限/IO 失败：错误必须包含**具体路径 + 错误码**；连续失败 3 次则**自动降级**（延长间隔 → 降低压缩级别）并告知，而不是继续每 30 分钟失败一次。

## 6. 保留策略

### 6.1 双条件

- **数量**：`retain_inc` / `retain_full`。
- **时长**：`retain_days`（超期才可裁剪）。
- 两者都要满足才裁剪（更保守）。

### 6.2 安全阀（最重要的规则）

**R-SAVE-8**：**永不删除"当前存档可还原所需的最少集合"**——至少保留 **1 个全量 + 其依赖的增量**。即使玩家把 `retain_*` 设成最小值，也不允许把最后一条还原路径删掉。

**R-SAVE-9**：玩家手动 `pin` 的包**永不被裁剪**（可 pin 数量上限 50，超出则要求先取消）。

### 6.3 裁剪顺序与告知

裁剪顺序：**最老的增量 → 最老的全量**（若某全量仍是最老还原链的唯一依赖，跳过它并继续找下一个）。

- **R-SAVE-7**：**先校验、后删除**——删除前确认该包不是唯一依赖，且其 manifest 可读。
- 每次裁剪写日志；若裁剪导致"历史跨度缩短"（例如从 30 天缩到 7 天），**必须告知**（Notice 或下次进入时的提示）。

## 7. 恢复流程

### 7.1 恢复到新存档，绝不覆盖当前

1. 选择包 → 校验 manifest + sha256；
2. 解压到**临时目录**（同分区）→ 做完整性校验（§7.2）；
3. 校验通过后，**创建一个新存档目录**（名字建议 `<原名>-restored-<时间>`），把包内容放进去；
4. 玩家确认后**切换**（或自己从主菜单打开）；
5. **恢复前**自动做一次 `pre-restore` 全量并 `pin`（回滚点）。

**R-SAVE-10**：恢复**不得原地覆盖**当前存档。**R-SAVE-11**：恢复前必须有 `pre-restore` 回滚点。

### 7.2 四类完整性校验

| 类别 | 校验什么 | 失败怎么办 |
| --- | --- | --- |
| **居民** | 数量、id 唯一、附件（`body_state` 等）存在 | 报告缺失 id；**保留可加载部分**，标记 `dangling` |
| **关系** | 关系边两端存在、无悬空、亲缘边不成环 | 丢弃悬空边并记录（绝不崩溃） |
| **库存** | 账本可加总（不为负、不超上限）、物品 id 存在 | 报"哪一项为负/超限" |
| **世界状态** | `SaveVersion` 可比、维度存在、殖民地 registry 可解析 | 报"版本 X > 当前 Y"或"维度缺失" |

### 7.3 失败诊断

错误信息格式固定：`哪一类 / 哪个 id 或文件 / 期望 vs 实际`。**禁止**只写 "restore failed"。

### 7.4 可回滚

恢复失败 → 自动回到 `pre-restore` 状态（当前存档从未被改动，所以"回滚"= 什么都不做 + 删除临时目录），并输出诊断。**R-SAVE-12**：恢复过程**不修改当前存档的任何文件**。

## 8. 存档格式与迁移

### 8.1 自管版本号

- 基底 `SaveVersion.CURRENT = 1` 是**硬编码常量**（r01 §4），我们不能改它来给"我们的数据"编号。
- 因此：**自管 `plaa_save_version`**，写进 `Colony.keep("plaa.saves", tag)`（r01 §9 第 7 条推荐的路线）。
- 版本号**只增不减**；同一存档内的多个模块各有自己的子版本（`plaa.saves.relations`、`plaa.saves.atmos`…），互不阻塞。

### 8.2 迁移必须显式、一次一步

- 加载 → 读 `plaa_save_version` → 若低于当前，**依次执行 vN→vN+1 的迁移函数**，每步写日志（`from`、`to`、变更摘要、耗时）。
- 迁移**失败必须回滚**：迁移前自动触发一次全量备份（`pin`），失败则告知"迁移失败，已保留原档，建议使用 <包名> 还原"。
- **禁止**"边读边猜"式迁移（例如缺字段就填默认值），因为那会把**数据丢失**伪装成**数据正常**。

### 8.3 绝不静默只读（补偿基底的 `sealed()`）

基底在不可解析/更高版本时 `sealed()`，此后不回写且**无提示**（`ColonyRegistry.java:42-51`、`SaveVersion.java:27`、r01 §9 第 8 条）。我们的补偿：

1. **加载后检测**：若本应可写却被 `sealed`（或读到我们无法解析的 `plaa.saves`），**主动告知**玩家（Notice + 日志 + 殖民书自检页一行）。
2. **封印时不备份**：给一个"永远不会回写"的存档做备份是自欺欺人 → 拒绝并说明原因（R-SAVE-13）。
3. 提示可执行的下一步：用哪份备份还原、或联系谁（多人时是主机）。

### 8.4 未知内容容错

- 数据包/内容被移除（玩家删了 mod、删了数据包）：**保留原始 NBT**，把引用标为 `unknown`（附原始 id 字符串），**不允许**用默认值覆盖。
- 告知：加载时汇总一行"有 N 项内容缺失（已保留原始数据）"，点击展开明细。
- 这样做的理由：**内容可以再装回来，数据丢了就真没了**。

### 8.5 `Keeps` 与 `WorldPos` 迁移

- `WorldPos` 的自定义 `Keeps` 迁移**必须**列进迁移清单（r01 §9 第 7 条明确提示过这个坑）。
- 迁移清单是**显式的表**（版本 → 涉及哪些 owner → 做什么），新增模块时**必须**在此登记，否则评审不通过。

## 9. 决策日志与编年史归档

### 9.1 为什么单独归档

主存档每写一次都要序列化，把几万条日志塞进去会让存档膨胀、加载变慢。**日志是"读多写多"的数据，存档是"写少读少"的数据**，混在一起两边都受伤。

### 9.2 格式：双写

- `chronicle/<date>.md`：**人类可读**（玩家能直接看、能分享、能进史书）。
- `chronicle/<date>.json`：**程序读**（结构化，供校验与二次加工）。
- 一条记录的字段：`date`（游戏内 + 现实）、`kind`、`actor`、`choice`、`rule_used`（[PRD-012](../prd/PRD-012-multiplayer-and-permissions.md)）、`consequence`、`witnesses`。

### 9.3 导出「殖民地史书」

`book.md`：按**年代 / 家族 / 重大事件**分章，自动生成；玩家可一键导出到剪贴板或文件。它是**衍生物**，不是新数据源——删掉可重建。

### 9.4 与 PRD-002 / PRD-012 的对接

- **唯一写入点**：日志由编年史模块 append，备份模块**只负责归档**，不自己造日志（避免两套历史）。
- `rule_used`（仲裁用了哪条规则）由 PRD-012 产生，归档时原样保留——多人纠纷复盘靠它。

## 10. 性能与体积预算

### 10.1 压缩级别三角权衡（**估算**，非实测）

| 级别 | 相对体积 | 相对 CPU 时间 | 建议场景 |
| --- | --- | --- | --- |
| 0（不压缩） | 1.00 | 1.0 | 只为速度 |
| 1 | ≈0.75 | ≈1.1 | 低配机 |
| **6（默认）** | **≈0.45** | **≈2.5** | 通用 |
| 9 | ≈0.40 | ≈6.0 | 归档冷存 |

> 标注：**这是量级估算**，用于说明"6 是拐点附近"——9 只多省约 10% 体积，却要多花约 2.4 倍 CPU。S1（§13）必须实测后回填。

### 10.2 体积增长预期（**估算**）

- 存档主体是 `region/*.mca`；殖民地数据（居民、账本、关系）通常只有几 MB。
- 预期：60 居民 / 100 游戏日，未压缩存档 ≈ 80–200 MB（取决于探索范围），压缩后 ≈ 35–90 MB。
- **增量对小存档收益有限**（§3.2），对 >500 MB 存档约省 30–60%。

### 10.3 探针（没有探针不许合并）

`backup_ms_last`、`backup_ms_avg`、`archive_bytes_last`、`archive_count`、`index_bytes`、`free_space_mb`、`sealed_detected`、`verify_failures`、`restore_ms_last`。

### 10.4 预算与降级阶梯

- 常态 **≤0.5% tick**（空闲时几乎为 0），峰值 **≤2%**（备份期间）；额度从 [pack/03](../pack/03-performance-budget.md) 的"余量 ≥10%"里扣（R-PB-2）。
- 降级阶梯（**单调、可预测、必须告知**）：
  1. 延长增量间隔（30 → 60 → 120 分钟）；
  2. 降低压缩级别（6 → 3 → 1）；
  3. 减少保留数量（但**不破 §6.2 安全阀**）；
  4. 关闭逻辑快照；
  5. 暂停自动备份并提示（**永不删除已有包**）。

## 11. 多人

### 11.1 权威

- **服务端/主机是唯一写盘方**；备份在服务端后台线程执行。单机 = 集成服务器，走同一条路径。
- **R-SAVE-15**：客机**不写盘**、不触发备份（防"每个客户端各存一份、互相覆盖"）。

### 11.2 权限（接 [PRD-012](../prd/PRD-012-multiplayer-and-permissions.md)）

| 动作 | 最低权限 |
| --- | --- |
| 查看备份列表 / 下载 | L2 成员（只读） |
| 手动触发一次备份 | L3 管理者 |
| 修改保留策略 / 压缩级别 | L3 |
| **恢复 / 删除包 / 改 `pre-restore`** | **L4 主机**（恢复是破坏性操作） |
| 服务器级目录与磁盘设置 | **L5 服务器管理员** |

- 恢复与删除必须写 `rule_used`，谁做的、什么时候、恢复到哪个包，**可复盘**。

### 11.3 专用服务器

按 [ADR-018](../00-charter.md)：**延后**到单机全部完成之后（OQ-4 只留一条风险，不展开设计）。

## 12. 可改写性

| 内容 | 可被谁改 | 路径 | 热重载 |
| --- | --- | --- | --- |
| 间隔 / 保留 / 压缩级别 / 帧上限 | 玩家配置 | `config/plaa-backups.toml` | 否（下次备份生效） |
| 剧本级覆盖（如"硬核剧本每小时全量"） | 剧本数据包 | `data/plaa/scenario/*.json` | 重载剧本时 |
| 编年史字段与文案 | 数据包 | `data/plaa/chronicle/*.json` | 否 |
| 史书分章规则 | 数据包 | `data/plaa/chronicle/book.json` | 否 |

**原则**：格式与迁移逻辑**不可**被数据包改写（否则一个坏数据包就能让所有存档读不出来）；只有**策略与展示**可改。

## 13. 风险与未验证项（诚实清单）

| # | 风险 | 影响 | 现在怎么处理 |
| --- | --- | --- | --- |
| 1 | **区域文件半写**：备份与自动保存并发时读到未完成写入的 `.mca` | 备份里出现损坏区块 | R-SAVE-4（先落盘确认）；S2 实测 1.21.1 的 flush 语义 |
| 2 | **压缩包损坏** | 该时间点不可还原 | 包内 sha256 + 恢复前校验 + 至少保留 2 个可还原点 |
| 3 | **磁盘 IO 卡顿** | 服务器掉 TPS | 后台线程 + 每帧 2 ms + 降级阶梯；S3 实测 |
| 4 | **存档膨胀** | 加载变慢 | 日志不进主档（§9）；快照可关 |
| 5 | **`sealed` 误判** | 误报"存档被封印" | 只在"本应可写却 sealed"时报；附原始异常 |
| 6 | **增量收益低** | 玩家觉得"没用" | §3.2 提前说实话；配置可改成"只做全量" |
| 7 | **多存档同 world_id**（复制粘贴存档） | 还原到错误世界 | manifest 里的 `world_id` + 路径双校验，不匹配则拒绝 |
| 8 | **未验证**：`SavedData` 在备份时的可见性（读到的是内存还是磁盘） | 可能备份到"内存里更旧/更新"的状态 | S2 必须先做；结论出来前**不排期**自动化恢复 UI |

### 先行 Spike（**必须**先做，否则不许合并）

- **S1 压缩三角**：同一 200 MB 存档，级别 1/6/9 的体积与耗时实测（回填 §10.1）。
- **S2 flush 语义**：备份与自动保存并发 50 次，检查是否有损坏区块。
- **S3 卡顿**：60 居民 + 2 玩家，后台备份时测 P99 帧时间与 TPS。

## 14. 规则族索引（`R-SAVE-1..20`）

| 编号 | 规则 |
| --- | --- |
| R-SAVE-1 | 备份产物必须"临时文件 → 原子改名"，禁止直接写最终文件 |
| R-SAVE-2 | `index.json` 原子替换；损坏时能扫目录重建 |
| R-SAVE-3 | 备份不得让单帧超过 `max_frame_ms`（默认 2 ms），超限即分片更小并告知 |
| R-SAVE-4 | 备份前必须触发落盘并确认完成 |
| R-SAVE-5 | 每个包必须有 `manifest.json` + 每文件 sha256 |
| R-SAVE-6 | 磁盘不足时**不删旧包**，暂停备份并告知 |
| R-SAVE-7 | 裁剪前必须校验（manifest 可读、非唯一依赖） |
| R-SAVE-8 | **安全阀**：永不删除"1 全量 + 其依赖增量"这条最少还原路径 |
| R-SAVE-9 | `pin` 的包永不被裁剪 |
| R-SAVE-10 | 恢复必须到新存档，禁止原地覆盖 |
| R-SAVE-11 | 恢复前必须生成 `pre-restore` 回滚点 |
| R-SAVE-12 | 恢复过程不得修改当前存档任何文件 |
| R-SAVE-13 | `sealed`（封印）存档拒绝备份并说明原因 |
| R-SAVE-14 | 迁移显式、一次一步、失败回滚到迁移前备份 |
| R-SAVE-15 | 客机不写盘、不触发备份 |
| R-SAVE-16 | 恢复/删除包需 L4；改策略需 L3；恢复须写 `rule_used` |
| R-SAVE-17 | 任何降级/裁剪/失败都必须告知（不是只写日志） |
| R-SAVE-18 | 失败信息必须含"路径 + 原因 + 期望 vs 实际" |
| R-SAVE-19 | 压缩级别可配，默认 6 |
| R-SAVE-20 | 索引损坏可自愈（扫目录 + 读包内 manifest 重建） |
