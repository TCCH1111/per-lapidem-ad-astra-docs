> 立场：**单人体验完整，多人是增强**。任何系统先定义单人行为，再定义多人行为。
> 同时，多人是 colony sim 类游戏最容易被低估的复杂度来源：权限、并发、同步、性能、存档归属。

---

## 1. 设计目标

| 编号 | 目标 |
| --- | --- |
| G1 | 2–4 人小服可流畅协作，行为与单人一致 |
| G2 | 权限模型简单可理解（谁拥有殖民地、谁能改什么） |
| G3 | 并发冲突有明确规则（不出现两人同时改同一条规则导致状态错乱） |
| G4 | 性能随玩家数与居民数增长可控，有明确上限与降级策略 |
| G5 | 服务端权威，客户端不做影响世界的决策 |
| G6 | 掉线/重连/换人不破坏世界状态 |

---

## 2. 协作形态

| 形态 | 说明 | 目标支持度 |
| --- | --- | --- |
| 单人 | 完整体验 | 一等公民 |
| 合作小服（2–4 人） | 共享一个殖民地或各自殖民地 | 一等公民 |
| 多人多殖民地（4–8 人） | 各自殖民地 + 互访/贸易 | 目标支持 |
| 大服（8+） | 需要领地、经济、管理工具 | 尽力而为（见 §6 上限） |

> 基底 Folkways 已支持：殖民地属于玩家（不是书）、邀请成员、多殖民地切换、FTB Teams 转交。我们沿用并扩展。

---

## 3. 权限模型

| 层级 | 角色 | 能做什么 |
| --- | --- | --- |
| L0 所有者（Owner） | 殖民地创建者 / 被转交者 | 一切，包括解散、转交、驱逐 |
| L1 管理者（Steward） | 被授权的成员 | 职业排序、订单、库存规则、建造、日程 |
| L2 工匠（Artisan） | 被授权的成员 | 建造、生产、库存操作（不能改策略） |
| L3 成员（Member） | 被接纳的居民所属玩家 | 查看、个人操作、取用（受规则限制） |
| L4 访客（Visitor） | 非成员 | 只能看（若开启）或不能交互 |

**R-MP-1**：权限必须**按「动作类别」授权**，不是简单的「管理员/普通」两档。
**R-MP-2**：默认配置必须让 2 人合作**开箱即用**（不需要先配权限）。
**R-MP-3**：所有权限变更必须有日志（谁在何时改了什么）。

## 4. 并发与冲突

| 冲突场景 | 规则 |
| --- | --- |
| 两人同时改同一块地/同一订单 | 后提交者生效，并向前者显示「已被 X 修改」 |
| 两人同时下达相反的覆盖指令 | 按权限层级 + 时间戳裁决，落败方收到明确告知 |
| 两人同时建造同一地点 | 第二人不能放置（位置已占用），给出原因 |
| 一人删除另一人正在使用的资源 | 事务化：已认领的资源不被删除（或删除时返还） |
| 玩家断线时其指令 | 保留（世界继续运转）；可选「暂停该玩家的指令」 |
| 玩家间交易 | 双方确认才生效（避免误操作） |

**R-MP-4**：所有**改变世界状态**的玩家操作必须走服务端校验 + 事务化，不允许客户端直接改。
**R-MP-5**：冲突必须**可见且可解释**，不允许静默失败。

## 5. 同步与网络

| 项 | 策略 |
| --- | --- |
| 权威 | 服务端 |
| 同步内容 | 面板数据（按需分页）、世界内标记（区块/工地/威胁）、通知 |
| 同步方式 | 事件驱动推送 + 打开面板时拉取；避免逐 tick 广播 |
| 大对象 | 传说页/统计按需拉取，支持分页 |
| 覆盖层 | 优先在客户端由已有数据计算 |
| 频率上限 | 每类包有最小间隔与合并策略（防刷屏） |

**R-MP-6**：任何新增网络包必须声明：大小、频率、触发条件、是否可合并（写进 PRD 的「网络与多人」章节）。

## 6. 性能预算与上限

### 6.1 目标（对应章程 S5）

| 场景 | 配置 | 目标 |
| --- | --- | --- |
| 基线 | 60 居民 + 2 玩家 + 无事件 | 服务端 TPS ≥ 20 |
| 峰值 | 60 居民 + 2 玩家 + 袭击进行中 | 服务端 TPS ≥ 20（允许短时 15） |
| 极限 | 120 居民 | 允许 TPS < 20，用于找瓶颈 |

### 6.2 预算分配（草案，详见 [性能预算](../pack/03-performance-budget.md)）

| 系统 | 每 tick 预算占比 | 说明 |
| --- | --- | --- |
| 基底（Folkways 原有机能） | ≤ 50% | 不可超 |
| 需求/情绪/记忆 | ≤ 8% | 按日结算，分摊到 tick 上极少 |
| 事件与叙述者 | ≤ 2% | 按日结算 |
| 威胁与战斗 | ≤ 15%（战斗期间） | 峰值，需实体上限 |
| 经济与物流扩展 | ≤ 10% | 复用基底索引 |
| UI/网络 | ≤ 5% | 按需同步 |
| 余量 | ≥ 10% | 留给整合包内其它 mod |

### 6.3 降级策略（超过上限时）

| 顺序 | 降级 |
| --- | --- |
| 1 | 远处居民/实体 LOD（降低决策频率） |
| 2 | 抽象层结算间隔拉长（季 → 更粗） |
| 3 | 覆盖层与统计关闭或降采样 |
| 4 | 非关键视觉（粒子、动画）降级 |
| 5 | 拒绝新移民（人口硬上限保护） |

**R-MP-7**：降级必须**告知玩家**（可配置），不允许静默变形。

## 7. 服务器管理（小服场景）

| 需求 | 方案 |
| --- | --- |
| 世界备份 | 沿用常规存档备份；我们的数据全在存档内，无外部数据库 |
| 配置 | 服务端配置 + 世界级设置（难度/叙述者/季节长度） |
| 管理员工具 | 命令：查看殖民地状态、重置某系统、调试事件、导出传说页 |
| 反作弊/防滥用 | 服务端权威 + 权限校验；不做反作弊系统 |
| 跨版本升级 | 存档迁移策略（见各 PRD 的「数据与存档」） |
| 日志 | 关键事件写日志（便于排障） |

## 8. 与基底（Folkways）的关系

| 需求 | 基底已有 | 需要新增 |
| --- | --- | --- |
| 殖民地所有权与邀请 | 有（Members 页、邀请/接受、多殖民地、FTB Teams 转交） | 更细的权限分级 |
| 网络框架 | 有（packet 体系，如 `RosterSyncPacket`） | 新包 |
| 命令 | 有（`/folkways ...`） | 新的管理命令 |
| 多人兼容测试 | 基底有 e2e 双端测试框架（Blockwright） | 我们的多人验收方法 |
