## 1. 玩家幻想（Player Fantasy）

> 「我在地图边缘扎下第一顶帐篷。三十个小时后，同一片山坡上有一座城：水车在转，火车把矿石从山里运出来，城墙上有民兵在轮班。城里有三百年的家谱，有个铁匠因为我没给他足够的酒而记恨了我二十年，也有一座坟——第一代人里唯一没活过第一个冬天的那位。这不是我盖的房子，这是他们活过的地方。」

三个关键词：**能动性**（我说了算）、**人味**（他们是人）、**因果**（每个结果都有来路）。

## 2. 三种玩家，一个存档

| 原型 | 一句话动机 | 失败会让他离开的原因 | 我们必须给 |
| --- | --- | --- | --- |
| 建筑师 | 「我想造个东西」 | 造出来没人用、不好看 | 建筑被居民真实使用；蓝图/图案/机械/运输 |
| 管理者 | 「我想让它跑起来」 | 系统黑箱、无法诊断 | 可视化因果（为什么停工）、可调参数、统计 |
| 故事家 | 「我想看看会发生什么」 | 事件重复、无后果 | 事件有记忆、人物有关系、结果不可逆 |

**设计裁决规则**：当三个原型的诉求冲突时，优先满足**故事家**的底线（不能无后果）、满足**管理者**的日常（不能黑箱）、满足**建筑师**的表达（不能只有数值）。若仍冲突，回到第六章「反支柱」做减法。

## 3. 设计支柱

### P1 · 意图，而非指令（Intent over orders）

- **定义**：玩家表达**目标与约束**（这块地种麦子、这个箱子保持 64 个面包、铁匠优先于矿工），系统自己推导出「谁、何时、用什么、走哪条路」。玩家可以**选择**下探到微观指挥，但永远不被要求这么做。
- **为什么**：这是 Folkways 已有的能力（职业排序 + 区块 + 订单 + 图案），也是它能承载 50+ 居民而不变成点鼠标游戏的原因。同时它把玩家的注意力从「操作」转移到「决策」，这正是殖民地模拟的核心乐趣。
- **机制体现**：
  - 保留并强化意图层四件套：**划地（Zone）**、**订单（Order）**、**职业排序（Vocation ranking）**、**图案（Pattern）**。
  - 新增**策略层**：作息表（Schedule）、禁限区（Allowed Area）、库存规则（Stock rule）、优先级叠加（Priority override）。这些是「约束注入」，不是「任务指派」。
  - 玩家亲手做事永远可行（Minecraft 第一人称），但系统不依赖玩家当代劳。
- **反面（要避免的）**：把游戏做成 RTS 式点选每个单位；或者做成纯挂机放置游戏（玩家失去能动性）。
- **验收信号**：试玩者能在 2 小时内说出「我不用指挥每个人，我只要告诉他们要什么」；同时能在需要时精确干预某一个人。

### P2 · 每个人都是一个故事（Every settler is a story）

- **定义**：居民不是产能单位。他们有需求、情绪、记忆、关系、恩怨、偏好、技能、作品、后代、墓碑与讣告。
- **为什么**：RimWorld 证明了「三个有名字的人」比「三十个无名工人」更让人牵挂；DF 证明了「人味」能自然生成叙事，而不需要剧本。
- **机制体现**：
  - 需求层（Hunger / Rest / Warmth / Safety / Social / Beauty / Meaning）→ 情绪值 → 精神阈值事件（崩溃、出走、发疯、暴力）。
  - 关系层（好感/敌意/师徒/挚友/恋人/亲属/救命恩人/杀人凶手）→ 影响协作、争执、婚育、复仇。
  - 记忆层（Memories）：亲人去世、被袭击、吃到美食、升职、被救——每条记忆带情绪权重与衰减。
  - 生死层：伤病、后遗症、衰老、死亡；死者在传说页留下条目与坟。
  - Folkways 已提供的地基：姓名池、外观池、职业等级、Perk、讣告（`ResidentObituary`）。我们**不重做**，只在上面挂需求/情绪/关系/记忆。
- **反面**：把居民做成需要反复喂饭的宠物（负担）；情绪系统变成无法诊断的玄学。
- **验收信号**：玩家能说出至少 3 名居民的名字与他们的处境；情绪变化能在 UI 中追溯到具体原因（「他因为 XX 而不高兴」）。

### P3 · 世界会回应（The world pushes back）

- **定义**：世界不是背景板。季节、气候、地形、生态、疫病、野兽、外邦都会对殖民地施加压力，也会给出机会。
- **为什么**：没有压力就没有决策；没有外部世界就没有外交、贸易与战争，只有封闭的农场。
- **机制体现**：
  - 环境：四季（生长季/收获季/严冬）、天气（暴雨/暴雪/干旱/雷暴）、温度与保暖、照明与黑暗。
  - 生态：野生动植物、迁徙、捕食者、虫害、林火。
  - 健康：伤口、感染、疫病爆发、中毒、精神疾病。
  - 外部：商队、难民、流匪、敌对殖民地、外交关系、朝贡与条约。
- **反面**：随机天罚（玩家无法预防的纯惩罚）；压力曲线只有单调上升。
- **验收信号**：每种压力都有**可预防、可缓解、可承受**三条路径，且都能被玩家提前观察（预警机制）。

### P4 · 从石头到星辰（Per lapidem ad astra）

- **定义**：纵向进程分**时代**推进，每个时代解锁**新的玩法层**，而不只是更好的数值。
- **为什么**：这是「30 小时仍有新内容」的结构性保障，也是主题本身。
- **机制体现**（详见 [时代进程](08-progression-and-ages.md)）：

| 时代 | 新玩法层（而非数值） |
| --- | --- |
| 石器（落脚） | 采集/狩猎/简易庇护所/火；殖民地成立 |
| 农耕（定居） | 农田与水利、畜牧、仓储规则、第一个作坊、季节压力 |
| 铜石（分工） | 专职工匠与品质、贸易商队、防御工事、首支民兵 |
| 铁器（工程） | 矿场与熔炼链、机械动力（Create）、铁路、城市级建筑图案 |
| 工业（规模） | 集中供能、流水线、跨区物流、公共卫生、移民潮与阶级 |
| 蒸汽/天空（远征） | 铁路网、飞艇/飞船、远方据点、世界地图外交 |
| 星辰（终局） | 星际殖民前哨、跨世界物流、终局工程 |

- **反面**：科技树=数值+10%；跳过时代（玩家直接做出飞船但世界仍是石器）；每时代重复相同玩法。
- **验收信号**：每个时代至少有 2 个**只有该时代才能做**的动词，且上一个时代的瓶颈在该时代被解除。

### P5 · 失败长出故事（Failure is content）

- **定义**：饥荒、袭击、疫病、崩溃、死亡是内容的一部分；但玩家始终有调节权（难度、叙述者风格、可关闭模块）。
- **为什么**：DF 的「losing is fun」不是惩罚，而是叙事生成器。但 2020 年代的玩家需要可控的失败。
- **机制体现**：
  - 失败有**前兆与过程**（一定先出现饥饿→体弱→疫病，而不是瞬间团灭）。
  - 失败留下**可继承的东西**：经验、图纸、传说、墓志、后代。
  - 提供**叙述者（Narrator）**：和平/标准/残酷/自定义，控制事件频率与强度。
  - **不做**：惩罚玩家读档（无「读档即惩罚」机制）、强制铁人、不可逆的存档破坏。
- **反面**：无预警的团灭；失败只带来资源损失而没有故事收益。
- **验收信号**：试玩者能复述危机故事；同时能在设置里解释如何调低强度。

### P6 · 一切可被改写（Everything is a datapack）

- **定义**：内容、数值、规则、剧本、世界生成都可被数据包 / Starlark / 脚本替换；玩家的「世界与规则自由」是一等公民。
- **为什么**：Minecraft 生态的核心竞争力就是可修改性；Folkways 已经用「数据包货架（shelf）」和 Starlark 图案把这条路铺好了。
- **机制体现**：
  - 沿用 Folkways 货架：`pattern` / `piece` / `blueprint` / `resident_skin` / `resident_model`。
  - 新增货架：`needs` / `memories` / `events` / `scenarios` / `ages` / `trade_goods`（命名待定，见各 PRD）。
  - 剧本（Scenario）：从一个已有世界状态开局（流亡者、殖民地、废墟、帝国边陲）。
  - 规则改写：难度、经济系数、事件权重、时代门槛都能通过配置或数据包调整。
- **反面**：硬编码数值；数据包只能改文本不能改行为；改写需要写 Java。
- **验收信号**：不改 Java 也能新增一个事件、一个需求、一个时代门槛、一个剧本。

## 4. 支柱优先级（冲突时的裁决顺序）

```
P2 人味（不可退让——它是本作与其它 MC 整合包的分水岭）
  ↑
P1 意图层（不可退让——它是能放大的基础）
  ↑
P4 进程（保证长线）
  ↑
P3 压力（提供决策）
  ↑
P5 失败（提供叙事）
  ↑
P6 可改写（提供长尾与社区）
```

> 说明：箭头方向表示「当下层与上层冲突时，上层优先」。例如为了 P2 的人味，可以牺牲一部分 P3 的压力强度（不让危机把人全杀光）。

## 5. 体验曲线与节奏

### 5.1 多时间尺度循环

| 尺度 | 玩家的动作 | 系统的回应 | 情绪 |
| --- | --- | --- | --- |
| **秒** | 观察、亲手挖一块石头、捡起掉落物 | 居民在你身边干活、触发一次对话/动作 | 沉浸 |
| **分钟** | 划一块地、下一个订单、排职业 | 居民自己接活、搬运、建造 | 掌控 |
| **小时** | 规划一次扩张、处理一个短缺 | 一天结束的结算：吃饱了吗？累了吗？进度如何 | 期待 |
| **日 / 季** | 抢收、储粮、备冬、接待商队 | 季节切换、天气、作物、疫病、迁徙 | 紧迫与松弛交替 |
| **年 / 世代** | 招募、婚育、传承、建房、扩城 | 人口曲线、技能传承、死亡与新生、纪念 | 依恋 |
| **时代** | 决定下一个时代的方向（工业？贸易？军事？） | 解锁新动词、新压力、新机会 | 野心 |

### 5.2 张力节奏

采用「**季节基线 + 叙述者调峰**」双轨：

- **基线（可预测）**：农时与冬季的固定压力。玩家能规划，规划得好就能平稳过冬——这是「管理的回报」。
- **峰（不可预测）**：叙述者按强度与冷却投放事件（袭击、疫病、难民、天灾、机遇）。有预警期、有应对窗口。
- **谷（安全期）**：事件之后给一段可喘息的窗口，让玩家建设、扩张、社交。

**节奏规则 R-RHYTHM**（可配置）：
| 编号 | 规则 |
| --- | --- |
| R-RHYTHM-1 | 任何「峰值事件」在触发前必须有 ≥1 个游戏日的可见前兆（信使、足迹、侦察报告、气温预报、咳嗽声）。 |
| R-RHYTHM-2 | 两次峰值事件之间至少间隔 `max(3 游戏日, 上次事件的冲击 × 系数)`，防止连续天罚。 |
| R-RHYTHM-3 | 殖民地人口 <5 时，叙述者只投放「教学型」小事件；团灭风险事件在人口 <8 时不出现。 |
| R-RHYTHM-4 | 玩家可通过叙述者设置改变事件的频率与强度，但**不能**单方面取消已经进入世界的因果（例如已经结仇的势力）。 |

## 6. 反支柱（明确不做）

| 反支柱 | 说明 |
| --- | --- |
| 不做数值膨胀 | 时代的进步体现在**新动词**，不是「铁剑 20 伤害 → 钢剑 40 伤害」。 |
| 不做强制性战斗 | 和平叙述者下可以完全不打架；但世界仍然会给压力（饥荒、疫病、天气）。 |
| 不做惩罚性设计 | 不因读档/暂停/调难度而惩罚玩家。 |
| 不做「查 wiki 才能玩」 | 所有机制在游戏内可学（Ponder 课程 + 因果提示 + 图鉴）。 |
| 不做纯挂机 | 玩家不下达意图，系统不应无限自我优化；阈值决策必须回到玩家手里。 |
| 不做为了拟真而拟真 | 只有能产生**决策**或**故事**的拟真才做。 |

## 7. 差异化声明（一句话对各竞品）

| 竞品 | 它的强项 | 我们的差异 |
| --- | --- | --- |
| **矮人要塞** | 深度与意外叙事 | 我们保留「意外」，但用可视化的 3D 世界与 Minecraft 的亲手建造替代 ASCII 门槛 |
| **希克斯之歌** | 宏观规模与战略层 | 我们用「多殖民地 + 世界地图抽象」替代数百人同屏，并把每个人保留为个体 |
| **环世界** | 人物张力与事件设计 | 我们的事件发生在一个玩家能亲手改造的连续世界里，且有真实的物理建造与物流 |
| **石炉** | 可爱建筑与职业风 | 我们保留风格化职业，但拒绝线性剧情，改为涌现叙事 |
| **我的世界** | 建造自由与 mod 生态 | 我们的建筑会被居民**真的用起来**；你的城不是布景，是生产系统 |
| **Minecolonies** | 殖民地自动化 | 我们不是「放置建筑等工人」，而是「意图 + 涌现 + 人味 + 时代进程」 |

## 9. 验收信号汇总（本文件的「做完」定义）

- [ ] 体验曲线的每个时间尺度都有可复现的验收脚本或清单。
