## 1. 性能目标（验收口径）

| 场景 | 居民数 | 玩家数 | 事件 | 目标 | 判定 |
| --- | --- | --- | --- | --- | --- |
| 基线 | 60 | 2 | 无 | TPS ≥ 20，客户端 60 FPS @1080p | 里程碑验收 |
| 峰值 | 60 | 2 | 袭击/疫病进行中 | TPS ≥ 20（允许 ≤3 秒的 15 TPS 抖动） | 里程碑验收 |
| 极端 | 120 | 2 | 任意 | 允许 TPS < 20，用于定位瓶颈 | 压力测试（非门禁） |
| 参考上限 | 400（基底 bench 场景） | 多相机 | 无 | 不要求达标，只用于对比基线 | 参考 |

**R-PB-1**：门禁只看「基线」与「峰值」；「极端」只用于找瓶颈，不作为发布阻断条件。

## 2. 预算分配（服务端每 tick）

以「60 居民 + 2 玩家」的基线场景为 100%：

| 系统 | 常态预算 | 峰值预算 | 说明 |
| --- | --- | --- | --- |
| 基底（Folkways 原有机能：规划/劳动/旅行/物流） | ≤ 50% | ≤ 50% | 不可超；超出必须回上游或调参 |
| 需求 / 情绪 / 记忆 / 关系 | ≤ 8% | ≤ 8% | **按日结算**，分摊到每 tick 极低 |
| 事件与叙述者 | ≤ 2% | ≤ 5% | 按日结算；事件发生时短暂上升 |
| 威胁、战斗、敌人 AI | ≤ 2% | ≤ 15% | 峰值发生在袭击期间；须有实体数上限 |
| 经济扩展（品质/腐坏/工具消耗/贸易） | ≤ 10% | ≤ 10% | 复用基底索引；腐坏按批结算 |
| 时代与知识 | ≤ 2% | ≤ 2% | 事件驱动 |
| UI / 网络同步 | ≤ 5% | ≤ 5% | 按需推送 + 限流 |
| **余量（留给整合包内其它 mod）** | **≥ 10%** | **≥ 5%** | 保护玩家装 mod 的空间 |

**R-PB-2**：任何新系统的 PRD 必须给出「常态/峰值」两项估值，并说明额度来自哪个已有项或从余量里扣。
**R-PB-3**：单系统常态预算超过 5% 时，必须提供降级开关（配置可关）。

## 3. 结算节拍（决定成本的根因）

> 性能不是靠优化救回来的，是靠**节拍**设计避免的。

| 系统 | 结算节拍 | 每次的复杂度 | 备注 |
| --- | --- | --- | --- |
| 移动 / 寻路 / 劳动执行 | 每 tick | 与活跃居民数线性 | 基底负责 |
| 规划（任务生成） | 基底自身的节拍（待 `research/01` 确认） | 与任务数相关 | 不要绕过基底另开规划 |
| 需求衰减 | 每游戏小时 | O(居民数) | 单次极轻（几个浮点） |
| 情绪/记忆/关系 | 每游戏日 | O(居民数 + 交互动数) | **禁止 O(n²)** |
| 事件调度 | 每游戏日 | O(可用模板数) | 模板数上限受控 |
| 生产/消费统计 | 每游戏日 | O(物品种类) | 聚合值，不扫容器 |
| 腐坏 | 每游戏日（按批次） | O(批次数) | 批次合并 |
| 季节/天气 | 每游戏日 | O(1) | 世界级 |
| 生态/肥力 | 每游戏日 | O(地块数) 或稀疏采样 | 地块用稀疏结构 |
| 贸易价格 | 每交易日 | O(物品种类) | —— |
| 抽象层（远层世界） | 每游戏季 | O(殖民地数) | 不加载区块 |
| UI 同步 | 事件驱动 | O(变化量) | 不做全量广播 |

**R-PB-4**：禁止「每 tick 遍历全体居民/全体方块实体/全体区块」的新系统。若无法避免，必须给出分摊方案（时间切片：把 N 个居民拆到 M 个 tick 里轮流处理）。

## 4. 单项成本估算表（实施时填写）

| 项（示例） | 常态 | 峰值 | 依据 | 已批准？ |
| --- | --- | --- | --- | --- |
| 需求系统（**默认核心集 8 条 + 变体/成瘾/专属需求，实测 8~12 条**，60 居民，每小时结算） | 0.1% | 0.1% | 60 次浮点运算/小时；**专注度（Focus）走同一批结算** | ✅ |
| 情绪（含原因清单，每日结算） | 0.3% | 0.3% | 60 × 常量 | ✅ |
| 记忆（上限 20 条/人，每日衰减） | 0.5% | 0.5% | 1200 条加权 | ✅ |
| 关系（稀疏，上限 30 人） | 0.5% | 1% | 交互动驱动 | ✅ |
| 事件调度（≤100 模板，每日） | 0.1% | 2% | 权重计算 | ✅ |
| 袭击（≤30 敌人，逐实体战斗） | 0% | ≤15% | 复用基底 AI/寻路 | ⚠️ 需实测 |
| 腐坏（≤50 批次） | 0.2% | 0.2% | 每批一次 | ✅ |
| **合计** | **≤ 20%** | **≤ 30%** | —— | —— |

> 上表为**草案**，实施时逐项替换为实测值（bench 场景对照）。

## 5. 内存与其它资源

| 资源 | 预算 | 说明 |
| --- | --- | --- |
| 服务端堆 | 标准档 6G（其中给整合包 mod 3G，我们的系统 ≤ 0.5G） | 60 居民场景 |
| 每居民状态 | ≤ 2 KB（需求 7 + 情绪原因 ≤10 + 记忆 ≤20 + 关系 ≤30 条） | 120 居民 ≈ 240 KB，可忽略 |
| 每敌人实体 | 复用原生实体成本 | 上限 30 |
| 客户端 | 覆盖层与面板不得常驻大量数据 | 按需拉取 |
| 网络 | 每玩家每秒 ≤ 20 KB 增量（UI 相关） | 限流 |

## 6. 降级策略（超过预算时）

| 顺序 | 措施 | 影响 | 是否告知玩家 |
| --- | --- | --- | --- |
| 1 | 远处居民/实体 LOD（降低决策频率） | 几乎无感 | 否 |
| 2 | 抽象层结算间隔拉长 | 远方变化变慢 | 是（可配置） |
| 3 | 覆盖层/统计降采样或关闭 | 诊断能力下降 | 是 |
| 4 | 非关键视觉降级（粒子/动画/阴影） | 观感下降 | 是 |
| 5 | 拒绝新移民（人口保护上限） | 玩法受限 | **必须明确告知** |

**R-PB-5**：降级必须**单调可预测**（从最无感到最有感），且任何影响玩法的降级必须告知玩家。
**R-PB-6**：禁止静默地降低模拟保真度（例如偷偷少算情绪），这会破坏信任。

## 7. 度量方法

| 手段 | 用途 | 来源 |
| --- | --- | --- |
| `tick-meter` 探针 | 每 tick 耗时分布（平均/95 分位） | 基底 bench 工具（r05 §5） |
| `census` 探针 | 实体/居民/物品数量快照 | 同上 |
| `work-tap` 探针 | 劳动利用率 | 同上 |
| `labor-share` | 劳动力在各职业的分配 | 同上 |
| 拒绝覆盖率报告 | 「没干活」的原因分布（诊断质量） | 同上 |
| 我们自己的探针 | 需求/情绪/事件/战斗耗时 | 新增（沿用同样的探针模式） |

**R-PB-7**：每个 P0 系统上线时，必须同时提交它的**探针**（能测出它花多少时间），否则无法验证预算。

## 8. 与整合包 mod 选型的关系

| 规则 | 说明 |
| --- | --- |
| 单 mod 成本需登记 | 每个「重」mod（Create、世界生成、AI 类、光影）必须在 [mod 清单](01-modlist.md) 标注性能档位 |
| 同类只选一个 | 不允许两个功能重叠的重 mod 同时存在（例如两套存储系统） |
| 默认档保守 | 默认档以「稳 20 TPS」为准，不追求内容最大化 |
| 提供低配预设 | 提供关闭光影/降渲染距离的预设与说明 |
