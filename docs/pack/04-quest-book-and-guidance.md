## 1. 定位与红线

### 1.1 任务书只做三件事

| # | 职责 | 说明 |
| --- | --- | --- |
| 1 | **引导** | 告诉玩家"现在有什么可做、下一步大概是什么"，降低第一次游玩的上手门槛 |
| 2 | **剧情呈现** | 把已经发生的事（事件、洞见、死亡、婚姻、袭击）串成**可读的一条线**，让玩家记得住这个殖民地 |
| 3 | **进度可视化** | 用章节结构映射 **7 个时代**，让玩家看得见自己走到哪一格 |

### 1.2 红线（评审拒绝项）

| 编号 | 红线 | 理由 |
| --- | --- | --- |
| R-QB-1 | **不得成为规则来源**：任务书里的任何目标、奖励、条件都不得改变玩法规则（规则在 PRD 与数据包货架里） | 规则写进 FTB 就不可测试、不可诊断（[pack/02](02-config-and-datapack.md) R-CD-12） |
| R-QB-2 | **缺失 FTB Quests 时，游戏必须完整可玩** | 与 ADR-010 的"可整套删除"同一纪律 |
| R-QB-3 | **奖励必须驱动居民**：物资、蓝图、种子、牲畜、知识线索、移民、关系机会、配方 —— **不是给玩家 buff** | [ADR-013](../00-charter.md) |
| R-QB-4 | **不得用奖励替代玩法**：不允许"点一下领一堆资源"跳过生产链 | 否则经济与需求系统失去意义（[PRD-006](../prd/PRD-006-stock-rules-and-diagnosis.md)） |
| R-QB-5 | **不得强制**：任务书随时可关、章节可跳过，跳过不判负、不锁内容 | [PRD-007](../prd/PRD-007-scenarios.md) OQ-5：教程只在列表推荐 |
| R-QB-6 | **不得替玩家做决定**：时代推进的"选择时刻"必须在**游戏内**由玩家按下（[PRD-011](../prd/PRD-011-progression-knowledge-and-space.md) R-AG-3），任务书只提示"该做决定了" | 自动推进/自动选择会使 [d08](../design/08-progression-and-ages.md) R-AGE-2 失效 |
| R-QB-7 | **不得重复叙事**：剧情钩子只能引用 [PRD-002](../prd/PRD-002-incidents-and-narrator.md) 的事件与编年史条目，禁止另写一套与游戏状态无关的文本 | 两套叙事必然矛盾 |
| R-QB-8 | **双语齐全**：所有键 `zh_cn` + `en_us`；缺 `en_us` 视为未完成 | [ADR-017](../00-charter.md) |

### 1.3 什么时候玩家会遇到它

| 时机 | 表现 |
| --- | --- |
| 第一次进入世界 | 一次性提示："按 `Q` 打开任务书（可关闭）"+ 殖民书里多一个入口 |
| 每个时代开始 | 新章节自动解锁，**第一页只有一句话 + 2–3 条可选目标**，不铺满 |
| 每章结束 | "抉择时刻"任务：指向时代面板的**玩家选择**（[PRD-011](../prd/PRD-011-progression-knowledge-and-space.md) §9.1） |
| 关键人物事件 | 人物线任务在**当事人**身上出现（居民页 → 编年史条目 → 对应任务） |
| 玩家关掉任务书 | 一切照常；时代门槛、事件、诊断都不依赖它 |

## 2. 与剧本、教程的关系

| 关系 | 规则 |
| --- | --- |
| **章节集随剧本走** | 剧本通过 [PRD-007](../prd/PRD-007-scenarios.md) 的三级覆盖（`剧本 > serverconfig > 整合包默认`）声明 `questbook.chapters`；`plaa:standard` 用全量章节，`plaa:severe_winter` 把"过冬"章节提前到第 0 章 |
| **教程不强制** | `plaa:tutorial` 提供"新殖民地手册"（第 0 章的精简版 + Ponder 引导链）；其他剧本只在任务书**列表顶部推荐**一次，玩家可永久关闭 |
| **入口一致** | 三个入口指向同一份内容：① `Q` 键（FTB 原生界面）② 殖民书面板 → 任务书页 ③ 殖民书 → 自检页（[pack/01](00-pack-spec.md) 的"这个值是谁定的"同源精神） |
| **不做的事** | 任务书**不**定义剧本、不定义时代门槛、不定义事件权重；这三样分别在 PRD-007 / [d08](../design/08-progression-and-ages.md) / [PRD-002](../prd/PRD-002-incidents-and-narrator.md) 里 |
| **奖励发放** | 奖励走**游戏内实体生成**（`colony.submit` 生成的物品/蓝图/牲畜），而不是 FTB 的凭空物品；生成的物品必须进仓库并遵守 [PRD-006](../prd/PRD-006-stock-rules-and-diagnosis.md) 的仓储规则 |

**章节结构固定为 4 段**（所有章节一致，便于玩家形成预期）：

| 段 | 名称 | 内容 |
| --- | --- | --- |
| A | **引子** | 1–2 句剧情，引用已经发生的事（来自编年史） |
| B | **立命** | 2–3 条主线任务：本章的**新动词**首次被使用 |
| C | **扎根** | 3–4 条经营任务：把新动词变成稳定产出（这一段的奖励最"居民化"） |
| D | **抉择** | 1 条抉择任务 + 1–2 条人物/世界线支线（对齐 §5） |

## 4. 逐章大纲与任务列表

> **阅读方式**：每条任务给出「目标（玩家做什么）→ 完成条件（系统怎么判定）→ 提示 → 奖励（驱动居民）→ 前置」。
> 完成条件一律写成**可判定的系统状态**（建筑存在、物资数量、事件发生、洞见获得、居民状态），不写"感受"。
> 奖励栏里的 `+` 表示新增生成；全部走 §2 的实体生成路径。

### 4.1 序章 · 拾石（时代 0 落脚）

**引子**：「你们从船上下来的时候，只带了四个人、两把镐和一袋种子。今晚要有地方睡。」

**本章新动词**：采集 / 狩猎 / 搭简易庇护所（[d08 §2](../design/08-progression-and-ages.md)）。

| id | 标题 | 目标 | 完成条件 | 提示 | 奖励 | 前置 |
| --- | --- | --- | --- | --- | --- | --- |
| `q0-01` | 第一块石头 | 用手或工具取得石头 | 库存石材 ≥ 20 | "对着石头长按左键" | 无（教会采集即可） | —— |
| `q0-02` | 第一根木头 | 取得原木 | 库存原木 ≥ 16 | "先做一把斧头更快" | +1 简易斧（耐久低） | `q0-01` |
| `q0-03` | 有个能躺下的地方 | 搭一个能避雨的庇护所 | 检测到**有顶 + 有床位**的可居住空间 ≥ 4 人 | "屋顶要完整，门口别朝天" | +1 火把 | `q0-02` |
| `q0-04` | 火 | 生一堆火 | 存在点燃的火源方块且持续 ≥ 1 游戏日 | "火也影响体温" | +4 木炭 | `q0-03` |
| `q0-05` | 今晚吃什么 | 用食物喂饱全体居民一次 | 全体居民饥饿值 ≥ 阈值（[PRD-003](../prd/PRD-003-season-temperature-thirst-nutrition.md)） | "采集 + 狩猎都算" | +8 杂粮 | `q0-04` |
| `q0-06` | 第一件工具 | 完成一次制作 | 任意工位完成 1 次制作 | "工坊在工作台那一页" | +1 蓝图：`plaa:crude_bench` | `q0-02` |
| `q0-07` | 认得这地方 | 划定第一块区域用途 | 存在 ≥ 1 个用途区域（[PRD-005](../prd/PRD-005-intent-and-micro-control.md)） | "区域 = 告诉居民这里该干什么" | +1 蓝图：`plaa:storage_pit` | `q0-03` |
| `q0-08` | 活过第一夜 | 全员存活到第二天清晨 | 进入第 2 个游戏日时，死亡数 = 0 | "夜里会冷，别让人在外面睡" | +2 居民（第 3 日起陆续到达） | `q0-05` |

**事件钩子**：野兽（`incident.wildlife` 类）、寒夜（`incident.cold_snap`）；首次死亡必须写编年史（[PRD-002](../prd/PRD-002-incidents-and-narrator.md)）。

### 4.2 第一章 · 第一捧谷（时代 1 定居）

**引子**：「种子撒下去了。接下来三十天，你们要么学会算账，要么学会挨饿。」

| id | 标题 | 目标 | 完成条件 | 提示 | 奖励 | 前置 |

| `q1-02` | 水要送上去 | 建立第一处灌溉 | 农田 50% 格子处于灌溉覆盖 | "水渠比水桶省人力" | +1 蓝图：`plaa:irrigation_ditch` | `q1-01` |
| `q1-03` | 会攒东西 | 设置第一条仓储规则 | 存在 ≥ 1 条规则（保留量/配额） | "留着过冬的粮不要被吃光" | +1 蓝图：`plaa:granary` | `q1-01` |
| `q1-04` | 圈起来 | 建第一个畜栏并养 2 只 | 畜栏内动物 ≥ 2 且围栏完整 | "动物会吃田里的东西" | +2 鸡 | `q1-01` |
| `q1-05` | 第一次收获 | 完成一次作物收获并入库 | 收获事件 ≥ 1 且入库数量 > 0 | "别让它在田里烂掉" | +1 蓝图：`plaa:threshing_floor` | `q1-02` |
| `q1-06` | 存到冬天 | 让储粮达到过冬线 | 可食用库存 ≥ 全人口 × N 日（默认 24） | "任务书会算出你还差多少" | +1 知识线索：`plaa:insight_drying` | `q1-03` |
| `q1-07` | 有个当家的 | 指派第一份稳定的工作 | 存在 ≥ 1 名居民持有固定岗位 ≥ 3 游戏日 | "岗位比临时指派省心" | +1 居民 | `q1-05` |
| `q1-08` | 抉择：稻作还是牧养 | **在游戏内**选择本时代方向 | 玩家在时代面板按下选择（任务书只提示） | "选了也能补，只是更贵"（[d08 R-AGE-3](../design/08-progression-and-ages.md)） | 对应方向 +1 蓝图 | `q1-06` |

**事件钩子**：歉收（`incident.crop_failure`）、虫害、严冬前兆；**第一次歉收**触发人物线（§5.2）。

### 4.5 第四章 · 一万件同样的东西（时代 4 规模/工业）

## 5. 三条并行剧情线

### 5.1 主线 · 拾石而上

**骨架** = 7 个时代（§4 的 8 章）。主线**不发明新情节**，它只做一件事：把时代门槛翻译成"你现在该干什么"。
每个时代的"抉择时刻"是主线的**节拍点**，玩家按下的那一刻写进编年史（[PRD-002](../prd/PRD-002-incidents-and-narrator.md)）。

| 节拍 | 呈现 | 依据 |
| --- | --- | --- |
| 章首引子 | 引用上一章真实发生的事（自动拼接编年史条目） | [PRD-002](../prd/PRD-002-incidents-and-narrator.md) `ChronicleEntry` |
| 章中任务 | 只用**可判定状态** | [PRD-011](../prd/PRD-011-progression-knowledge-and-space.md) 门槛三部分 |
| 章末抉择 | 指向时代面板，任务书只提示 | R-QB-6 |

### 5.2 人物线 · 有名字的人（至少 6 条）

**规则**：人物线**必须**由真实居民触发，引用其记忆与关系；居民死了，线就断（并写成讣告）——**不允许 NPC 剧本杀式复活**。

| id | 标题 | 触发 | 任务链（3–5 步） | 依据系统 |
| --- | --- | --- | --- | --- |
| `pl-p1` | 发现的那个人 | 首次获得洞见 | 见证 → 让他继续研究 → 教会第二人 → 命名一座建筑 | [PRD-011](../prd/PRD-011-progression-knowledge-and-space.md) 洞见有人名 |
| `pl-p2` | 一个家名 | 出现第二代 | 出生 → 成年礼 → 成家 → 让家名传到第三代 | [PRD-009](../prd/PRD-009-generations-and-legacy.md) |
| `pl-p3` | 回不来的人 | 有居民被掳 | 得知 → 谈判/营救 → 归来或讣告 → 立碑 | [PRD-004](../prd/PRD-004-threats-and-defence.md)、[PRD-015](../prd/PRD-015-captivity-and-prisoners.md) |
| `pl-p4` | 冤家 | 出现 `grudge` 高值的一对 | 冲突 → 调停/共同经历 → 和解或永久敌对 | [PRD-008](../prd/PRD-008-relationships-and-social.md) |

### 5.3 世界线 · 别人的心思（分支钩子）

**规则**：世界线只读**关系值与非玩家势力的真实状态**（[PRD-010](../prd/PRD-010-diplomacy-and-trade.md)），且每个分支必须能在**游戏内**被观察到（商队变少、袭击变多、使节上门）。

| id | 分支 | 玩家行为 | 后续钩子（写进任务书与编年史） |
| --- | --- | --- | --- |
| `wl-1` | 邻居 | 长期与某势力交易 | 该势力派使节求盟；拒绝则关系回落（有前兆） |
| `wl-2` | 债 | 多次赊欠/欺诈成交 | 商队收费上浮 → 断供 → 掠夺者得到情报 |

| `wl-4` | 榜样 | 长期收留难民/释放俘虏 | 移民增多、出现"慕名而来的工匠"（+1 居民 + 技能） |
| `wl-5` | 名声 | 出现器官摘取等黑暗行为 | 名声下坠 → 商队拒绝 → 内部情绪与 `grudge` 连锁（[PRD-013](../prd/PRD-013-medical-and-surgery.md) 的四项级联） |

### 5.4 世界线的触发阈值（必须写死，不许"感觉式"）

| id | 触发量 | 阈值（默认） | 前兆（[PRD-002](../prd/PRD-002-incidents-and-narrator.md) `herald`） | 玩家可干预窗口 |
| --- | --- | --- | --- | --- |
| `wl-1` | 与某势力累计成交额 / 成交次数 | 成交 ≥ 5 次且 `standing` ≥ +40 | 商队开始打听你们的名字 | 3 游戏日内决定结盟或婉拒 |
| `wl-2` | 未履约/欺诈成交次数 | ≥ 2 次 | 商队要求预付、报价上浮 | 补款或换供应商 |

### 5.5 多人下的三条线

| 项 | 规则 |
| --- | --- |
| 进度归属 | **殖民地共享**（与 [PRD-012](../prd/PRD-012-multiplayer-and-permissions.md) R-MP-7"归属殖民地而非玩家"一致）；倾向见 OQ-5 |
| 人物线归属 | 线跟着**居民**走，不跟着玩家走：谁在线都能看到"某居民的故事"，但**只有当事人/管理者能替他做决定**（如是否出战） |

### 5.6 人物线断线时的处理（必须写清，否则实现会乱来）

| 情形 | 处理 |
| --- | --- |
| 当事人死亡 | 线**立即终止**，转为讣告 + 编年史条目；后续由 `pl-p2`（家名）或 `pl-p5`（活下来的人）接续，**不复活、不幻觉** |

### 7.4 无 FTB 时的"自检页"规格（兜底的**不可丢**部分）

殖民书面板 → 自检页：**每进入一个新时代就多一页**，页内固定 4 行结构（复用 [PRD-006](../prd/PRD-006-stock-rules-and-diagnosis.md) 的"为什么"组件，遵守 32 行/页、8 行/卡预算）：

| 行 | 内容 | 数据来源 |
| --- | --- | --- |
| 1 | **一句话结论**：「要到<下一时代>，你还缺 2 项」 | [PRD-011](../prd/PRD-011-progression-knowledge-and-space.md) 门槛求值 |
| 2 | **材料**：名称 + 当前/需要（例：铁锭 40/60） | [PRD-006](../prd/PRD-006-stock-rules-and-diagnosis.md) 库存账 |

| 4 | **选择**：待玩家按下的方向（有按钮，按下即推进） | [d08](../design/08-progression-and-ages.md) R-AGE-2 |

**R-QB-14**：自检页与任务书必须**同源**——两者都从同一份门槛求值结果渲染；不允许各算一遍（否则会出现"任务书说可以了、自检页说还差"的矛盾）。

| 奖励实体 | 一律通过游戏内生成（§2），奖励 id 形如 `plaa:reward/<name>`，可被数据包重定义 |
| 剧本覆盖 | 剧本用 `questbook.chapters=[...]` 与 `questbook.sandbox=true` 覆盖章节集；覆盖优先级 `剧本 > serverconfig > 整合包默认`（[PRD-007](../prd/PRD-007-scenarios.md)） |
| 与编年史互引 | 任务页可显示"相关编年史条目"链接；编年史条目可标注"它属于哪一章"（**单向读取**，任务书不改写编年史） |
| 版本迁移 | 任务进度随存档保存；章节/任务 id **只增不改**，废弃项标 `deprecated:` 保留键（保证老存档不出现断链任务） |

### 8.1 判定层：系统怎么知道"这条任务完成了"

| 方式 | 适用任务 | 说明 | 状态 |
| --- | --- | --- | --- |
| **原生任务类型**（物品/进度/维度/击杀…） | `q0-*`、`q1-05`、`q3-03`、`q6-06` 这类"有物品或进度可查"的 | 直接用 FTB 自带类型，零代码 | 可用（FTB 2101 面） |
| **自定义 Task 注册** | `q0-03`（可居住空间）、`q1-06`（过冬线）、`q4-05`（失禁次数）、`q6-07`（自持度）这类**只有我们算得出**的 | 需要在我们 mod 侧注册只读判定器，把"游戏状态"暴露给 FTB；**属于 L2 集成点**，实现前必须先验证 FTB 2101 的自定义 Task 注册 API 是否公开 | **未验证**（M2 前 spike，见 §9.5 T-3） |
| **事件驱动推送** | 抉择时刻、结局、人物线节点 | 由我们的事件总线推一条"里程碑达成"给任务书（单向：状态 → 任务书） | 设计已定（[PRD-002](../prd/PRD-002-incidents-and-narrator.md) 同类机制） |
| **`checkmark` 兜底** | 自定义判定失败时 | 玩家手动勾选；但**我们的面板必须独立显示真实条件是否达成**（否则等于骗玩家） | 降级方案 |

**R-QB-15**：判定层**只读**——任何判定器不得写入玩法数据（静态检查，见 AC-11）。
**R-QB-16**：判定成本必须**相位化**：不得每 tick 扫描全区；按 [PRD-002](../prd/PRD-002-incidents-and-narrator.md) 同级的 `Cadence` 槽位低频求值（建议 1 秒级），并给出探针（"任务判定耗时/刻"）。
**R-QB-17**：判定逻辑**只有一份**：任务书、自检页、诊断页三者共享同一求值结果（R-QB-14 的推广）。

### 8.2 提示与文案规范

| 规范 | 要求 | 反例 |
| --- | --- | --- |
| 长度 | 标题 ≤ 12 字（英 ≤ 6 词）；描述 ≤ 40 字；提示 ≤ 30 字 | 「建立一套完整的、可持续运转的、能够抵御各种自然灾害的农业生产体系」 |
| 人称 | 第二人称"你"；不出现"玩家" | 「玩家需要建造」 |
| 术语 | 只用 [d03](../design/03-glossary.md) 的官方译名（殖民地/居民/殖民书…） | 「聚落」「小人」 |
| 无实现名词 | 不出现货架、id、tick、方块坐标 | 「把 `need` 货架里的 thirst 调高」 |
| 不剧透数值 | 提示不给精确公式，给方向（"烟囱有方向"而不是"扩散系数 0.35"） | —— |
| 不指责 | 失败提示描述原因，不评判玩家 | 「你太蠢了，居然没存粮」 |
| 前兆友好 | 危机类提示必须带"还能做什么" | 「要过冬了」→「要过冬了；先把储粮补到 24 日线」 |

### 8.3 奖励清单（全部可被数据包重定义）

| 奖励 id | 内容 | 驱动方式（[ADR-013](../00-charter.md)） | 通胀保护 |
| --- | --- | --- | --- |
| `plaa:reward/starter_tools` | 少量低耐久工具 | 让居民先能干成活 | 仅序章，且不可交易 |
| `plaa:reward/blueprint/<name>` | 建筑蓝图 | 解锁新动词 | 每蓝图唯一，重复发放前检查已有 |
| `plaa:reward/insight/<name>` | 知识线索（[PRD-011](../prd/PRD-011-progression-knowledge-and-space.md)） | 缩短知识门槛但**不替代行为** | 洞见必须有人名与来源 |
| `plaa:reward/seed_pack` | 种子 | 农业起步 | 数量固定、不随人口缩放 |
| `plaa:reward/livestock` | 牲畜 | 牧养起步 | 仅在无牲畜时发放 |
| `plaa:reward/migrant` | 1–2 名新居民 | 人口与技能 | 受住房/食物压力自然约束（[PRD-009](../prd/PRD-009-generations-and-legacy.md) 无硬上限） |
| `plaa:reward/relation` | 关系机会（`standing` 调整由 [PRD-010](../prd/PRD-010-diplomacy-and-trade.md) 唯一写入） | 外交起步 | 单次幅度小，且双向（帮忙也会得罪另一方） |
| `plaa:reward/medicine` | 药品 | 医疗起步 | 数量小；依赖 PRD-013 的药品级 |

**R-QB-18**：**禁止**的奖励形态——玩家属性 buff、经验倍数、永久价格折扣、无限资源、"跳过生产链"的成品大批量投放。
**R-QB-19**：奖励发放必须有**上限与去重**（同一蓝图/洞见不重复给），且进仓库时服从 [PRD-006](../prd/PRD-006-stock-rules-and-diagnosis.md)（仓库满了要有行为，不能凭空消失）。

### 8.4 反模式（明确不做，评审可直接引用）

| 反模式 | 为什么不做 |
| --- | --- |
| 任务树当成"科技树" | 时代推进必须是材料 ∧ 知识 ∧ 玩家选择（[PRD-011](../prd/PRD-011-progression-knowledge-and-space.md)），任务不该变成解锁开关 |
| 用奖励勾着玩家走 | 奖励只解决"起步摩擦"，长期动力来自居民与世界（支柱 P2/P3） |
| 满屏红点/每日任务 | 与"意图而非指令"（P1）冲突，制造焦虑 |
| 剧情文本与游戏状态脱节 | 一旦矛盾，玩家立刻不信任务书（R-QB-7） |
| 强制教程/强制章节 | R-QB-5 |
| 把重要诊断藏在任务书里 | 诊断是管理者生命线（[PRD-006](../prd/PRD-006-stock-rules-and-diagnosis.md)），必须在殖民书里随时可见 |
| 多人下按玩家分发进度 | 与 [PRD-012](../prd/PRD-012-multiplayer-and-permissions.md) 的"归属殖民地"冲突（OQ-5 待定但倾向已明） |

## 9. 验收清单

### 9.1 内容
- [ ] AC-1 8 个章节全部有：引子、≥ 2 条立命任务、≥ 3 条扎根任务、1 条抉择任务
- [ ] AC-2 每条任务的"完成条件"都能被系统状态判定（人工评审：不允许主观描述）
- [ ] AC-3 每条奖励都能驱动居民（物资/蓝图/知识线索/关系机会/居民），**无任何玩家 buff 类奖励**
- [ ] AC-4 每个时代至少有一个任务演示该时代的**新动词**（逐章核对 [d08 §2](../design/08-progression-and-ages.md)）
- [ ] AC-5 三条剧情线各自 ≥ 5 条链，且每条链的第一环都能由**真实游戏事件**触发
- [ ] AC-6 3 个结局各有一条可复现的达成路径（在测试存档上验证）

### 9.2 行为与边界
- [ ] AC-7 关闭任务书 UI 后，游戏全部功能不受影响（含时代推进与事件）
- [ ] AC-8 卸载 FTB Quests 后能正常启动、能完成"序章 + 第一章"的骨架（§7 的不可丢清单全部有兜底）
- [ ] AC-9 抉择任务**不能**替玩家做选择：不点时代面板就没有任何推进
- [ ] AC-10 已获得的奖励在中途卸载 FTB 后**不回滚**，重新装回后进度继续
- [ ] AC-11 任务书不修改任何玩法数据（静态检查：KubeJS 脚本里不得出现规则写入）

### 9.3 数据与本地化
- [ ] AC-12 所有任务/章节键 `zh_cn` + `en_us` 齐全，占位符一致（CI）
- [ ] AC-13 任务 id 只增不改；模拟"老存档 + 新版本"能加载且无断链
- [ ] AC-14 剧本覆盖 `questbook.chapters` 生效（用 `plaa:severe_winter` 验证"过冬章节提前"）
- [ ] AC-15 任务页能引用并打开对应编年史条目

### 9.4 体验
- [ ] AC-16 新手在**不看任何外部文档**的情况下，只用任务书能从落地玩到第一次过冬准备（可用性测试）
- [ ] AC-17 每章首屏信息量 ≤ 1 句引子 + 3 条任务（不铺满）
- [ ] AC-18 任务书随时可关闭，且关闭后不再弹出任何提示（除非玩家主动重新打开）
