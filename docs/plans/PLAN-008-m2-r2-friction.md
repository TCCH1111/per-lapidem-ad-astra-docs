## 1. 为什么这一刀不碰否决权

PRD-008 里"仇敌拒绝共事"最直观的实现是**否决权**（我们已有 `Vetoes`）。但读契约后确认：
`Veto.check(resident, cell)` **只拿到"谁"和"哪一格"**，拿不到"那格上还有谁"。
要表达"不和 X 一起干活"，必须在**派活的选留阶段**看另一名工人的位置——那是 `Tours`/`Scheduler` 的内部，属 **L3**。

**所以这一刀换个做法**：不做硬性否决，做**软性代价**——和仇人一起干活会**拉低心情**，玩家自己决定要不要把他们分开。
好处：L1、复用 R1 的采样器与卡片、且**不引入新的调度钩子**。

## 2. 切片内容

### 2.1 一句话

> 状态差的人容易和身边的人起摩擦；摩擦久了，两个人一起干活就都不痛快——
> **所以你要么改善条件，要么把他们分开。**

### 2.2 三件事

| # | 规则 | 层 |
| --- | --- | --- |
| 1 | 关系簿增加 `grudge`（与 `bond` **独立**，PRD 明确要求） | L1 |
| 2 | **采样时**：两人都在干活且 ≤8 格，其中**任一人处于 `STRESSED`/`DESPERATE`** → 双方 `grudge` 各 +1（同一冷却） | L1（复用采样器） |
| 3 | 心情：若**有仇人（grudge ≥ 40）在旁**，则**至少 `WORRIED`**，且享受不到伙伴加成 | L1 |
| 4 | 卡片：仇人在旁时一行「和 X 一起干活，心里不痛快」+ 建议「把他们分开」 | L1 |
| 5 | 解释：说清"他不痛快是因为旁边有人"，**不得冒充饥饿或作息** | L1 |

### 2.3 决策在哪里

| 决策 | 代价 |
| --- | --- |
| 改善条件（喂饱、减班） | 花资源；但怨气不再增长 |
| 把两人分开（分区/错班） | 牺牲排布效率；但两边都不再掉心情 |
| 什么都不做 | 怨气继续涨，两人长期 `WORRIED`，产能下降 |

**这就是"人事安排有内容"的第二次落地。**

## 3. 数据变更

```java
// 现有 Bond(target, bond, lastTouch, shared)
record Bond(UUID target, int bond, int grudge, long lastTouch, int shared) {}
```

- `grudge` 与 `bond` 独立：可以既亲近又怨恨（PRD 明确）；
- 同样受 30 条上限与 `lastTouch` 冷却约束；
- 存读沿用 `Writer.children`（与 R1 一致）。

## 5. 验收

| 判据 | 怎么验 |
| --- | --- |
| `grudge` 与 `bond` 独立 | 单测：既加 bond 又加 grudge 后两者都在 |
| 只在状态差时起摩擦 | 纯函数测试：双方状态好 → 不涨；一方 `STRESSED` → 涨 |
| 仇人在旁至少 `WORRIED` | 心情测试：`CONTENT` + 仇人 → `WORRIED`；`DESPERATE` 仍是 `DESPERATE` |
| 不冒充 | 卡片文案与解释不得出现"饿/作息"字样 |
| 默认零影响 | 没有仇人时，1479 基线一条不退 |
| 四语齐全 | 新键必须在四份语言表里（D18 的门禁会强制） |

## 6. 风险

| 风险 | 处理 |
| --- | --- |
| 怨气涨太快，全员互恨 | 与 bond 同一冷却（半小时一次）；40 才算"仇人"；每日衰减（TBD：是否 R2 就做衰减） |
| 与 mood 耦合变复杂 | 只加一个布尔 `amongRivals`，规则只做"至少 WORRIED + 无伙伴加成" |
| 玩家看不懂 | 卡片两行 + 解释层；文案直接说"把他们分开" |
| 采样器变慢 | 复用同一次采样，不新增扫描 |
