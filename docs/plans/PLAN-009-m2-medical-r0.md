## 1. 为什么先切这一刀

PRD-013 的 **R-MED-5** 要求 M2 交付**至少一条完整的"受伤 → 感染 → 治疗 → 康复或死亡"链路**。
那是整条医疗的下限，一条轮次做不完，所以先切出**能被看见、能被验证**的第一段：

> **伤口会存在、会流血、会让人变慢、会在卡片上说清——但还不会感染。**

这一段的价值：它把"伤"变成**引擎里真实存在的东西**，
后面接感染、包扎质量、卧床、搬运时，不需要重做数据层。

## 3. 明确不做（留给后续刀）

| 不做 | 原因 |
| --- | --- |
| **感染 → 发烧 → 死亡**（R-MED-5 的完整链路） | 需要 `Cadence` 与死亡处理，R1 再做 |
| **包扎/治疗质量**（医生熟练度/药品/病房） | R-MED-8 要求三者**各自可测**，需要设计确认 |
| **倒地与搬运**（`Carrying`） | 需要接管层与搬运工作，R2 |
| **手术、义体、截肢** | PRD-013 后半，M3 之后 |
| **受伤影响排班**（能不能去干活） | **见 §6-Q1**，不替玩家决定 |

## 6. 需要你拍板（本轮唯一阻塞项）

**Q1（最重要）**：受伤**要不要影响排班**？
PRD-013 的 R-MED-7 只要求"四选一"（速度/工作/意识/代谢），**速度已经满足条文**。

| 选项 | 含义 | 代价 |
| --- | --- | --- |
| **A（我建议先做）** | R0 **只做速度**，伤者照常干活 | 简单、可逆；但"重伤还在扛包"看起来不合理 |
| B | 重伤者**不被派活**（走 `Vetoes`，L1） | 更像殖民地；但会立刻改变排班与产能 |
| C | 分档：轻伤照常、重伤停下 | 最合理；需要先定"重伤"的判据 |

**Q2**：包扎由谁发起？
ADR-013 禁止玩家手动微操，所以倾向 **居民自己做**（urge：有伤→去拿绷带→自我包扎）。
但"绷带从哪来"需要 [PRD-006](../prd/PRD-006-stock-rules-and-diagnosis.md) 的仓储规则——**R0 先不做包扎，只做流血与速度**，把包扎放进 R1。

**Q3**：死亡处理（讣告/尸体）是否进 R1？
PRD-009 有对应内容；若要"康复或死亡"完整闭环，死亡必须有迹可循（否则玩家不知道为什么少了一个人）。

## 7. 验收

| 判据 | 怎么验 |
| --- | --- |
| 玩家能看见伤 | 卡片一行，且只在有伤时出现 |
| 玩家能看见后果 | 同一个居民受伤前后速度确实不同（gametest 断言修正值） |
| 不撒谎 | 文案不冒充饥饿/作息/禁限区 |
| 零默认影响 | 无伤时 1482 条基线不退 |
| 可继续 | 数据层结构允许 R1 直接加感染字段，不需要改 R0 的形状 |
