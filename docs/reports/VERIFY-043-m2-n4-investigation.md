## 2. 事实

| 事实 | 位置 |
| --- | --- |
| 需求 → urge → 选留的**唯一决策点**是内联谓词 | `ColonyLabor.java:318-321`：`urges.keenest(offered, tick, urge -> !personalRequests... && (!runner.executing() \|\| urge.preempts() && ...))` |
| `Urges.offered` 只做**过滤**（参与度/权重），`keenest` 只做**排序+退避** | `Urges.java:39-52` |
| `ColonyContext.urges` **只能追加**来源，不能压制 | VERIFY-022（实读 `ColonyWorks.urges`：纯拼接） |
| `Standing` 只在**派活**时被问 | VERIFY-016/017（`Tours.unfit`） |
| 该谓词**没有任何插件扩展点** | `ColonyLabor` 里没有 filter 列表/注册表 |

**结论**：

| 模式 | 代价 |
| --- | --- |
| `needs-first`（现状：需求总能越过作息） | **零改动**，但要在解释层**说清楚** |
| `rules-first`（规则压过需求） | **L3**：在 `ColonyLabor:318` 的谓词里加一个插件提供的否决（与 `Standing` 同款：注册表 + 一次调用） |

---

## 3. 建议（先说我的判断）

**这一轮只做 `needs-first` + 解释**，理由：

1. 现在玩家看到的现象是"到点收工，但饿了他就去吃"——**这本身就是张力**，而且是**可解释的**（"他到点收工了，因为饿"）；
2. `rules-first` 的代价是一次 L3，而它的收益（让居民忍着不吃饭）在 M2 当前阶段**不是必需**：PRD 的张力更多来自"资源不足时的取舍"，而不是"折磨居民"；
3. 按 D8 的教训：**先把话说对，再决定要不要加更狠的规则**。

如果将来要做 `rules-first`，实现形状已经清楚（与 `Standing` 完全同款），届时按 L3 报批。
