把 `NO_LICENCE` 与 `PACK_FULL` 从 **D 级（零证据）** 提到 A 级：用 W5 的求解器夹具造出来，证明引擎真的会产出这两个原因。

## 3. 三个假设（按可能性排序）

1. **生长阶段已经过滤**：`Fitness` 的类注释写明"计划只为合适的人生长活"（`Fitness.anyone`）。一个从头就不合适的人，**根本不会有活长出来**，自然也没有"没派出去"的记录。
2. **第二次仍用了同一个工人 id**：`Tours` 里 `keeping(seat, id)` 会把"已经在这条路线上的活"跳过判定。我的第二阶段沿用了 `fixture.crew.hands().getFirst()` 的 `who`，所以活可能被当成"他已经在做"而跳过，而不是被拒绝。
3. **这两个原因可能根本不走运输路径**：它们也许只在 `Survey`/`Requests` 之类的路径产生，而我只测了 `Delivery`。

## 4. 下一轮的具体做法（不需要再猜）

按假设 2 直接改：**第二阶段换一个不同 id 的工人**（`new Resident(UUID.randomUUID(), kind)`），让 `keeping()` 不成立；如果仍然为空，再按假设 3 去读 `Survey`/`Requests` 里 `Unassigned.Reason.NO_LICENCE` 的**构造点**（目前 grep 到的唯一构造点是 `Tours:1458` 从 `Unfit.NO_LICENCE` 映射，而 `Unfit` 又只由 `Fitness` 产生）。
