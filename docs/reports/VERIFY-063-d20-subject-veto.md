## 1. 补上的那一环

引擎问的是 `Veto.check(UUID resident, BlockPos cell)`——**只有 id**。
殖民地现在维护 `UUID → kind` 的映射（每秒刷新一次），否决权据此回答：

```java
ResourceLocation subject = kinds.apply(resident);
return state.refusal(cell, subject, 0).map(SteeringRefusal::of);
```

于是**主体类区域第一次真的起作用**：

| 区域 | 修复前 | 修复后 |
| --- | --- | --- |
| `ALLOW_ONLY`（只准农夫进） | 只进诊断 | **矿工确实被拒** |
| `CONFINE`（囚犯只能待在牢区） | 只进诊断 | **囚犯确实出不去** |
| `FORBID`（空主体） | 生效 | 仍生效 |

## 2. 两个刻意留下的限制（写在代码里，不藏着）

| 限制 | 原因 |
| --- | --- |
| `kind` 未知时**退回旧行为**（只认空主体 FORBID） | 若"不知道就全拒"，一次缓存滞后会把整个殖民地钉死 |
| `LIMIT` 的 insideCount 传 **0** | 每次格子询问都去数区内人数，等于**每次查询扫一遍殖民地**；等有廉价计数器再接 |

**所以 `LIMIT` 仍然只走诊断层**——这条写在注释与报告里。
