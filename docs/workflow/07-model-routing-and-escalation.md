# 模型分级与升级协议（把钱花在刀刃上）

```
状态：草稿
负责人：项目发起人
最后更新：2026-10-19
上游依据：docs/workflow/00-ai-workflow.md、docs/workflow/01-agent-roles-and-tools.md、docs/workflow/04-prompts.md
```

> 一句话：**贵的模型不该"多干"，该"干别人干不了的"**——凡是**能写成检查脚本**的活，都不该由它做；凡是**一次做错就要返工很久**的判断，才值得买它的思考。

---

## 0. 分派原则：按"不可逆 × 独占上下文"分，不按"感觉难"

| 维度 | 高（→ 贵模型） | 低（→ 便宜模型 + 脚本） |
| --- | --- | --- |
| **不可逆性**（改错要重写文档/返工架构） | 架构裁决、L3 评审、跨文档冲突裁决 | 登记、编号、链接、格式 |
| **上下文独占性**（必须同时握住很多约束） | 引擎硬常量之间的取舍、状态机与存档迁移 | 单文件内的增删改 |
| **可验证性**（能不能用一条命令判对错） | 不能（需要判断"这个方案会不会在 6 个月后咬人"） | 能（断链检查、表格列数、AC 编号存在性） |
| **重复度** | 一次性、没有先例 | 已有 5 个同类先例，照抄改参数 |

**判定口诀**：如果这件事**做错了我只会骂一句然后重做**，给便宜模型；如果**做错了我两周后才发现**，给贵模型。

## 2. 明确**不要**给贵模型的（便宜模型 + 脚本就够）

| 任务 | 正确工具 | 判据 |
| --- | --- | --- |
| 按模板批量生成/扩写文档章节 | 便宜模型 | 有模板、有先例、可抽查 |
| README 登记、编号、表格列数、断链修复 | 脚本 + 便宜模型 | 有确定性检查（本会话里就是 `Select-String` + 正则链接检查） |
| "四语言 → 双语"这类口径收敛 | 便宜模型 | 规则明确，命中可用 grep 列出 |
| 把一段结论改写成另一种格式 | 便宜模型 | 无判断，只有转换 |
| 重复已经做过一次的调研 | **谁都不派** | 先查 `docs/`，多数答案已在库里 |
| "顺便把文档也更新了" | 禁止 | 见 §5 反模式 |

**R-MR-1**：**能写成检查脚本的验收，不许用模型判断**。模型只处理"脚本判不了"的部分。

## 3. 怎么跟贵模型说（四段式模板，复制即用）

核心是**把问题削到只剩判断**：边界收窄 → 证据给足 → 交付物固定 → 停止条件明确。

```
【角色】你是本项目的架构裁决者。你只做一件事，不做别的。

【边界】
- 只回答：【一个具体问题，一句话，带问号】
- 不要动：【列 1–3 个文件/编号】；不要新增规则编号；不要重写全文；不要"顺手优化"别的章节。
- 不要写实现代码（本阶段禁止）；不要猜基底行为——没读到源码就写"未验证"。

【证据包】（以下是我已核实的事实，直接引用，不必再查全库）
- 【文件:行号 + 该行内容的关键常量，2–6 条】
- 【相关文档：链接 + 它已经决定了什么】
- 【已知约束：例如"不许 L4"、"L3 必须单独评审"、"双语文案"】
- 【已经排除的方案 + 排除理由】

【交付规格】（缺一项算没交付）
1. 结论：一句话，可执行（不是"建议考虑"）。
2. 依据：每条结论后面跟 `文件:行号` 或文档链接。
3. 取舍：你放弃了什么，代价是什么（数字或人日）。
4. 风险：如果这个判断错了，最先在哪一步暴露？怎么用一条命令或一个 gametest 提前发现？
5. 待决：需要人类拍板的点（最多 3 条），每条给两个选项与推荐。
6. 不确定：显式列出"我没验证、只是推断"的部分。

【停止条件】
- 达到交付规格就停；不要继续展开成文档，不要写代码，不要读无关文件。
- 如果你发现【边界】里的前提是错的，先停下来告诉我错在哪，不要绕过。
```

### 3.1 两段式（省钱的关键）

**第一段（便宜模型或你自己）**：把问题写成上面这个包——**这一步最花时间，但最省贵模型的钱**。
**第二段（贵模型）**：只跑"判断"那一步，输出上面 6 项。
**第三段（便宜模型）**：按结论改文档、登记、跑检查。

> 反例：直接把"帮我把 M1 做出来"丢给贵模型——它会先花 80% 的 token 重建上下文，然后用 20% 猜。

### 3.2 让它"少说"的三个硬要求

1. **一次只答一个问题**（多问会让它把答案搅在一起，你反而要重问）。
2. **结论先行，证据附后**（它天然爱铺垫；要求"第一行就是结论"能把输出砍掉一半）。
3. **禁止它重复你的话**（模板里明写"不要复述【证据包】"，否则它会把 500 字证据抄一遍再回答）。

## 4. 什么时候必须升级（触发信号）

出现下面任一情况，**停止用便宜模型硬扛**，直接升级——继续试的代价通常更高：

| 触发信号 | 例子（本会话真实发生过） |
| --- | --- |
| **两份文档互相矛盾**，且都有依据 | 诊断编号撞车（D-17~D-20 vs D-20~D-23）、温度场所有权、"需求固定 7 条"vs 数据驱动 |
| **同一个问题改了两轮还没收敛** | 双语口径改了两次仍有残留 |
| **结论会改变架构**（不是改文案） | 气体模型选型、器官腔用不用外部 mod |
| **错了很久才会被发现** | 存档静默只读、`enabledGameTestNamespaces` 少一个命名空间 |
| **需要同时握住 ≥4 个约束**（常量 + 权限 + 存档 + 性能） | 共享出行预算分配 |

**反触发**（这些**不要**升级）：格式、编号、链接、登记、翻译、表格对齐、把已有结论换个说法。

---

## 5. 反模式（花了钱还没效果）

1. **让它读全库**："先看看 docs/ 下 57 份文档"——它会把预算烧在重建上下文上。**只给相关文件 + 行号**。
2. **让它"顺便"改别的**：顺手重构是最贵的失败模式；用【边界】写死"不许动"。
3. **给它模糊目标**："优化一下 M1 的计划"——不可验收，必然产出废话。
4. **让它做登记类工作**：它做一次的钱，够脚本跑一万次。
5. **一次问五个问题**：答案会互相污染，你还要再问一遍。
6. **不告诉它已排除的方案**：它会把你已经否掉的路重新推荐一遍（例如又建议用 Pollution of the Realms）。
7. **不要求"不确定"**：它会把猜测写成事实，而你要到实现阶段才发现。

## 6. Harness 侧的省法（工具层）

| 手段 | 做法 | 省在哪 |
| --- | --- | --- |
| **模型路由** | `subagent` / `workflow` 可对单个子任务指定 provider/model；把 §1 的刀刃任务定向给贵模型，其余走便宜模型 | 只买需要的判断力 |
| **文件交接** | 决策写进文档（[R-ROLE-2](01-agent-roles-and-tools.md)），下次只贴链接 | 不用重复喂上下文 |
| **并行便宜、串行贵** | 便宜模型并行铺量（调研/文档/校验）；贵模型只在汇合点做一次裁决 | 避免贵模型空转 |
| **预算上限** | 派活时写"最多 2 次尝试 / 不超过 N 行输出 / 只读这 4 个文件" | 防发散 |
| **goal 回合** | 用 goal 把长任务切成有界回合，每回合只交付一件可验收的事 | 防跑题，也防"看起来很忙" |

**R-MR-2**：**贵模型的输出必须能落到一个文件或一条命令上**。落不下去的输出（"建议进一步研究"）不算交付。

## 7. 这次升级值不值（事后三问）

派完贵模型，用这三条判断它是否"花在刀刃上"：

1. **它给的是可证伪的结论吗？**（有 `文件:行号`、有"如果错了会在哪暴露"）
2. **它是否暴露了你原本没看到的真风险？**（不是重复你已知的）
3. **它是否让后续任务变短了？**（有的话，后面的执行任务可以直接派便宜模型）

三条里**有两条为否**，说明这个任务不该升级，或者【证据包】给得太差。
