## 0. 这份文档怎么用

### 0.1 三种读者

| 读者 | 怎么读 | 关心什么 |
| --- | --- | --- |
| **人（评审/决策）** | §1 DoD 与演示脚本、§3 总览、§8 风险 | 这一版能不能演示、风险是否可接受 |

### 0.2 与六阶段流水线的关系

[workflow/00 §4](00-ai-workflow.md) 的"阶段三 · Plan + Review"要求：**先把 PRD 的 AC 翻译成可派单的计划，再动手**。本文档就是 M1 的 Plan 产物；每个 WP 对应一次 Plan 的产物单元，每个任务对应一次可独立评审的提交。

### 0.3 三层颗粒度（不要混）

```
工作包 WP ── 能独立验收的交付单元（12 个）
   └── 任务 T ── 一次 agent 会话能做完并自测（58 个）
          └── AC ── 判定真假的锚（83 条，全部来自 PRD，本文档不新增）
```

### 0.4 三条硬纪律

1. **不新增 AC**：本文档引用的每条 AC 都能在对应 PRD 里用编号查到；查不到就是写错了。
2. **不越过 M1 范围**：§1.4 列出的东西即使"顺手能做"也**不做**——M1 的价值是**可演示**，不是覆盖。

## 1. M1 完成定义（DoD）

### 1.1 一句话

**M1 完成 = 一个新人能在 30 分钟内，从新世界走到"居民按玩家画的禁限区与作息表行动，并且任何一个'没发生的事'都能问出原因"，且这个过程在干净机器上可重复、可存档往返、可卸载。**

### 1.2 五条硬门禁（全部可判定，缺一不可）

| # | 门禁 | 判定命令/动作 | 依据 |
| --- | --- | --- | --- |
| G1 | **构建可重复**：干净机器出 jar | `npm install` → `npm run setup` → `./gradlew build`，`build/libs/` 有 jar | [CONTRIBUTING.md:14-22](../../reference/folkways-67f28b0/CONTRIBUTING.md)（`gradle/mod.gradle:39-47`（上游已拆为 ext.lib） 缺 `.blockwright/mods.json` 会抛异常） |
| G2 | **门禁四件套全绿** | `./gradlew build` + `npm run test:unit` + `npm run test:i18n` + `src/gametest`（现为 mods/*/src/gametest） 的 GameTest | §2.2；[workflow/03 §3](03-test-and-acceptance.md) |
| G3 | **运行期零可选依赖** | 只放我们的 jar（+ 必要前驱），游戏能启动，禁限区/作息/诊断可用 | [d12 R-FK-12:146](../design/12-fork-strategy.md)（**运行期**语义，见 §2.4） |
| G4 | **上游同步演练走完一次** | 按 [d12 §6](../design/12-fork-strategy.md) 全流程走一遍并留记录 | [d12 R-FK-11:214](../design/12-fork-strategy.md) |
| G5 | **演示脚本可复现** | §1.3 的 9 步连续走通，不靠 GM 命令救场 | 本文件 |

### 1.3 M1 演示脚本（9 步，逐步可判定）

| 步 | 动作 | 通过判据 |
| --- | --- | --- |
| 1 | 新世界（默认剧本，无额外 mod） | 世界生成完成、无报错日志 |
| 2 | 按基底正常流程建立殖民地、招募 ≥6 居民 | 居民开始自主工作（基底行为） |
| 3 | 画一个**禁限区**（例如"矿区只许这两人进"） | 区内出现该分组的人，区外同组成员不再进入 |
| 4 | 观察区内居民**仍在区内吃饭/取暖/如厕** | 无饿死/冻死/尿裤子（对应 AC-14） |
| 5 | 打开**作息表**（默认关闭 → 显式启用），设"工作/用餐/休息"三段 | 顶部出现启用标识；时段高亮随时间移动 |
| 6 | 观察居民**按表行动** | 用餐时段集中进食、休息时段回床、工作时段回岗位（对应 AC-3/AC-21） |
| 7 | 制造一次"没发生的事"：把食物挪出禁限区 + 关闭用餐时段 | 打开诊断 → 看到 **D 编号 + 具体对象 + 建议动作**（对应 PRD-006 AC-2/3/4/5） |
| 8 | 存档 → 退出 → 读档 | 禁限区、作息表、需求/情绪状态一致（对应 AC-23） |
| 9 | 移除我们的 jar（卸载安全） | 世界能加载、回到基底行为、不崩（对应 AC-12/AC-26） |

> **为什么第 7 步是核心**：M1 的差异化不是"能画区"，而是**画了区之后玩家知道为什么没生效**。这一步失败，M1 就退化成"一个更容易困惑的基底"。

### 1.4 M1 明确不含（防范围膨胀）

| 不含 | 归属 | 依据 |
| --- | --- | --- |
| 年龄 / 世代 / 生育 / 衰老 | M2 之后 | [d05 R-GEN-3](../design/05-settlement-and-residents.md)、ADR-014 |
| 指派（点选某人去干某事）与接管 | M2 | [PRD-005 §2.3](../prd/PRD-005-intent-and-micro-control.md)（M1 只做禁限区 + 作息表） |
| 仓储规则引擎（预留量/优先级/冲突裁决） | M2 | [PRD-006 §2.3](../prd/PRD-006-stock-rules-and-diagnosis.md) |
| 病历/手术/义体、关押、机械族、气体层 | M2–M4 | ADR-015/016/019 |
| 图表（趋势线/热力图）与 e2e/visual/bench/fuzz | M2 起 | §2.2 |
| 多人并发编辑与权限矩阵的完整实现 | M2/M3 | [PRD-012](../prd/PRD-012-multiplayer-and-permissions.md) |

## 2. 环境与门禁基线（WP-0 的事实依据）

### 2.1 一手事实

| 事实 | 证据 | 对 M1 的约束 |
| --- | --- | --- |
| Java 21 JDK、Node.js ≥ 22.14 | `CONTRIBUTING.md:8-9` | 环境脚本必须检查版本，别让"Node 20"烧掉半天 |
| **游戏测试需要 Linux x64**；构建在任何 Gradle 平台都可以 | `CONTRIBUTING.md:10-12` | Windows 本地**只能 build**，gametest 必须去 Linux runner |
| 顺序固定：`npm install` → `npm run setup` → `./gradlew build` | `CONTRIBUTING.md:14-18` | 少一步就抛异常，见下一行 |
| `.blockwright/mods.json` 缺失时构建直接抛 `GradleException` | `gradle/mod.gradle:39-47`（上游已拆为 ext.lib） | **WP-0 的第一件事**就是生成它 |
| 构建期编译可选集成（Create/JEI/EMI/GeckoLib/Modular Golems/Sable/FTB Teams），版本钉在 `blockwright.toml` | `CONTRIBUTING.md:20-22` | 这些是**编译期依赖**，不是运行期依赖（§2.4） |
| 源集：`main` / `gametest` / `fuzz` | `gradle/mod.gradle:24-26`、`gradle/mod.gradle:51-53`（fuzz 源集已删除） | gametest 是独立源集，能引用 main 的输出 |
| `gameTestServer` 配置存在，启用命名空间 `folkways,ldlib2` | `build.gradle:48-52`（run 定义移到根项目） | 我们的测试命名空间要加进去（`plaa`） |
| npm 脚本：`setup` / `typecheck` / `test:unit` / `test:i18n` / `test:e2e` / `test:coverage` / `visual:take` / `bench:take` / `fuzz:run` | `package.json` scripts | 门禁只用前四个里的三个（§2.2） |

### 2.2 两套测试，别混

| 层 | 位置 | 命令 | 需要 Linux | M1 门禁 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 游戏测试 | `src/gametest`（现为 mods/*/src/gametest） | `./gradlew runGameTestServer`（CI 内） | **是** | ✅ | NeoForge GameTest，跑真实注册表/世界 |
| 纯逻辑单测 | `tests/**/*.test.ts` | `npm run test:unit` | 否 | ✅ | Node `--test`，纯函数/数值曲线 |
| i18n | `tests/i18n/lang.test.ts` | `npm run test:i18n` | 否 | ✅ | 上游既有键不回归 + 新增键双语齐全 |
| e2e | `tests/e2e` | `npm run test:e2e` | **是** | ❌ M2 起 | 真实客户端；M1 用它会被拖慢 |
| 视觉 | `tests/visual` | `npm run visual:take` | **是** | ❌ M2 起 | 截图基线 |
| 基准 | `tests/bench` | `npm run bench:take` | **是** | ❌ M2 起 | M1 用探针 + 手动读数替代 |
| 模糊 | `tests/fuzz` | `npm run fuzz:run` | **是** | ❌ M2 起 | — |

> **为什么 M1 门禁不含 e2e**：e2e 依赖真实客户端与 Playwright，首次跑通的成本远大于 M1 的玩法量；M1 的"可玩"由**演示脚本 + gametest** 证明，e2e 从 M2 开始接管。

### 2.3 平台矩阵

| 平台 | build | gametest | 门禁四件套 | 定位 |
| --- | --- | --- | --- | --- |
| **Linux x64** | ✅ | ✅ | ✅ 全跑 | **CI 与验收的唯一权威环境** |
| Windows | ✅ | ❌ | 只能跑 unit/i18n | 本地开发（build 快、写代码） |
| macOS | ✅ | ❌（Blockwright 仅 Linux x64） | 只能跑 unit/i18n | 本地开发 |

### 2.4 R-FK-12 的准确表述（别写错）

- **运行期**：**零可选依赖**——不放 Create/JEI/EMI/GeckoLib/Modular Golems/Sable/FTB Teams，只放我们的 jar，游戏必须能启动、三个功能必须可用（G3）。
- **编译期**：**依赖由 `blockwright.toml` + `npm run setup` 统一提供**（`CONTRIBUTING.md:20-22`），**不是**"不装那些 mod 也能 build"。把这条写成"不装也能编译"会在 WP-0 就翻车。

### 3.2 任务单模板（派单时照抄）

每个任务单必须**九个字段齐全**，缺一个就不许派，否则 agent 会用猜测填空。

```text
任务编号：M1-WP4-T3
一句话目标：把禁限区约束求值写成纯函数，并可被单测覆盖
图层：L1（新文件）          允许触碰：plugins/steering/**（不得改 core/ 下任何文件）
必读（最小集）：PRD-005 §5/§14、d12:91-95、r01 §5.4
验收 AC：PRD-005 AC-13（同种子 solveThreads=1/N 结果一致）、AC-15、AC-16
自测命令：npm run test:unit -- <该文件>；./gradlew build（CI 跑 gametest）
禁止事项：不新建第 6 种 Board.Act；不访问 level/实体；不引入新的全局状态
交付物：代码 + 单测 + 变更登记 1 行 + `// PLA:`（若碰上游）
失败回退：若纯函数化不成立 → 停下并上报（不要改成"每 tick 求值"绕过）
```

**为什么强调"允许触碰的目录"**：M1 的返工大多来自"顺手改了别处"——尤其是 `core/` 下的文件，一旦被改就会在季度同步时变成冲突源。

## 6. 依赖与关键路径

### 6.1 依赖图（文字版）

```
WP-0 环境门禁
 ├─> WP-1 可读面 ──────────────┐
 ├─> WP-2 需求/专注度 ──┬─> WP-3 如厕 ──┐
 ├─> WP-4 禁限区 ───┬──> WP-5 作息表 ──┤
 │                   └──────────────┐  │
 ├─> WP-10 同步演练（可全程并行）    │  │
 │                                   v  v
 │                            WP-6 解释层
 │                                   │
 └─> WP-7 UI/教学（与 WP-6 并行）────┤
                                     ├─> WP-8 存档/卸载
                                     ├─> WP-9 性能探针
                                     └─> WP-11 交付与移交
```

### 6.2 关键路径（最长链）

`WP-0（2–3）→ WP-1（3–5）→ WP-4（8–10）→ WP-5（6–8）→ WP-6（8–12）→ WP-8（3–4）→ WP-11（2–3）` ≈ **32–45 人日**（单人串行）；并行扇出后约 **20–26 人日**（§3.1 C 档）。

**关键路径上的三个卡点**：
1. **WP-1 的只读面**决定 WP-6 能解释多少（读不到 = 解释不了）；
2. **WP-4 的 `Schema.Setting` 扩展（L3）** 是全 M1 唯一的逻辑级改动，评审不过就退回"用页面内选择器"的降级方案；
3. **WP-6 的覆盖率**依赖 WP-2/4/5 的阻塞类别是否齐全——所以 WP-6 必须在三者之后，不能"先搭架子"。

### 6.3 可并行扇出点

| 扇出点 | 可并行 | 冲突面 |
| --- | --- | --- |
| WP-0 之后 | WP-1 / WP-2 / WP-4 / WP-10 | 不同目录，低 |
| WP-2 之后 | WP-3 / WP-7 / WP-9 | 需求结算 vs UI vs 探针，中（共享状态只读） |
| WP-4 之后 | WP-5（必须，共享约束层） | 高：约束求值层接口要先定死 |
| WP-2/4/5 任意两个之后 | WP-6 可开工（但结论要等三个齐） | 中 |

### 6.4 时间盒（三个两周冲刺，供排期参考）

| 冲刺 | 内容 | 出口判据（不满足就不进下一冲刺） |
| --- | --- | --- |
| **S1（第 1–2 周）** | WP-0、WP-1、WP-2 起步、WP-10 | 干净机器出 jar；CI 四件套能跑；只读面清单确定；需求结算单测通过 |
| **S2（第 3–4 周）** | WP-2 收尾、WP-3、WP-4 | 演示脚本第 1–4 步可复现；`steering why` 能答"他为什么不进去"；存档往返不炸 |
| **S3（第 5–6 周）** | WP-5、WP-6、WP-7、WP-8、WP-9、WP-11 | 演示脚本 9 步全通；门禁四件套全绿；同步演练留档；AC 勾选与矩阵一致 |

> **每个冲刺只认"演示脚本能走到第几步"**，不认"代码写完了没有"。这是 M1 唯一不会自欺的进度指标。
